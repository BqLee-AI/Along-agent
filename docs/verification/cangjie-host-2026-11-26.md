# 仓颉宿主与能力通道验证

2026-11-26，在 Docker Desktop Linux x64 中从同一工作树构建 `host-runtime` 与 `release`。两者使用仓库锁定的仓颉 1.0.5、stdx 1.0.5.1 和 Bun 1.4.2，连接同一个临时 PostgreSQL 16。仓颉镜像 ID 为 `sha256:221a9944281f0a5e8c9d8995fb495eeb5c8cc12914ed1f4512368eb3607fd7ca`，TS 基线为 `sha256:eb7d7cb6c0f068bed3b2aa379093a2d009c2317bf653b332403e4df7c383554e`。复现步骤见 [宿主运行验证](../../apps/host/README.md)。

- 仓颉明文和 TLS 监听的探针状态及 JSON 与 TS 基线一致。四个并发请求各自保留请求 ID，缺省 ID 自动生成。
- 明文与 TLS 都收到 SSE 注释和就绪帧。暂停能力进程后，客户端收到注释就取消读取，宿主在能力调用到期前仍可响应健康检查。
- PostgreSQL 停止后返回 `503 NOT_READY`。暂停能力进程后，一个新就绪请求在仓颉内部读超时后得到同一错误。SIGTERM 后宿主以状态 0 退出。
- 标准库在 Linux 动态加载 `libssl.so`。增加指向发行镜像中 OpenSSL 3 的链接后，带受信任临时证书的 TLS 探针与 SSE 验证通过。

就绪查询受数据库时限和通道读时限约束。断开验证覆盖 HTTP 响应可中断和宿主继续服务。业务流的逐条取消及数据库效果回执由相应业务切片取证。
