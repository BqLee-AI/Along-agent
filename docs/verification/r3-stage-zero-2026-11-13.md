# R3 阶段 0 实验记录

> 日期：2026-11-13。仅记录本次实际实验；不是 R3 功能验收。

## 运行时静态梳理

- `packages/contracts/src/harness.ts` 的 Run 状态只包含 `running/suspended_approval/done/failed/cancelled`；`harness-authority.ts` 的 suspend/resume 与真实批准及等待 checkpoint 绑定，没有通用暂停恢复。手动 `/compact` 若要暂停进行中的 Run，需要新合同与实现，不能借用批准语义。
- `harness-authority.ts` 在模型流活跃时只允许 `model_next` 和 `answer`；自动 compact 须等当前流收尾，在下一次模型请求前协调，不能插入进行中的响应。
- `repository.ts#listHarnessMessageRefs` 选最近 63 条历史加当前输入；`readHarnessMessages` 限制最多 64 条。`harness-authority.ts` 还要求快照消息引用与冻结引用逐位一致。移除 SQL 限制不等于完成协议、快照及旧 Run 兼容。
- `main.cj#projectOldest` 在容量压力下确定性投影旧工具观察，不生成对话摘要。策略的模型窗口默认未知、输入计量默认不可用；没有据此可靠计算百分比的默认自动摘要阈值。24 次迭代/64000 token 是默认累计预算，跨 attempt 不重置；真实摘要调用须如实计账。
- 同一会话的多个 Run、摘要覆盖边界及新消息竞争需要设计；已有 snapshot 只能恢复有限批准等待，不能据此声称支持任意崩溃恢复。本节为静态阅读，不是运行验收。

## 摘要和记忆候选

使用当前宿主的 `completion` 执行两次真实模型调用；不是 Along 的 TS transport、native Harness 或 Web 路径。宿主未公开具体模型身份及 token 用量。

输入为 8 条自造中文消息：项目发布日期从 6 月 12 日更正为 6 月 19 日，发布文档使用中文且负责人为小林；安全审查未完成、负责人未定，接口示例待议；另含助手猜测和无关闲聊。要求返回摘要和带消息 ID 的记忆候选。

- 首次调用耗时 5.45 秒；摘要保留更正、文档语言与负责人、审查状态和待议事项。三条候选的来源分别为 `m03/m04`、`m06`、`m08`；该样本的人工对照未发现不存在的来源或将闲聊、助手猜测写成事实。审查未完成属于时间敏感状态，不保证之后仍有效。
- 第二次调用耗时 6.85 秒，输入故意错误的摘要：旧发布日期、审查已批准及不明确的负责人。模型指出日期更正、审查状态冲突和遗漏事项，并区分文档负责人与审查负责人。错误为人工注入，并非首次调用实际产生的错误。
- 两次单样本不证明错误率、成本、上下文极限或长期稳定性；未验证服务端来源校验、持久化、预算和后续 Run 接续。
- 补查发现两套本地 Along API 均运行且 `/readyz` 正常，无法据此确定用户当前使用哪一套。选其中一套，通过其镜像的正式 TS model transport 和已配置的 `deepseek-v4.1-flash` 对同一材料做一次真实调用：31.47 秒后返回 `HARNESS_PROTOCOL_ERROR: harness model response rejected`，零正文增量、usage 不可得。传输层错误已脱敏，原因未知；这不是 Web/native/Run 的完整链路，也不证明 Along 的摘要能力。未回显凭据或写入实验数据。
- 正式 transport 将多种 SSE、JSON、响应结构或结束状态错误统一映射到上述错误，原请求未采集元数据，不能确定具体原因。随后用同一容器执行不同的短虚构输入：HTTP 200、`text/event-stream`，成功完成，4 个正文增量、194 tokens、4.157 秒；仅证明该次短请求可用，不解释原失败。
- 同一容器用更短的提示及 2048 输出上限重试原八条样本：正式 TS transport 成功，58 个正文增量，14.647 秒，provider 报告总计 1236 tokens。摘要保留更正、负责人和待议事项，但把“项目发布日期”说成“发布文档的发布日期”，有指代偏移，且摘要本身没有来源 ID。8 条记忆候选引用均存在且对应原文，排除闲聊及助手猜测；候选较碎且包含旧日期和时间敏感状态，如何更新及去重未验证。更短提示与不同上限不能解释前次失败；仍不是 Web/Run/native 全链路。

## 中文检索

字面基线为 PostgreSQL `position(完整查询 in 原文)`，不是分词或模糊检索；向量取无阈值 top 3；融合使用两路 top 3 的 `1/(60+rank)` 秩融合。

- “我点餐要避开什么坚果”字面未命中，向量和融合均将花生过敏排第一。
- 查询 `XQ-4792` 时，向量把相近的错误编号 `XQ-4793` 排第一、正确编号排第二；融合将字面命中的正确编号升至第一。
- 两条无答案查询的向量与融合结果均返回 3 条无关资料；无阈值 top-k 不能当成找到答案。
- 28 次编码共 381 tokenizer tokens；初始化 213.84 ms，预热后平均每条 1.67 ms、最大 3.17 ms。单次 14 行向量查询 `EXPLAIN ANALYZE` 为 0.042 ms；不是端到端或生产 p95。
- 实验初次重跑因扩展已存在失败，改为 `CREATE EXTENSION IF NOT EXISTS` 后成功。`pg_trgm` 未参与排序。临时脚本、容器及本次下载镜像已清理。

上述结果仅适用于小型人工样本，字面基线偏严格；不覆盖中文分词、阈值校准、大规模、ANN、owner/时间过滤或生产质量。
