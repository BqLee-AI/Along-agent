### 任务自有文件挂载护栏实验

Linux 隔离容器以只读根和旧资料挂载、独立可写编辑及输出卷、无网络和无 capabilities 运行目标源码的 `publishWorkspaceCreate`、`publishWorkspaceReplace` 与读取函数；使用模拟 advisory lock，而非真实 PG 许可或完整 native/gateway 派发。允许的文件实际创建、替换和独立容器读回；旧资料直接写入/重命名遭 `EROFS`，业务入口拒绝未授权目标、符号链接、硬链接和路径穿越，已有文件创建及陈旧版本替换返回零写冲突。

### 任务自有数据库作用域实验

在独立 PostgreSQL 16.15、迁移 0001–0027、Bun 1.4.2 环境中构造非 owner、非 superuser、无 `BYPASSRLS` 的运行角色，对 35 张 public 表启用 `RLS + FORCE RLS`，仅为固定测试 owner、Run、task 和关联事实设置白名单，其余默认拒绝。实验连接实际进入目标源码的 driver、scheduler 和独立通知接收池；测试数据是直接构造的隔离 fixture，依赖及包构件未证明与最终源码完全一致，不是真实 provider 的新提醒。

受限角色运行真实 driver 后，白名单 Run 的 attempt 为 `fenced_out`、Run 为 `failed`；同 owner 旧 Run 和另一 owner Run 均保留 `running`。真实 scheduler 使白名单任务从 `saved` 到 `fired` 并产生站内 `sent`，两个旧任务仍为 `saved`、原 schedule outbox 仍 pending；另一逾期样本只将白名单任务记为 `missed`。改用隔离 superuser 的反向对照后，两个旧 Run 均被 fence、两个旧任务均被标记 missed。跨 owner 插入、绕过 RLS、设置 replica 和 `TRUNCATE` 均被权限拒绝；同 owner 旧任务和另一 owner Run 的更新影响零行。identity-mail 仅验证一条过期 rate-limit 维护行在受限角色下保留、管理员下删除，没有验证邮件投递。

### 动态授权及目标级 DAC 补充实验

在任务自有 PostgreSQL 16.15 应用 0001–0027，以 `f82a9a5` 的 `createTaskWithinTransaction` 产生真实随机 task ID。临时适配器拦截该插入参数，由隔离管理员连接先将 ID 加入受保护授权表；非 owner、非 superuser、无 `BYPASSRLS` 的运行角色随后同事务写入 task、`created` 和 pending schedule outbox。运行角色直接修改授权表被拒（`42501`），未授权随机 ID 插入被 RLS 拒绝，同 owner 旧 task 的更新为零行；管理员撤销新 ID 授权后，再更新该 task 为零行。

另一个隔离库对新 Run 使用产品的 `insertMessage`、`insertRun`、`insertAttempt` 写入函数及同一事务，由测试操作员先为随机 Run ID 登记授权后成功提交 Run 与 attempt；未授权插入和自行修改授权表被拒，同 owner 旧 Run 更新为零行，撤销新 Run 授权后更新也为零行。该实验未调用完整 `startConversationRun`，消息表未实施完整 RLS。同一事务内的新输入 message 在运行连接可见，但独立管理员连接在提交前不可见；实验是操作员强行授权，而非授权者核实该来源。

这些结果只证明预先获权后的局部 RLS 行为，不证明可信准入：task 适配器持有管理员连接并信任拦截的来源，Run 探针的独立连接又无法核实未提交的来源。两者的授权都在产品事务外，回滚清理、并发撤销、完整工具派发和全表覆盖均未证明；不能将隔离策略用于原安装。需要独立可信的授权主体、来源核验及事务/回滚关系，并在 API/worker 启动前分离所有运行连接和迁移角色。

另在无网络的任务自有容器 overlay 文件系统验证普通进程身份隔离：目标目录属于 UID 1001，权限为 `0700`；以该 UID 调用产品 `publishWorkspaceReplace` 和 `publishWorkspaceCreate`，分别经原来的临时文件加 `rename`、`link` 成功发布，独立进程读回。UID 1002 对目标、符号链接别名、其他文件和目录内创建、rename/link 均被拒绝；但发布 UID 1001 可直接改写未授权文件，并创建、链接和重命名任意别名。目录 DAC 保护了不同身份，不能限制拥有父目录写权限的发布身份只写单一目标。首次容器准备因缺少 `FOWNER` 在权限设置阶段失败，补齐实验所需 capability 后才执行发布探针。

此文件实验直接调用发布函数，数据库 advisory lock 为测试替身；不是有效 gateway/native 派发或真实 PG 许可，不覆盖真实挂载、原 grant 物理身份、并发和在途撤销。现有实现依赖目标父目录中的随机临时文件及原子发布；要作为独立护栏，必须同时约束发布身份自身的目标范围并保留这些系统调用。

FUSE 可用性另在无网络、自有容器内探测：显式映射 `/dev/fuse` 后设备可打开，但默认权限下 mount 被拒；加 `CAP_SYS_ADMIN` 后裸 mount 返回成功。未实现 FUSE 服务端，没有证明逐目标强制 `rename`/`link` 或保留原挂载 `dev/inode`；无服务端的卸载阻塞后仅终止该任务自有容器。这个结果既不是可用护栏，也不证明 FUSE 本身不可行。

### 最小候选的具体评估

- **事务内准入**：`conversations/service.ts` 在运行事务内写入调用方内容和 owner 的 message 后插入随机 Run；`tasks/create.ts` 明确由调用方负责校验来源。把授权登记放进 `SECURITY DEFINER` 函数可使登记与产品事务同提交或回滚，但若其只检查运行角色可写的 message、invocation 或调用方提供的 owner/ID，运行方仍能构造来源并自扩权。前述隔离 Run 探针还观察到事务外管理员看不到未提交 message。合理候选需要独立可信主体验证来源和具体效果，提供运行角色不能伪造的授权，再由受限数据库入口绑定来源、目标和新 ID 并在同一事务内消费；同时要分离迁移、运行及派生连接的身份。现有产品没有这些入口或独立凭证，本轮没有以手工授权替身重复探针，也没有证明此候选能端到端工作。
- **目标级文件**：Linux [Landlock 文件权限](https://docs.kernel.org/userspace-api/landlock.html#filesystem-flags)针对文件层级及目录内容，创建和替换要对同一父目录允许临时文件创建与 `link`/`rename`；目录规则不能按目标文件名单独授权。该判断来自内核文档与源码，并非本机 Landlock 实测。目标单文件挂载的 `EBUSY`、同身份 DAC 绕过和仅裸 FUSE 挂载的证据见上，不代表所有内核机制都不可行。独立发布进程是候选，但当前 gateway 在 API 进程内直接发布；需要独立核验冻结授权与许可，并阻止运行进程绕过发布者，再以真实派发、原注册 grant 的根及输出目录 `dev:ino`、并发和在途效果验证。替换前会校验原目标 inode；原子 rename 后目标变为新 inode，本身不是身份失败。

当前没有可直接接入、已端到端验证的独立边界。缺的是独立来源与授权凭证、可信准入/发布组件和启动前分离连接与文件访问的实际部署方式，以及真实原挂载的身份事实；扩大权限、禁用后台或把受控代理当独立授权，都不能代替这些前置。是否构建上述组件或采用其他机制需要具体设计和验证；本记录不宣称原理上不存在其他方案。

### 独立发布进程隔离原型

以源码 `9e487995774346a9d3f9252851cdd5e3c35b4308` 的 workspace 模块，在无网络任务自有 Linux 容器 overlay 中实验；镜像为 `sha256:356b0557a9a7302ffea7005eec257862fc1902b033564f369cba1a4d44ae9676`。UID 1001 的独立发布进程在同一底层文件系统注册并冻结一次测试 grant，UID 1002 通过 Unix socket 递交经独立测试签发者 HMAC 授权的请求；发布进程调用真实 `publishWorkspaceCreate`/`publishWorkspaceReplace`，分别经 `link`/`rename` 成功创建和替换，产品读取函数及容器父进程分别读回。注册前后无重注册或换挂载，冻结的 root 和 output `dev:ino` 始终不变；目标文件替换后的 inode 按原子替换机制改变。

无授权、伪造签名、篡改已签路径或内容以及成功请求的进程内重放均被拒；UID 1002 直接写目标、相邻文件、新建文件、通过符号链接写入、rename 覆盖和向外硬链接均遭 `EACCES`，相邻文件读回不变。这证明该隔离夹具的 IPC 及文件身份边界，不是正式产品 gateway 派发：签发者是测试父进程，advisory lock 为替身、无真实 PG 一次许可，重放状态仅在发布进程内存；重启、崩溃、并发撤销、在途效果、实际原安装挂载及 grant 均未证明。首次容器初始化因缺 `DAC_OVERRIDE` 失败；第二次发布探针运行后因缺 `KILL` 清理失败、整体退出 1；补齐实验容器 capability 后第三次退出 0，任务自有容器及 overlay 随退出删除。不得将实验的容器权限扩展当作原安装护栏。

### 事务内独立准入隔离原型

以源码 `9e487995774346a9d3f9252851cdd5e3c35b4308`、任务自有 PostgreSQL 16.15 和迁移 0001–0027 验证：独立 issuer 为合成 owner、source 和部分效果预登记一次性凭证；无 superuser/`BYPASSRLS` 的独立运行进程不能写凭证表，且不持 issuer 或管理员连接。测试适配器在真实 `createTaskWithinTransaction` 生成随机 task ID 后、实际插入前调用 `SECURITY DEFINER`，在同一产品事务内检查凭证及其事务内 source、登记新 ID 并消费凭证。真实函数创建两个随机 task，各有 `created` 和 pending outbox；一次创建后整体回滚，再使用同一凭证重试成功并生成不同 ID。

伪造凭证、变更 source、跨 owner、变更凭证绑定的 note、指定旧 task 或重放已消费凭证被拒；同 owner 旧 task 更新为零行。**但测试还实际发现绕过**：运行角色能更新获权 task 的 outbox 命令中的 `fire_at_utc`，因为该实验策略只按 task/owner 限制 outbox 而未绑定命令内容；该绕过在隔离事务内回滚。source 由运行进程按 issuer 预授权的合成声明在事务内构造；声明一致不证明 issuer 独立核验了真实请求或运行进程不能伪造来源。测试没有调用完整 `startConversationRun`、gateway、worker 或真实派发，也没有覆盖全部效果字段、表或连接；因此不是完整执行层护栏。

### 正式 gateway 接缝补验
