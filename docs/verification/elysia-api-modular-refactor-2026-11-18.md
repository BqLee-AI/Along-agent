已观察的重构回归以原断言复验：Elysia parser 包装错误曾把 403/413 映为 400；默认方法和参数处理曾接受 HEAD 或编码 UUID；请求 schema 曾抢在审批路径校验前；MCP 子进程曾引用旧构建路径；D1 声明曾引用旧 fixture 路径。没有改动历史迁移或放松相应门槛。

全量 DB 集成的 Windows 尝试超时，不计通过。Next 生产构建通过；浏览器证据仅覆盖开发入口的签名会话和模型配置写入/回读，不包括生产入口、登录表单、默认模型切换、页面暂停/继续或批准全流程。已知 SSE POST 幂等回放撤权问题不属于本次修复，本次不制作复现。

后续独立修复：SSE POST 已存事件回放逐条复验会话与账户。隔离 PostgreSQL 16 的 `conversations-sse.test.ts` 回归复验 24 通过、0 失败，覆盖有效会话完整回放、会话撤销后无事件交付、事件账不变。此次采用修复后定向验证，未运行修复前的负例。

旧安装升级演练：以 `0270689` 启动隔离安装（schema `0038`），在生产 Web 首次创建账户并留存对话、已确认提醒和未确认提醒。用 Bun 1.4.2 调用目标版本的真实升级 CLI；升级后使用原账号登录，读回原对话和带排期回执的任务。原未确认提醒没有自动消费；在页面明确确认一次，刷新后显示已确认，从原 Run 补读原五条 SSE 事件，任务数由一增至二。首次登录遇到的 `503 NOT_READY` 来自演练配置未提供 sign-in 所需的身份 keyring；补齐独立测试 keyring 后重走 CLI 成功。此用例的业务 Run 终态为 `done`，未覆盖跨版本原生 `suspended_approval` 的显式 resume。
