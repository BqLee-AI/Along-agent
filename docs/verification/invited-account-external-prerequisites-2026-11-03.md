## 公开兼容性核对

以下为本日读取的官方资料，不是运行实验或采购推荐；供应商仅作有实质差异的兼容性对照。

| 资料                                                                                                                   | Observed                                                                                                           | 对合同/后续实验的约束                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| [Resend：Bun](https://resend.com/docs/send-with-bun.md)                                                                | 官方提供 Bun + Node.js SDK 发送路径，要求 API key 和验证域名                                                       | 具备公开兼容性依据；没有安装/锁定其 SDK，也未实测本仓库 Bun 1.4.2 下的 SDK、网络错误、许可证与依赖树                    |
| [Resend：域名验证](https://resend.com/docs/add-a-domain.md)                                                            | 须持有域名并按实际生成值配置 DKIM/SPF，另配置 DMARC；子域分别验证                                                  | 不能用文档示例地址、`local.invalid` 或未经授权的现有域名发信；DNS 值只能来自获选供应商真实账户                          |
| [Resend：幂等键](https://resend.com/docs/dashboard/emails/idempotency-keys)                                            | 发送接口支持 `Idempotency-Key`，最长 256 字符，结果保留 24 小时                                                    | 稳定 delivery ID 可用于去重，但不能承诺超过 24 小时仍去重；邀请 48 小时寿命不扩大该窗口。接受结果未知不得凭同键无限重投 |
| [Resend：事件](https://resend.com/docs/webhooks/event-types.md)                                                        | `email.sent` 表示 API 成功并将尝试投递；`email.delivered` 表示收件服务器接受；另有 bounced/failed/delivery_delayed | `submitted` 不等于入收件箱或人已读；供应商事件也不能证明用户点击完成。P1 不因公开事件目录预建 webhook 平台              |
| [Resend：敏感内容存储](https://resend.com/docs/knowledge-base/how-do-i-ensure-sensitive-data-isnt-stored-on-resend.md) | 关闭邮件内容存储属于附带资格与付费条件的选项                                                                       | 本地载荷销毁不意味着供应商没有恢复链接副本；不能宣称默认零保留或端到端保密。须单独批准供应商处理与保留口径              |
| [Amazon SES：沙箱/生产访问](https://docs.aws.amazon.com/ses/latest/dg/request-production-access.html)                  | 新账户按 Region 处于沙箱，只能发给验证地址/域或模拟器；离开沙箱后仍须验证发件身份                                  | 不能假定部署者已有生产发送资格；模拟器不是受控真人邮箱送达。此核对未证明 SES 具备本合同要求的发送幂等语义，获选前须补证 |

未使用 Better Auth 邮件 hook 示例直接发送：现有 `auth_email` 是 HMAC 派生的认证句柄，真实联系人/邀请/恢复用途和事务由 identity 拥有；供应商示例不能改变该事实源或开放全量认证 handler。

## 获得前置后的最小真实验收

由 identity 负责人使用获准测试配置发送邀请/验证/恢复，记录供应商接受与受控邮箱实际收到两层证据；链接/原邮箱/供应商请求标识只留私有证据，不提交 Git。必须区分明确拒绝、网络超时/接受未知及投递延迟；只有明确有效的供应商幂等窗口或可核查接受事实才能裁决重发，不能用假邮件/模拟器代替送达。

Web 负责人另在确定的生产 HTTPS 来源，通过正式 Web/proxy/API 验证 Cookie 属性、Origin/CSRF、多 Cookie、无 token query/第三方脚本泄漏、GET/预览不消费、完成后只读重登。部署者/安全负责人验证 key-id 备份恢复、缺旧 key 明确失败而非重生覆盖。以上均未在本阶段执行，不计为绿色。
