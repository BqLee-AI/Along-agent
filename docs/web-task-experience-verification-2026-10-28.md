## 入口、加载与读取恢复

- 处理资料初始没有默认登记。显式选择读取成功的登记并填写目标后才开放发送；完整可读/可写路径及受管副本说明可见。仅选择和填写的请求账中没有发送 POST。
- 今日简报 503 时仍有两个目标入口，错误只占简报区域。production HTTP 延迟 brief 3000ms 时，15ms 已交付入口及 skeleton，3012ms 收到事项。另以 10000ms 延迟在真实浏览器中观察到两个入口、6 个 skeleton 和“正在读取简报，仍可选择新任务目标”，尚无事项卡；完成后 skeleton 归零、事项出现、两个入口保留。
- 成功空集合实际覆盖会话发现、Run 索引、展开消息档案、提醒确认、任务范围、任务事件；分别显示没有记录及本次读取范围，不报读取失败。工作区空集合说明没有可选登记，资料发送禁用；这些只读场景零 POST。
- 提醒确认、任务索引与选中任务事件均实际从 50 追加到 51，末页按钮移除。尾页 503 保留已有内容与 cursor，显式重试使用原后续页；活动不会为所有任务拉事件，第 51 项可选择且保留索引。
- 403 留在资源页显示无权执行；503 留页显示依赖/读取失败，均不跳登录。任务详情 404 不渲染假任务，独立成功事件区保留。受保护 401 到安全 `/login?returnTo=...`。
- 运行事件首批 200 条保留首项文档批准；尾页 503 后旧回复、批准和游标仍在。显式重试仍用 `after_seq=200`，追加 2 条，取得第二项提醒批准及下一页回复尾；末页按钮移除，全程零 POST。不是只看首个批准或最后一次 attempt。
- 将第一个 Run 状态 GET 实际挂起，展开运行导航并键盘选择第二个 Run，确认第二份原话/独立回复后再释放旧响应。旧回复与批准没有串到新 Run，释放后仍为新 URL、零旧批准卡；全程零 POST。
- 资料登记 GET 503 时目标仍为处理资料、发送禁用、错误可见且零 POST。SSE 分别返回 MODEL_NOT_CONFIGURED、WORKSPACE_REVOKED、TOOL_EFFECT_UNKNOWN 时，显示领域错误；每次仅有原 `execution=harness` 和原登记的单次发送，没有备用模型或提醒 POST；unknown 另禁用新提交。
- 375px 从正文跳转开始，用 Tab/方向键切换资料目标、明确选择登记、进入原话和主动作，填写不产生 POST。长校样页 Tab 可到完整内容的锚点、读取动作、底部批准与拒绝，聚焦动作均在视口内，没有触发决议。

## 文档授权与效果

- 完整 before/after、目标全文、`preview.body` 的最后字符可达；自然文档滚动，没有固定高度裁剪或窄屏横向溢出。
- 实际批准 POST 的 `seen_content` 与原 `preview.body` 完全相等，涵盖 CRLF、尾空白、制表与不换行空格；没有从 DOM 或摘要重建。批准之后没有 resume POST。
- 批准后保留全文、移除重复批准入口；旧效果失效。后续效果 GET 503 仍保持授权事实及“最新效果尚未核验”，没有退回旧 not_started 或宣称保存。
- `approved + not_started + can_resume=false` 分别显示授权与尚无保存；不猜不可继续原因。效果为 unknown 时，即使受控 Run 返回 can_resume=true，操作区仍禁止盲目继续。
- 受控 reserved、unknown、conflict、failed、applied、verified 六种效果逐项核对，均保留单项批准。unknown 配合 can_resume=true 时两个布局中的继续按钮均禁用；cancelled 配合 applied 仍显示已记录写入且尚未全文核对；done 配合 verified 才显示本项已保存并核对。此状态浏览全程零 POST。
- 受控状态展示不证明批准真实零写、唯一 apply 或新 read verified；这些仍需正式安装的事实与文件证据。

## SSE 与历史导航

主会话持有本节验证。夹具实际保持 HTTP SSE 开启，并通过活动连接计数观察是否断开；只发送通过公开 schema 的事件。

1. 修复前，同页锚点返回误弹离开确认；历史 Forward 未显示离开确认，流被断开。只读审查另指出原实现将所有遍历当 Back，恢复与确认方向不正确。
2. 修复后，同页锚点 Back 保持连接计数 1，无离开弹窗。批准链接实际打开新的完整校样标签，原页仍有连接 1、无离开弹窗。
3. 正常挂起 EOF 后，GET 得到 suspended_approval，显示挂起及当前不可继续；没有网络错误、取消终态或隐式取消/resume POST。
4. 现代 Navigation API 路径与屏蔽该 API 的兼容路径均验证两步 Forward：弹窗时仍在原 Run，确认后准确到原活动页，连接归零。兼容路径另验证原生 hash 条目标记、保留 Next 历史字段及包含 hash 的三步遍历。
5. production Back 默认焦点为“留在此页”；选择留页后连接仍为 1。再次 Back 并明确离开，准确回原活动页，连接归零。离开文案没有把断开当取消回执，也没有承诺后台继续。
6. 实际触发过 beforeunload；工具默认处理原生提示并导致刷新。刷新后只读载入原 Run，不自动发送。没有完成用户手动拒绝原生刷新/关闭提示的验收。
7. 保持真实 SSE 时停止受控上游，浏览器收到 network error，并显示“连接中断不等于完成或取消”；原话保留，状态 GET 的 502 独立显示。恢复上游后明确读取最新状态，仅有会话及 Run GET，回到挂起事实，零业务 POST。
8. 继续请求 503 后，读取最新状态不重发。第二次明确继续沿用同一 checkpoint 和幂等键，仅两次显式 resume POST。停止请求 503 后同样先 GET、再由第二次明确停止沿用原键；有效 cancelled 回执后显示“已停止；已发生的效果不会撤销”，已记录写入仍保留。此项只证明 Web 消费与请求身份，不证明后端去重或真实文件效果。

连续快速遍历、历史恢复尚未完成时确认、真实互联网断网及迟到流片段交错未穷举；不能把以上代表性传输与迟到响应检查扩大为所有浏览器与并发时序证明。
