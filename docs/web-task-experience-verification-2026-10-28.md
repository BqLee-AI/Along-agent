## SSE 与历史导航

主会话持有本节验证。夹具实际保持 HTTP SSE 开启，并通过活动连接计数观察是否断开；只发送通过公开 schema 的事件。

1. 修复前，同页锚点返回误弹离开确认；历史 Forward 未显示离开确认，流被断开。只读审查另指出原实现将所有遍历当 Back，恢复与确认方向不正确。
2. 修复后，同页锚点 Back 保持连接计数 1，无离开弹窗。批准链接实际打开新的完整校样标签，原页仍有连接 1、无离开弹窗。
3. 正常挂起 EOF 后，GET 得到 suspended_approval，显示挂起及当前不可继续；没有网络错误、取消终态或隐式取消/resume POST。
4. 现代 Navigation API 路径与屏蔽该 API 的兼容路径均验证两步 Forward：弹窗时仍在原 Run，确认后准确到原活动页，连接归零。兼容路径另验证原生 hash 条目标记、保留 Next 历史字段及包含 hash 的三步遍历。
5. production Back 默认焦点为“留在此页”；选择留页后连接仍为 1。再次 Back 并明确离开，准确回原活动页，连接归零。离开文案没有把断开当取消回执，也没有承诺后台继续。
6. 实际触发过 beforeunload；工具默认处理原生提示并导致刷新。刷新后只读载入原 Run，不自动发送。没有完成用户手动拒绝原生刷新/关闭提示的验收。
7. 保持真实 SSE 时停止受控上游，浏览器收到 network error，并显示“连接中断不等于完成或取消”；原话保留，状态 GET 的 502 独立显示。恢复上游后明确读取最新状态，仅有会话及 Run GET，回到挂起事实，零业务 POST。
8. 继续请求 503 后，读取最新状态不重发。第二次明确继续沿用同一 checkpoint 和幂等键，仅两次显式 resume POST。停止请求 503 后同样先 GET、再由第二次明确停止沿用原键；有效 cancelled 回执后显示“已停止；已发生的效果不会撤销”，已记录写入仍保留。此项只证明 Web 消费与请求身份，不证明后端去重或真实文件效果。

连续快速遍历、历史恢复尚未完成时确认、真实互联网断网及迟到流片段交错未穷举；不能把以上代表性传输与迟到响应检查扩大为所有浏览器与并发时序证明。
