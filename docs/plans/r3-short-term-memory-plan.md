# R3 跨窗口短期记忆规划

> 状态：Proposed，仅供评审；不改变现行合同，不授权实施。
> 范围：近期对话在上下文窗口之外的写入、存储和检索。
> 不包含：R4 长期记忆、知识库 RAG、部署或启用 R2-B。
> 阶段：R3；下述参数均为待实验校准的建议，不是现有 SLA。
> 合同入口：后续拟议行为及存储/执行细节以 [design/23](../design/23-r3-short-term-memory-and-compact.md) 与 [OpenSpec change](../../openspec/changes/define-r3-short-term-memory/proposal.md) 为准；[阶段 0 证据](../verification/r3-stage-zero-2026-11-13.md)记录真实观察及其局限。本规划保留实施顺序，不构成第二份有效合同。

## 结论

原始消息继续以 PostgreSQL `messages` 为事实源；跨会话记忆是有来源的独立记录。建议在新增的摘要式 compact 中提取候选，同时支持用户明确要求记住；检索使用字面匹配及经评估的 pgvector。记忆是历史材料，不是当前业务状态或执行授权；不依赖默认关闭的 R2-B。

字面检索可直接在数据库按 owner、时间和范围过滤后匹配原文，无需导出聊天记录再执行 shell grep。精确词、人名、路径、日期适合字面匹配；中文同义改写需要单独评估语义检索。现有工作区 grep 是文件内字面搜索，不是对话记忆服务。

## 现状和边界

- **Observed**：`apps/api/src/modules/conversations/repository.ts` 保存消息，并在接纳时选择同一会话的近期历史；`service.ts` 冻结相关引用。`run-state.ts` 在终态事务保存最终助手消息。原文已有持久存储，不需要再建立 Markdown 或 JSONL 事实副本。
- **Observed**：R2-A 是单 Run 有界上下文，既有回取针对本 Run 已接受的观察，不是跨 Run 记忆；参考 [design/18](../design/18-r2a-harness-context.md)。[design/19](../design/19-r2b-readonly-intent-routing.md) 的 R2-B 默认关闭，不是 R3 前置条件。
- **Required**：短期记忆须跨会话；原消息仍可通过现有历史路径读取。
- **Deferred**：保留期限、历史回填和停止召回的具体产品语义仍需评审；不把此前的 7 天或当前会话建议当成决定。

## 写入与存放

**Proposed**：记忆能力归 conversations，工具通过其公共用例读取；不拆服务，不直接复用服务于调度任务的 outbox。消息仍是权威原文，索引可重建。

1. 用户明确要求记住时，经受控写入工具保存，成功后才确认；普通信息在下述摘要式 compact 中提取候选，不对每轮对话额外调用模型。
2. 记忆记录保存内容、owner、来源消息、创建和更新时间、有效性及提取版本；向量与编码版本绑定，是可重建派生数据。模型生成的记忆不替代原消息事实。
3. 对相同来源批次的重复处理幂等；不同消息即使文字相同也保留来源，不能仅凭向量相似度自动覆盖旧记忆。更正和冲突的具体处理须结合来源和时间评估。
4. 初次升级是否回填已有历史、到期规则和停止召回均待定；不得把删除派生记忆表述为删除原消息、已接受结果、checkpoint、回答或备份。

## Compact 与记忆提取

**Observed**：`apps/harness/src/session/context.cj` 的 `projectOldest` 在容量压力下对已见旧工具观察做确定性投影，保留来源及回取能力，不是模型摘要；`repository.ts#listHarnessMessageRefs` 在新 Run 接纳时选最近 63 条可见历史及当前输入，`service.ts` 冻结引用。两者是不同接缝，现有实现不会因历史退出窗口自动提取记忆。

**Proposed**：新增摘要式 compact，不将已有工具观察投影误称为摘要。手动 `/compact` 由用户触发，执行时暂停当前 Run；暂停及继续的具体接入须与现有生命周期合同对齐，不假设已支持任意挂起恢复。手动与自动触发共用压缩用例；手动成功只需简短状态，不向聊天输出整篇摘要或记忆列表，失败说明原因。摘要与记忆不是模型正在执行的用户消息，也不作为用户可见回答。

自动 compact 在一次模型请求完整结束后的安全边界发生，不在流中插入请求或污染当前模型的函数调用历史。运行时先用现有确定性投影处理可回取的旧工具观察；需要摘要时以独立的请求消息构造 compact 输入，专门的 system 指令要求输出当前会话摘要与独立的跨会话记忆候选。候选引用实际输入消息 ID，允许空数组。当前输入、批准和未完成任务所需事实等保护集不丢失；原始对话、工具结果与已接受事实不覆写。成功后将摘要作为明确标注的不可信历史资料供后续请求使用，不作为 system 权威或用户指令；compact 交互本身不混入原对话。

服务端验证候选结构、owner、来源消息及引用范围，保存记忆与来源；引用存在只证明出处，不证明概括正确。摘要和记忆是不同产物：前者用于当前会话延续，后者用于其他会话检索。模型用量、上下文和迭代如实计入实际所属预算，预算不足不得另建 Run 绕过；若采用独立后台调用须先定义资源预算和生命周期。摘要生效与记忆写入失败分别记录，不能谎称均已成功。

**现有容量与触发**：`model_window_tokens` 可配置但默认未知，`input_meter` 可为 unavailable；现有压力下投影和容量拒绝不等于在某个百分比主动触发摘要。目前没有自动摘要阈值。自动 compact 的起始阈值、留给摘要的空间和不可用计量时的策略须经实验确定；计量为 estimated 时不得宣称精确窗口保证。provider 已拒绝或剩余空间不足时无法假定完整上下文还能送入摘要请求，不能绕过既有失败和预算合同。

**新 Run 窗口切换**：移除固定最近 63 条作为产品上下文选择规则，改为已保存摘要及其覆盖边界之后的原消息，并受模型窗口、字节帧、消息和预算等真实边界约束。当前 64 条引用上限及 snapshot/协议校验也是合同，不能只删 SQL 的 LIMIT；新旧 Run 的冻结引用、批准恢复及协议迁移须成套设计，历史 Run 保持原规则。摘要覆盖精确消息引用，手动压缩与新消息并发时不得丢消息或重复覆盖；原消息不删除。摘要压缩批次应可重放去重，失败不将未处理的消息标为已处理。

短会话可能从不触发 compact，因而只靠自动提取不能保证被记住。明确记住走当次工具写入；其余按 compact 提取，不为普通短会话额外增加自动提取触发。项目安排、提醒等应由相应业务能力与当前用户目标处理，不用短期记忆代替真实提醒或安排；相关 skill 或业务能力不在本规划中预先确定。

## 检索与运行路径

**Proposed**：仅为获授权的新 Harness Run 提供记忆工具，旧 Run 的冻结工具权限和批准恢复合同不变。搜索范围、owner、截止时间、检索版本与预算由服务端确定并冻结；模型不能指定他人身份或扩大范围。历史 GET 不执行搜索、编码或写索引。

- 仓颉在需要窗口外信息时调用搜索，TS 分别返回字面和语义候选；结果标注来源会话、消息、角色、时间、原文范围和有界摘录。当前 Run 已冻结消息不重复召回。
- 字面与语义分开排序，使用版本化的排序融合并保留精确命中；合并重叠片段但保留不同来源。按需回读只允许访问本 Run 已接受搜索结果中的命中，不能用任意消息 ID 探测。
- 历史用户陈述与历史助手表述分开标识；不得凭时间或相似内容猜旧助手消息对应的 Run 或动作收据。任务是否仍有效等当前状态由其所属模块查询。
- 记忆作为不可信工具资料，不进入 system 权威层；历史中的指令不能授予操作权限。创建提醒、修改偏好或写文件仍受当前目标与原工具守卫约束。
- 空结果、索引未就绪、查询不完整和编码器故障应区分。语义不可用时可明确标记降级并返回字面结果，不能把未完成当成“你没说过”。查询截止冻结到 Run 接纳时刻，实际返回时仍检查当前到期和排除资格；已接受结果在恢复使用前也须复核资格，不能改写原账或暗中换一次搜索。
- 结果与调用次数计入现有 R2-A 容量及工具预算；top-k、结果大小与调用次数由合同及真实材料评估确定，不将实验 top-3 固化为生产参数。

## 向量、中文和部署取舍

MVP 验证字面与语义候选在基本中文检索场景中可用，并如实标记无关候选及降级；不要求先完成代表性数据基准或比较排序算法。PostgreSQL `simple` 全文检索不等于中文分词，`pg_trgm` 也不是语义检索。数据规模或延迟表明有需要时，再评估检索策略和索引；不将小样本指标当成质量保证。

`apps/embedding/manifest.py` 固定的中文 BGE INT8 可作为语义候选路径；R2-B 的意图分类成绩不能证明记忆检索质量。编码服务不可用或输入超限时，明确报告不完整或降级；不静默截断或把候选当成事实。

现有 `infra/compose/compose.yaml` 使用 `postgres:16-alpine`，并未配置 pgvector 或正式编码 sidecar。语义阶段需要固定并验证 PG16 扩展镜像和版本、前向迁移、生命周期检查、备份恢复及编码资产；不要直接假设 Alpine 数据卷可安全切换到另一 libc 的镜像。R3 独立控制编码服务，不需要打开 R2-B。向量只作候选索引，源文本及排除规则仍是权威。

## 交付顺序与并行关系

**总体依赖**：设计与实验 → 固定共享合同 → 手动 compact 与记忆能力并行实施 → 集成后自动 compact 与完整语义召回 → 真实使用路径验收。各阶段的 PR 可以独立评审；不能把中间切片当作完整 R3。

### 0. 设计与可行性实验

- 梳理现有 Run、暂停/继续、snapshot2、模型窗口计量与 63/64 条引用限制；输出摘要覆盖边界、旧 Run 兼容和自动压缩可行的安全点。用户要求手动压缩时暂停，但不能假定现有生命周期已有通用暂停/恢复。
- 已完成固定对话摘要/候选实验与同一组材料的 PG16/pgvector 中文检索实验，见[阶段 0 记录](../verification/r3-stage-zero-2026-11-13.md)；样本有限、正式 transport 一次失败原因未知，不替代实际应用验收。
- 依据实验拟定摘要结构、记忆来源和安全点合同；自动触发阈值、top-k、保留/删除和历史范围仍需证据或产品决定，不把小样本指标写成生产保证。

### 1. 共享合同：独立收敛后再实施

单独评审 OpenSpec 与设计增量：手动命令及暂停/恢复语义、摘要覆盖和新 Run 装配、旧 Run 不变、记忆写入/检索及失败、授权和预算、64 引用上限迁移、部署/回滚。固定 TS/native/工具/存储接口及文件所有权；相关 PRD、schema、API 和索引随合同更新。合同不代表功能可用，也不授权后续实施。

### 2. 可并行实施的两条主线

**A：手动 compact 与上下文装配**。实现 `/compact`、真实模型摘要、摘要来源及覆盖持久化、新 Run 消费摘要与后续消息、旧 Run 兼容；移除固定 63 条产品规则，并同步引用与协议容量合同。等待/继续与权限不绕过既有保护集。手动成功只给简短状态；初期若记忆线尚未集成，不能声称已提取记忆。真实验收须观察后续模型输入、暂停/恢复和失败路径。

**B：记忆存储、显式写入与检索**。实现 PostgreSQL 记忆及来源、明确记住的写入工具、本人跨会话字面检索、必要的纠正/停止召回合同；实际写入成功后才确认。它可独立验证，不依赖摘要功能或 R2-B。保留期限与旧历史回填按合同确定，不预置未经批准的值。

A/B 共享摘要候选格式、来源引用、所有者、错误及提交语义；这些必须先由第 1 步确定。各自负责文件，公共协议与迁移由单一集成负责人统一修改，避免并行覆盖。A 完成后不等于完整 R3；B 只有字面召回也不等于语义召回完成。

### 3. 并行试做后集成

- **A+B 集成**：compact 模型请求返回摘要与记忆候选；以原消息作为来源，保存成功的候选并在跨会话真实检索中使用。摘要及记忆结果独立记录；不把失败伪报成功。
- **语义召回**：使用隔离 pgvector 和编码服务，验证真实候选和本人来源；不可用时明确标示降级，不假装空结果。代表性数据集和排序调优不作为 MVP 的前置条件。
- **自动 compact**：依赖手动 compact 的真实摘要/继续闭环、窗口计量证据和安全点合同；可并行进行阈值实验，不能在这些前提未定时声称完成。Run 中通过安全边界暂停、调用压缩并继续，原预算、取消、工具事实和批准保护不变。

### 4. 整体验收与放行

正式 Web/native/TS/PG/真实模型路径验证手动和自动压缩、同 Run 继续与跨会话记忆；以现有覆盖验证 owner 隔离、来源、取消、预算、失败语义及旧冻结资格。隔离环境验证升级和备份恢复，不要求操作原安装或真实用户数据。代表性质量基准、排序优化和容量校准留待真实使用需求驱动；小样本结果不构成质量保证。不自动开启 R2-B。

任一前置实验或合同未解决时，不把候选设想写成已完成；可继续不依赖该决定的并行工作。只要求规划时不实施代码、部署或启用。

回滚优先关闭新 Run 的语义能力，必要时关闭新记忆入口并停止索引 worker；保留原文、已接受事实和排除记录。新类型事实写入后不能假定旧二进制可读，故障优先停写或前滚，不删除迁移、账本或用户数据。
