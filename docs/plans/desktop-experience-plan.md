# 持续对话与工作区

## 范围与完成条件

全站重构覆盖今日、聊天和历史、提醒、批准、活动、完整文档校样、账户及认证。记忆页面沿用本人记忆的读取、更正和停止使用能力；资料与日记、技能、连接、渠道、设备和普通待办提供可导航的未接通页面，不伪造目录、授权、已连接设备、成功记录或写入能力。沿用原认证、权限与业务合同。

这不是代表页方案，也不保留旧导航作为并行实现。桌面持续聊天与真实工作区共存；窄屏只有一个可见表面，路由、刷新与返回正确恢复选中资源。交付需要全部页面、原功能、架构迁移、优化构建、五视口和同负载性能证据，不以目录改名代替功能完成。

## 依据与视觉决定

研究公开可达产品界面的紧凑工具栏、信息密度、可扫读条目和分层导航，并以 B01 的授权登录态观察确认双区、收起工作区和窄屏导航的实际用途。借用结构而非素材、字体、品牌或手工玻璃。研究与截图原件保存在仓库外；其他产品的入口与声明不构成 Along 能力证据。推荐不等于创建，目录不等于授权，协议声明不等于效果已核对。

沿用 TypeScript、Next.js App Router、Tailwind v4、LumenUI/Base UI、官方 Linen 固定浅色、lucide 和 Motion；不引入平行主题、字体或控件库。标题 24px/32px、正文 16px/28px、辅助 14px/22px。背景与局部表面低强调，主操作有单一优先级，内容通过间距与分隔对齐，不为每段消息套卡片。桌面工作区本身已是半屏，内部不再次依据整个视口添加固定侧栏。

## 布局与导航

- 1024px 起，聊天在左，工作区在右；展开时约等分可用宽度，两区独立滚动。聊天输入常驻聊天底部，工作区切换、收起和展开不卸载聊天。
- 关闭工作区后聊天扩宽，正文仍保持可读行宽。收起状态进入 URL，不用仅在内存里的显示状态冒充可刷新导航。
- 工作区主入口为今日、提醒、记忆与助理资料；设置可达账户及未接通能力。批准与活动属于真实事项入口，不伪装成全局运行审计。
- 窄屏用聊天、今日、提醒、记忆与助理资料五个主要入口。隐藏表面不可聚焦，不覆盖输入；切换表面仍保留同一聊天实例与草稿。
- `/conversations` 保留原新对话和历史深链。其他工作区 URL 带上当前 `conversation_id/run_id`；`surface=chat` 表示保留路径但只显示聊天。打开工作区恢复对应路径，不创建新对话。
- 原历史、提醒详情、批准及文档批准路径继续可直接读取。历史发现明确区分已读取范围与全部历史。

## 状态归属与真实迁移

| 边界                   | 唯一职责                                                                          |
| ---------------------- | --------------------------------------------------------------------------------- |
| `app/`                 | 路由参数、RSC 与身份入口，组装 feature screen；不保留业务页面、分页状态或执行编排 |
| `shell/model`          | 工作区路由、导航项目及 URL 投影，不拥有 Run 或批准                                |
| `shell/viewmodel`      | 表面与导航状态、持续聊天身份，工作区切换不创建第二个会话控制器                    |
| `shell/view`           | 双区框架、窄屏导航、焦点与可见性                                                  |
| `features/*/model`     | 对应类型、数据访问、协议转换、冻结内容与纯业务投影                                |
| `features/*/viewmodel` | 状态、用户命令、异步生命周期、迟到响应隔离和请求清理                              |
| `features/*/view`      | 展示及 DOM adapter；布局、滚动和焦点不编排业务执行                                |
| `shared/`              | 跨功能 HTTP/会话传输、无业务基础 UI、主题与 Motion 策略                           |

`useConversationTask` 保留发送、原 Run SSE、GET、显式继续与取消、未知发送保护、幂等键的唯一所有权。根布局持有一个不以路由为 key 的会话视图。显式切换会话才重读选中身份；切换工作区不重连、不重发、不取消。新对话、身份改变或真正离开应用仍遵守在途离开保护。

提醒、批准、文档、账户与简报各自拥有模型和状态；不把业务类型、转换和导航继续堆入根 `lib/`。迁移所有真实调用和测试，删除被替代业务文件及兼容 re-export。静态依赖门禁必须指向新边界，而不是保留旧目录的文本断言。

## 必须保留的业务合同

- 导航、读取、分页、展开、刷新、返回与重登恢复不自动执行。历史恢复只 GET；下一轮与继续均是显式用户命令。
- 资料必须显式选择读取成功的登记；保留完整可读/可写范围，不默选、不接受任意宿主路径。
- 提醒展示冻结字段；确认、取消与撤销回执沿原事务及资格合同，不将流结束当成功。
- 文档保留完整 before/after、目标、版本、技术引用与原 `preview.body`；CRLF、空白及组合字符不被格式化或摘要替代。提交的 `seen_content` 直接来自冻结字符串。
- 批准只授权，不写入、不自动继续。运行资格与批准分别读取；`applied`、`verified` 与 `unknown` 分别表达。
- 未知结果不盲重做；取消不撤回既成效果。助手措辞不充当业务回执。
- 原认证、Cookie/CSRF、401 安全返回、403 权限含义、建号资格、转正及退出撤销合同保持。

## 性能与验证方法

优化前在原优化构建采集基线，优化后以同设备、1440×1000、相同合成消息/运行及 HTTP/SSE 节奏比较。记录真实工作区路由往返、长历史滚动与原节点定位、SSE 增量及输入并发、脚本/布局耗时、长任务、帧间隔和客户端 JS 资源。原框架没有持续工作区时如实记录语义差异，不拿只读关联展开冒充等价工作区。

候选热点是消息更新与 ResizeObserver 的重复滚动读写；先量再决定，不能预先宣布根因。滚动跟随由单一 DOM adapter 管理，保留手动阅读和回到最新。历史 Markdown、静态运行投影与实时消息隔离，避免每次增量重算整页。全页内容不做进入位移，Motion 只用于局部反馈并尊重减少动态效果；不以动画驱动请求或完成。

普通交互阻止并记录意外业务写入。性能发送只进入仓库外的受控 HTTP/SSE 服务，不到真实 API、不调用模型；多行草稿使用原生 value setter 加单次 input event，禁止用可能把换行解释成 Enter 的 fill。真实原安装读取和合成场景分别记录，不能将后者称为真实执行验收。

完成后运行受影响行为测试、类型、Lint、格式、依赖门禁和优化构建；在 `http://127.0.0.1:3100/` 验证 1280、1440、1920、375、768 五个视口。只停止并重启已核实归属的预览，不动原生端口或正式安装。已知锁和端口失败不重跑确认，不声称全仓全绿。
