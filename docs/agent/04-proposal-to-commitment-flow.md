# 04 提议到承诺流程

| 状态     | 范围                                                   | 不包含                                                               | 阶段标签                              |
| -------- | ------------------------------------------------------ | -------------------------------------------------------------------- | ------------------------------------- |
| Proposed | 分诊、澄清问法、time-core 错误到话术映射、确认绑定规则 | Scheduler 登记回执/门禁细节（design 真源）、取消后触发数统计口径实现 | v0：干净单次提醒闭环；混合与摘要进 v1 |

## 分诊（路由建议，不是授权）

[Required] 每轮用户消息先分诊（B06 §8），输出三路之一；分诊错由分诊层记，不推给用户：

| 路       | 条件                                                                       | 走向                                                                           |
| -------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 提醒路   | 有明确"提醒/到点通知"意图（"明天 9:20 提醒我喝水"）                        | `propose_task`；信息不全留澄清，不转 Agent 猜                                  |
| Agent 路 | 只有看/分析/解释，无写入要求（"我明早有几个会？"→ v0 答无数据+要明确时间） | 只读工具+答复；不产 approval                                                   |
| 混合澄清 | 两者掺杂（"帮我看看灰度，明天提醒我"）                                     | 先一起问清关系和时间再拆路，不静默猜；v0 混合与摘要原则上挡回 v1，只做时间澄清 |

- [Required] 分诊只是路由建议：两条路都要过确认门；提醒路确认前不建 task，Agent 路不产副作用。
- [Required] 明确提醒进提醒路，信息不全留澄清：缺年份/时区/时段（B06 §3.3）即澄清，不默认、不顺延、不猜设备时区。

## 澄清问法（问一次，问准）

[Required] v0 只收完整日期时间时区，缺就问一次（B06 §1 不做清单：高级多轮追问进 v1）。问法模板：

| 缺什么                       | 问句                                                                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 年份                         | "请给年份：是 2026 年 10 月 17 日 09:20 吗？（年份不能默认，请确认）"                                                                      |
| 时区                         | "请给时区：按哪个时区排？（如 Asia/Shanghai；本次确认只用于本次）"                                                                         |
| 时段（"9 点"无早晚）         | "请明确是上午 09:00 还是晚上 21:00？（差半天，不能替选）"                                                                                  |
| "12 点"/"0 点"               | "请明确是中午 12:00 还是午夜 00:00？/ 0 点指 16 日开头还是进 17 日的午夜？"                                                                |
| 范围词（"左右/尽快/有空时"） | B06 §3.4 原话挡回："范围无法唯一排触发点，请给准确时刻；v0 不支持范围提醒。" / "v0 不读日历不监测空闲，这次不保存；请给明确日期时间时区。" |
| 两条待确认并存+无指向确认    | "有两条待确认（A-0051…、A-0052…），请点对应按钮确认。（S0 #14 冻结：v0 只认按钮，无文本意图消歧）"                                         |

- [Required] "明天"锚说明：回显必须写清锚（"按首次收到+Asia/Shanghai 冻为 2026-10-17"），延迟超 1min 不重算相对日期；跨确认时区午夜重问具体日期（B06 §3.5）。
- [Required] 未办成的愿望记独立"未支持请求"列表（30 天归档、一年删），只在用户主动看或 v1 评审时翻（B06 §3.4）。

## time-core 错误到话术映射

[Required] `propose_task` 内 time-core 归一失败保留 typed 错误并呈现以下话术，不建 C、不重问已给信息。安全 spec Scenario 1.2 要求 `NONEXISTENT_LOCAL_TIME / AMBIGUOUS_LOCAL_TIME / UNKNOWN_TIMEZONE` 终结为 `thread.failed`（422语义），不能把“请重定/请选择”误映成 completed；只有普通缺信息/模糊表达走成功澄清。规则预检503、流中failed503、结构化两候选、零承诺写与 Web新键重提议统一引用 `docs/design/05-time-core.md §5/§9/§10`；本表是话术而非另一套传输合同，也不作为运行通过证据。

| 错误码                   | 话术                                                                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `NONEXISTENT_LOCAL_TIME` | "当地并不存在这个时刻；不猜、不存、不排，请重定。（如 2027-03-14 02:30 America/New_York）"                                                                                                                                                       |
| `AMBIGUOUS_LOCAL_TIME`   | 必须摆两偏移让用户二选一："出现了两次：第一次 UTC−04:00（05:30 UTC），第二次 UTC−05:00（06:30 UTC），你要哪一次？"（缩写会撞、偏移不会；B06 §3.6）。用户选定后 `fold_choice=first\|second` 重调归一，新 C 回显写清"选择第×次出现（UTC±XX:XX）"。 |
| `TZDB_UNAVAILABLE`       | "时区规则库暂不可用，现在无法排期，请稍后再试。（服务端未就绪，不收'明天'。）"                                                                                                                                                                   |
| `UNKNOWN_TIMEZONE`       | "这个时区别名认不出来（别名表版本 V…）；请给规范 IANA 时区，如 Asia/Shanghai。"                                                                                                                                                                  |
| `BUDGET_EXCEEDED`        | "本轮推理预算用完，已停下；请换句更具体的话重说（如带完整日期时间时区）。"                                                                                                                                                                       |
| `PRESENTATION_MISMATCH`  | "摆和存对不上，已暂停待核对，不建不排；请看新回显重新确认。"（展示快照与 C 快照不一致）                                                                                                                                                          |
| `APPROVAL_EXPIRED` (410) | "这条确认已过期（24h）；目标日期不变的话请重新生成回显再确认。"                                                                                                                                                                                  |
| `APPROVAL_SUPERSEDED`    | "这条已被新回显替代，请确认最新一条（A-…），旧的不再有效。"                                                                                                                                                                                      |

- [Required] 归一输入永远完整到秒：秒没说按入口约定补 `:00` 再递 time-core（B06 §3.2）；别名（"北京时间"）由入口版本化别名表查完再递规范值。
- [Required] 单次语义冻结：按确认时那只钟对应的瞬间触发，出差换城市不改（上海 09:20 定的，纽约当地 21:20 响）。

## 确认绑定（承诺唯一入口）

[Required]（B06 §5；与 01 链一致，本节为 Agent 侧话术投影）：

- v0 只认点确认按钮（S0 #14 冻结：整句文本只做展示，旧 `C-XXXX/c_id` 作废统一 `A-` + 路径 `approval_id`）；“好/嗯/行”与整句文本均不算——Agent 收到这类回复必须回：“请点对应按钮确认，文本不算确认。”
- 确认请求带三样：路径 `approval_id` + 当时看到的完整内容 `seen_content` + `presentation_hash`；服务端按快照重建预期比对，对不上即 `PRESENTATION_MISMATCH` 停在待核对。
- 回显有效 24h；23:50 摆的日期 00:05 点头还是那一天（冻住不重算）；超 24h 或目标已过旧确认作废。
- 连点两次只回同一个 task："这是重复确认，没有新建第二条。"
- 展示层只读 C 冻结字段固定格式呈现；模板带 `presentation_version`；旧模板有显示 bug→作废旧 C 重来，不悄悄替换。

## 与 design/04/09 的一致性

- 分诊/澄清/话术均为 Agent 侧表现层；时间判定权威在 time-core（design/09），承诺事务权威在 approvals（design 真源）。
- 错误码全集以 design 为准：本篇 8 个（PRESENTATION_MISMATCH/APPROVAL_EXPIRED/APPROVAL_SUPERSEDED/NONEXISTENT/AMBIGUOUS/TZDB_UNAVAILABLE/UNKNOWN_TIMEZONE/BUDGET_EXCEEDED）。
