## AC5：旧深链可读，当前授权仍独立

以下另建真实当前版本 native 等待点，属于显式材料准备/负向动作阶段，不混入上节零 POST 基线：

1. 用同一正式 UI、获准模型与原有限工作区读取目标文件，只提出新的精确批准；未授权写入。到达 pending 等待点后，临时撤回专用安装登记并通过正式重载加载；不改 owner/root 或模型配置。
2. 原会话事件、RunView、冻结 workspace 摘要和旧文档批准仍为 200；旧效果仍 `verified`，当前工作区列表为空。真实批准页的新 confirm/reject 均为 403，新发送同一已撤销 workspace 的请求也是 403；16 张表摘要不变。
3. pending 时 resume 先得到 409 STATE_CONFLICT。这只证明前置条件，不能当成撤权授权证明。
4. 原样恢复登记后，仅明确批准该等待点，不继续、不写文件；实际 RunView 为 suspended_approval、can_resume=true。再次撤回登记并正式重载，can_resume=false，原有效 checkpoint 的新 resume 为 403 PERMISSION_DENIED；16 张表摘要不变、attempt 仍为 1。
5. 撤权期间明确安全停止该验收 Run，实际状态为 cancelled；新批准保持 approved，effect 为 not_started，没有保存文件。原登记逐字节恢复并正式重载，原私有配置 SHA-256 不变；素材与原已验证目标文件仍不变。

当前工具授权、unknown 不重写、同等待点唯一继续及取消边界复用本次完整 PG/native 合同覆盖，不为真实安装制造不确定文件效果来重演底座。

### 旧原话回退的实际查询计划

- 在专用 PostgreSQL 16 中应用原始迁移，准备 52 个 Run、30,051 条幂等账本引用，其中 30,000 条属于页外 Run；使用实际 `listRunHistory` 生成的完整 SQL 读取 51 个 Run，不用简化查询替代。
- 修正前观察到 `conversation_idempotency` 的 `Seq Scan` 执行 51 次，每次过滤 30,050 行，shared hit blocks 为 43,758。该观察证明缺少查找路径，不属于业务结果失败或测试先行 Red。
- 将受控夹具置于 `0017` 索引/版本状态，执行修改后的真实 `0018` 及 catalog verifier；新增非唯一 `conversation_idempotency_run_id_idx (run_id)` 后，同数据同 SQL 使用该 `Index Scan`，执行 51 次、每次返回一行，shared hit blocks 为 151。
- 单次受控执行时间为 88.443ms → 1.996ms；它不是通用性能承诺。51 行历史响应及完整幂等账本摘要前后相同，未改变原话关联语义。
- 生命周期冒烟现为 **53 场景通过**：原升级/事实保留/重复升级/两次禁止 DDL 重启继续通过；新增第四索引缺失、错键、唯一、错表、无效及未就绪六类拒绝。拒绝前后非空历史、幂等账本和索引签名相同，不自动修复。
- `0018` 是本 PR 的新增迁移，0001–0017 未改。旧三索引的开发/验收库不会被自动补建；新 verifier 会拒绝其不完整结构，本轮使用专用夹具及全新库，不修改原验收安装或用户数据库。
