# 02 核心循环与页面

> 状态：产品合同 / 范围：v0 八步闭环与 R1 个人助理的页面/恢复边界 / 不包含：字段级定义（见 schema）、路由合同（见 api）、版本化验收结论 / 技术设计真源：[design/01 §6](../design/01-tech-stack-and-repo-structure.md#6-r1-web个人助理与职责边界)

> 授权作用域：本文八步、提醒按钮、资料先选及文档逐项批准描述 legacy；新委托按实际冻结能力在本人登记集合内查找、编辑和有限创建资料。离开断流仍适用于 request-bound 委托；24小时只属 task 批准，不含文档批准。详见 [design/20 §1–§9](../design/20-goal-scoped-delegation.md)，合同不代替真实验收。

## 核心循环（八步）

- [Required] 1 简报：用户打开 Web，GET /brief 聚合今日 tasks 与待确认 approvals；无事则页面安静，只留记录入口。
- [Required] 2 卡片：每条简报条目为结构化卡片，只读 presentation 冻结字段做固定格式呈现，不换算、不推断、不改写。
- [Required] 3 对话：用户进入自己的 Bot，创建或打开一个对话。可在独立页面设置 Bot 的名称、简介、角色、指令、模型和可用工具及资料。消息经 SSE 流式返回回复和待审批。预算超限时停止并告知。
- [Required] 4 提议：Agent 产出待确认方案并冻结 presentation（含 presentation_version）；confirm 请求携带当时看到的完整内容 + presentation_hash，对不上即停（PRESENTATION_MISMATCH）。
- [Required] 5 确认：只认明确按钮确认，不把“是的/好”当写入授权；回显有效24小时，确认绑定所见冻结内容。
- [Required] 6 调度：Approval 消费 + 建 Task 同事务；收到 Scheduler 登记回执才标 scheduled，否则停在 pending_schedule。
- [Required] 7 触发与通知：到点先查三样（task 对得上、状态为 scheduled、登记凭据绑同一 task）；15 分钟内触发一次；超窗标 missed 不补发。
- [Required] 8 活动账：task_events 只追加投影，用户可核对每一步 type 与 evidence_ref（有凭据写号，无则写"服务端记录"）。

## 场景 A：喝水提醒（v0 第一条验收场景）

- [Required] 输入："明天 9:20 提醒我喝水。"（已确认时区；"明天" = 服务端首次接收时刻 + 已确认时区，解析一次即冻结，B06 §3.5）。
- [Required] 提醒必须给出日期、明确时刻、已确认时区和非空事项，缺字段只澄清、不建批准或任务，不按接收锚补今天。中文时钟“下午三点二十分”唯一解析为15:20；时间原话与事项原话独立保留，不拼接、不改写其中的中文数字（design/05 §2、agent/02）。首次接收锚和超1min/跨午夜重确认政策不变。
- [Required] 回显："2026-10-17 09:20（Asia/Shanghai）提醒你：喝水。"由已保存并校验的 approval 草稿生成；确认绑定这份草稿。
- [Required] 06 喝水提醒降级为调度子用例：task.kind=notify_only，不走 LLM 先验调度；time-core 仅做 wall_time → fire_at_utc 的确定性归一。
- [Required] 确认后才建单次 task 并排期；到点写触发记录、生成应用内通知；对外只报告系统记录到的状态，不声称用户已读。
- [Required] 未完成提醒列表为空，只说明没有匹配的活动任务，不代表之前没有创建成功；已触发、已错过、已取消的任务须按历史状态核对。不因当前列表为空否定已确认回执或建议重建提醒。
- [Required] 当前 Harness 提醒等待点就地完整展示并提供明确的“确认创建并继续”或“确认取消并继续”按钮；一次点击依次确认并继续同Run，不强迫切页或再点继续。成功只展示真实任务结果；未知响应先只读核实，历史、business快捷入口和文档批准不自动执行。
- [Required] 归一失败回澄清；存摆、确认、排期、触发任一步失败都保持未完成并进可重试队列，绝不报成功。

## 场景 B：每日简报（聚合场景）

- [Proposed] 用户立多个单次任务后，次日打开简报页看到按 fire_at_utc 排序的今日条目：已排期待触发、待确认提议、昨日 missed（含一键重约入口）。
- [Required] 简报数据只从 tasks / approvals / task_events 聚合，不读、不猜任何记忆或外部状态；missed 条目不补发，只给重约口（新 task，recreated_from 指回旧 task）。
- 聚合形态参考外部产品，v0 按打开时实时聚合。

## 活动页（事件账投影）

- [Required] 活动页逐行展示 task_events 的 type 与 evidence_ref：scheduled（含登记回执号）、fired、missed、cancelled、superseded；无外部凭据的行写"服务端记录"。
- [Required] missed 行必带一键重约入口：开新 task，recreated_from 指旧 task（唯一约束）；内容当候选、时间重给，不继承旧确认。
- [Required] cancelled 行展示后不再有任何触发行；取消提交（事务落 cancelled 才算）后排队重试全作废。
- [Required] 对不上账时活动页只说三种话：没记录到触发（原因不明）/ 已错过（给重约口）/ 对不上（暂停等维护者，不怪用户）。
- [Deferred] 独立审计库与巡检：v0 活动页只读本库 task_events；跨库对账进 v1。

## 状态机摘要（产品语义，字段见 schema）

- task：saved→pending_schedule→scheduled（回执）→fired|missed；saved/pending_schedule/scheduled→cancel_pending→cancelled。
- approval：pending→consumed|rejected|expired|superseded；过期顺路清（启动/读取/确认时），不另养后台进程。
- 触发门禁到点先查三样；查到一半变了就先拦、不重查放行，等重新确认。

## R1 个人助理

统一采用自有 LumenUI（基于 shadcn/Base UI）与 Tailwind CSS v4，固定浅色官方 Linen 主题；不维护平行控件、字体或主题，不用手工 CSS 仿造玻璃。完整内容与错误不依赖 toast 或颜色表达。应用覆盖今日、聊天及历史、提醒、批准、活动、完整文档校样、账户及认证，不以代表页或只读对话关联区代替真实工作区。组件接入与功能分层见[技术设计 §6](../design/01-tech-stack-and-repo-structure.md#6-r1-web个人助理与职责边界)。

桌面 1024px 起左侧持续聊天、右侧真实工作区，展开时约等分可用宽度，两区独立滚动；收起工作区后聊天扩宽，正文仍有可读行宽。工作区四个主入口为今日、提醒、记忆、助理（助理资料），设置独立可达；待确认与活动从今日的真实事项入口进入，不形成全局运行审计。工作区内部按自身容器宽度排版，不重复建立整屏固定侧栏。窄屏只显示聊天或工作区一个表面，主要导航为聊天、今日、提醒、记忆、助理五项，隐藏表面不可聚焦、不遮挡输入。Motion 只做局部反馈，尊重减少动态效果，无全页进入位移，首屏不等待动画；方案见[持续对话与工作区](../demo/desktop-experience-plan.md)。

未接通页面只是可读取的能力边界与关联入口，不是新增后台或授权承诺；已有业务操作、冻结内容、时间规则、预算、认证与精确批准合同不因页面重组改变。`/api/[...path]` 继续承担原同源传输，不是业务页面。

选中会话由 `conversation_id` 与可选 `run_id` 表达，工作区导航继承当前身份；`/conversations` 的显式新对话、历史身份深链及认证链接保留自己的目的地，不被当前身份覆盖。`surface=chat` 保留工作区路径但只显示聊天，展开时恢复该工作区，不创建新对话。刷新、深链与返回依 URL 恢复选中身份/表面。根布局的 shell 始终只持有一个不以路由为 key 的聊天实例；工作区往返、收起/展开与窄屏切换不卸载聊天、不重连原 SSE、不重放发送或取消，保留原草稿。显式切换会话、新对话和真正离开应用仍受原在途保护约束。

源码按功能拥有 MVVM 与数据：`account`、`brief`、`approvals`、`reminders`、`conversations`、`capabilities` 的 model 负责类型/数据/协议与纯业务投影，viewmodel 负责状态、显式命令和请求生命周期，view 负责 screen、展示和 DOM adapter，不直接客户端 fetch；无交互状态不建立空壳层。`app/` 仅为路由、RSC、身份入口及 screen 组装；`shell` 拥有持续会话身份、表面和工作区导航，`shared` 只承接 HTTP/会话与无业务 UI，不作为根业务库。`features/conversations/viewmodel/use-conversation-task.ts` 唯一拥有发送、原 Run SSE/GET、明确继续/取消、未知发送保护和幂等键；文档决议、提醒与账户各有自己的 viewmodel。

登录页以欢迎、用户名、密码和登录动作为主，密码可在输入框内显示/隐藏，支持自动填充与粘贴；维护说明在帮助中展开。新密码至少 8 位，上限 128 位仅用于兼容，不要求用户使用超长口令；改版不替换已有口令或改变随机盐哈希存储。建号、转正和退出的明确确认与失败恢复保留。

对话输入常驻聊天底部，消息区独立滚动；「＋」展开提醒和资料工具，选择不执行，已选工具可移除。用户消息为气泡，助手增量与历史消息共用安全 Markdown，历史消息/Markdown 以 memo 隔离更新；生成时可停止，也可编辑下一份草稿，但发送仍受原资格限制，成功结束不清除生成期间已改写的草稿。单一聊天 DOM 滚动 adapter 将内容/viewport 变化合并到 animation frame，手动向上阅读不被强拉到底，可回到最新或定位本聊天内原卡片；工作区保持独立滚动。这些结构不代表已取得性能改善或检查通过证据。运行细节默认折叠，必要批准、明确继续和未知效果仍可见。第二轮沿用同一会话；模型默认简体中文，用户明确指定其他语言时遵从，不翻译代码和专有名称。新 Harness 运行只使用接纳时冻结的最新63条本人同会话可见消息及本轮完整输入，不承诺永久记忆；旧消息仍可独立分页读取。历史恢复不会自动发送下一轮；执行中、批准挂起或效果未知时不能通过新消息绕过原运行。

legacy 资料快捷入口发送前显式选择服务端真实登记；新普通 Agent 无须先选资料模式，接纳时冻结本人有效登记集合，可显式收窄而不默认首项。均不接收宿主 root；无登记不阻断其他能力，无 writable_paths 不等于不可读，原 Run 范围不因新登记或新任务改写。

文档校样页完整展示 before/after、完整目标、版本与 `preview.body`；确认直接提交原 `preview.body` 字符串，不从排版、diff、摘要重建或 trim。批准成功保留全文与授权事实，不自动写入或继续。approved/not_started 为已授权未保存；applied 不等于已核对；verified 依新全文读取证据；unknown 可能已写入，不盲重做。Run 终态与每项效果分开，`can_resume=false` 不等于尚未批准。

会话、Run、消息、事件、批准、任务的打开/分页/刷新/展开与重登恢复只 GET；局部失败保留成功内容和未推进游标，不自动补发消息、决议、继续或取消。批准独立标签不提前断开原流；普通工作区切换保留原连接，不属于离开聊天生命周期。显式身份切换或真正离开活动流仍受原断连取消合同约束，不能承诺后台继续或回滚文件。

只有真实受保护 HTTP 401 引导安全站内返回的重登；403 保留权限/CSRF 含义，404 不作空集合，网络/503 不一概称模型缺配置。账户状态未知不猜空安装，`pending_local_configuration` 不代表模型/资料就绪；原安装登记/重载由部署者经 `local:account` 完成，不换 owner/root/秘密。

本节描述产品行为与源码边界，不声明键盘、断点、真实模型或文件闭环已验收。受控 HTTP 页面观察不等于同一正式安装的 Web/API/native/MCP/PG/模型跨模块证据；后者须独立取得。

## 本人目标内委托（Proposed，#105）

用户明确发送目标后，模型在冻结资格内选择正常步骤；保存默认时区、创建/取消唯一提醒、编辑已登记现有文件及在授权输出目录内创建新文件不逐项批准。多个合理对象/日期冲突只问缺口。创建不得覆盖已有名称，写后独立新全文读取才可验证；已确定零写版本冲突可自行重读，不沿用旧精确许可，unknown 不重做。
本人创建并接受的产物，在后续具备相应输出目录资格的 Run 中可发现和读取；不因此开放目录中其他未登记文件。撞名后的另一个文件即使内容相同，也不自动视为原目标已完成。

未固定名称的零写撞名可在原委托内改名；目标结果将原冲突与真实创建及独立回读明确关联，页面保留未写入事实并显示实际产物。名称是否固定仍由模型理解，系统校验来源和执行事实，不把模型解释视为独立的语义证明。

新profile需要新增影响授权时，允许一次明确、精确范围的“授权并继续”动作，不要求再点一个继续；授权决议本身不是已保存。仍核原Run/有效等待点、当前资格、稳定调用、停止与预算，拒绝/unknown/迟到不得推进，GET/重登不触发；legacy保留原类型的审阅/显式继续合同，HTTP请求数量不在此预设。详见design/20 §3。

页面分别呈现执行生命周期、目标 completed/partial/blocked/unknown 及每项真实 created/排期/取消中/applied/verified。未做和未知不藏在“运行完成”里；用户补缺口只续未完成部分。生成的简报为文件，今日仍是只读投影；UTC/跨冻结时区提醒的列表/详情/今日同交付。

授权修订不等于后台已上线：偏好等先交付可冻结并显示request-bound，断连仍按请求绑定策略收尾，已接受效果不回滚。后台所有权/失联验收完成后，仅新接纳且冻结server-owned的Run在刷新/离开/断网后仅断订阅、原预算/超时内继续；旧/先前Run不随部署改义。仅server-owned的退出不撤已接纳执行，request-bound不承诺退出后继续；停止不取消既成task/回滚文件，禁用阻止新动作。重连/重登只GET；最终重构仍须完成server-owned，详见 [design/20 §1、§4、§8](../design/20-goal-scoped-delegation.md)。
