# 23. R3 短期记忆、同 Run 暂停与 compact

> 状态：**Proposed**；本文是 #144 的设计合同，不是已实现能力或验收记录。
> 范围：通用安全点暂停/继续、手动及自动 compact、新 Run 上下文选择、本人跨会话短期记忆；行为变更先经 OpenSpec 评审。R2-A、已有批准和 delegation 除本文明确对新 profile 的变更外继续生效。
> 非目标：R4 长期记忆、知识库 RAG、独立记忆平台、任意崩溃恢复、自动启用 R2-B、以记忆授权操作或删除原始事实。

## 1. 决定和证据

**建议**先为新接纳 Run 建立与 compact 无关的通用安全点暂停/继续：用户可明确暂停并继续，运行时可为已登记的内部操作请求暂停并在操作结束后受控继续；仓颉在安全点交还控制，conversations 持有资格与暂停点，TS 验证并持久化。手动 `/compact` 和自动触发均以此为前置，调用同一隔离摘要用例，生成有来源、低信任的派生历史。活动任务成功后仍是**同一 Run**，累计预算、权限及已接受效果不变。跨会话记忆只来自用户明确要求记住或 compact 的原消息候选，保存来源并由本人检索；原消息和领域回执始终权威。

[Observed] 当前没有摘要功能或通用暂停。`packages/contracts/src/harness.ts` 的状态只有 running、suspended_approval 和终态；`apps/api/src/modules/conversations/harness-authority.ts` 的 resume 必须匹配批准、waiting checkpoint 和决议，不能拿它模拟普通暂停。流活跃时只允许 `model_next` 和 `answer`；取消先提交终态撤销资格再 abort。`repository.ts` 的接纳选择最近 63 条可见历史加当前输入，读取要求最多 64 个、唯一且当前输入在末尾；快照逐位绑定冻结引用。`service.ts` 在接纳时冻结该集合。仓颉 `apps/harness/src/main.cj` 的 `projectOldest` 是确定性工具观察投影，不是对话摘要。R2-A 的 24 次/64000 tokens 是默认累计 Run 预算，不是模型窗口；窗口与输入计量可未知。详见 [design/18](18-r2a-harness-context.md) 与 [阶段 0](../verification/r3-stage-zero-2026-11-13.md)。

[Observed] 三项阶段 0 证据限制设计结论：

1. 静态梳理确认无通用暂停、流中不能插入摘要、63/64 涉及多个协议边界；批准快照只支持有限等待恢复，不证明任意崩溃恢复。
2. 宿主两次小样本摘要不是 Along 全链路。正式 TS transport 的一次真实请求 31.47 秒后返回脱敏 `HARNESS_PROTOCOL_ERROR`，无正文增量及 usage；原因未知，网络波动只是可能性，不能当作已证实原因。短请求成功并不能解释失败。原材料以更短提示和不同输出上限重试成功，但把项目发布日期错误指代为发布文档发布日期；8 条候选引用存在且对应原文，不代表概括一定正确，也未证明端到端接续、成本或可靠性。
3. PG16/pgvector 0.8.7 对 14 条中文资料的小样本精确余弦可运行；向量和融合的无阈值 top 3 对两条无答案查询仍返回无关资料，编号 `XQ-4792` 的向量第一名是错误的 `XQ-4793`，字面融合纠正排序。该实验不是生产部署、端到端延迟、质量或规模保证，top-k 不是相关性保证。

**取舍**：只扩长窗口或移除 SQL `LIMIT` 既不能无限容纳历史，也无法满足冻结引用与协议；借用批准等待会混淆授权和继续；在每轮后台抽取记忆增加模型调用和来源风险。复用现有模型 transport、PG、编码资产、R2-A 投影及工具事实账，新增的仅是通用暂停、可审计的摘要/记忆事实及编排；不自建向量数据库或第二个 agent loop。仓颉仍决定运行步骤，TS 不是模型驱动的业务执行器。

## 2. 责任与接口合同

以下字段/名称是 Proposed 的语义合同，实施时需落到共享 strict schema、TS/native、存储和 API 并一起版本化，而不是在旧 v5/v6 帧中暗塞字段。旧 profile 走原规则，不能因新二进制扩权。具体 wire 编号应在整合 [design/20](20-goal-scoped-delegation.md) 后统一分配，避免抢占其版本。

| 所有者                        | 责任及边界                                                                                                  |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| conversations / Run authority | 新 profile 冻结、同 Run 安全点/唯一继续、锁序、授权与取消、摘要发布和会话覆盖版本；不执行模型决定的领域操作 |
| 仓颉 Harness                  | 本 Run 的安全点、上下文组装、模型/工具步骤和累计预算；摘要结果只是低信任资料，不是授权                      |
| 摘要用例及模型 transport      | 在预算和大小门下构造独立请求、验证结构及来源，返回候选；不把专用 system 或原始模型响应写入普通消息/工具历史 |
| memory 用例                   | 本人明确记住、compact 候选验证和保存、状态/来源与检索；不创建任务或替代原领域事实                           |
| tools、approvals、领域模块    | 唯一拥有真实调用结果、批准及任务/文件事实；原验证和当前权限继续有效                                         |
| Web                           | 发送明确动作、显示短状态和错误、只读加载历史；不在重连或 GET 自动发动作                                     |

建议的稳定语义接口（示意而非当前 HTTP 声明）：

```text
requestPause(owner, conversation, run, {reason: user | runtime,
             purpose: none | manual_compact | automatic_compact, idempotency_key})
             -> pending | paused(pause_id) | conflict
resumePaused(owner, conversation, run, {pause_id, idempotency_key}, source: user | runtime)
             -> accepted(same_run_id, attempt_id) | replay | conflict
compact(pause_id, frozen_coverage, budget) -> published(summary_ref, coverage_revision)
             | failed(reason, usage) | cancelled
remember(owner, source_message_refs, content, idempotency_key) -> saved(memory_ref) | failure
recall(owner, query) -> {items: [memory + source_refs], completeness: complete | degraded | incomplete}
```

手动 `/compact` 在活动、支持新合同的 Harness Run 上是显式控制动作，不作为普通用户对话发给模型；先请求安全点，摘要成功后由本次手动命令授权的运行时接续**同一 Run**，不是另一次用户授权或批准。自动 compact 由运行时在安全点提出并在成功后按同样资格门继续；普通用户暂停则保持 paused，直到用户明确发送继续，不因刷新、GET、重连或后台计时自动继续。运行时只能继续自己为特定内部操作登记的暂停点，不能消费用户普通暂停或批准等待；用户的继续也不得跳过正在执行的摘要、未决工具或失败处理。原因、目的和允许的继续来源绑定 pause_id 并经 authority 验证，而非由调用方自行声明即可获权。

会话空闲时没有活动 Run 可暂停：用户显式 `/compact` 可接纳一个**用户发起的 compact 控制 Run**，不是系统自动新建 Run 绕预算。它使用正常接纳、owner、预算和生命周期门，在初始安全点进入同一通用暂停与摘要用例；命令作为可信控制输入持久记录，但不伪装成普通会话消息或摘要内容，故该新 profile 须在 start/引用校验中明确支持控制输入，不破坏旧 profile 的当前 user message 约束。摘要成功后受控继续该 Run，报告简短完成并终结，不虚构一个需要继续的旧任务或模型聊天回复；失败按相同预算、取消和回执规则报告。若没有可压缩的已提交消息，明确返回无需压缩，不制造摘要或虚假成功。旧 profile、批准等待、已有暂停或不符合资格时明确返回不可用/冲突，不自动批准或新建隐藏 Run。

语义上使用独立 pause/continue action；现有 `/actions/resume` 与批准的请求结构及行为不变，不能用空 approval 绕过它。`pending` 只表示请求已登记，不表示安全点或摘要已提交。手动操作和自动触发使用相同摘要与继续逻辑；API、Web 只展示简短的等待、压缩、继续或失败状态，不固定输出摘要/记忆清单。

## 3. 安全点、资格与并发

新通用暂停是独立于 `suspended_approval` 的可复用能力，而非 compact 专有状态：至少区分 `pause_requested`、安全点已确认的 `paused` 和可选内部操作处理中；可以用内部子状态表示，不得让旧客户端把普通暂停误识别成批准。暂停不是取消、完成或授权，也不声称已停下正在进行的外部副作用。一个有效 pause_id 绑定 owner、conversation、run、当前 attempt、原因、用途、可继续来源、版本和安全点内容；每个暂停点只能消费一次，幂等键按 owner 绑定完整请求，重用不同参数冲突。不发生 compact 的用户暂停和继续也须满足本节所有安全点、资格、预算、取消与唯一后继规则。

1. 请求在 Run authority 的资格门登记，当前 attempt 不再预约新的模型请求或工具动作，但在途工作先按原协议收尾。活动模型流必须消费至 `complete` 或明确失败，保留已接受 delta 和可得 usage；不能在流中发送 measure、摘要或下一次 model。取消可中止流，不承诺得到完整正文。
2. 在途工具必须等其已接受结果持久化并纳入保护集后才能确认安全点；非事务调用已许可但结果不确定为 `unknown` 时沿现有规则停止并真实报告，不通过暂停、重试或摘要把 unknown 当成功或零写。若进入真正的批准等待，保留原批准合同，不创建普通暂停点来绕过决议。安全点必须没有活动流、无未决工具许可/响应，并持有完整有序状态、`next_call_no`、usage 和必要的观察引用；不能通过重做工具重建状态。
3. 安全点提交和唯一后继在同 owner/Run 资格检查下执行，遵守现有 attempt → Run 锁序及 latest-attempt 重查；涉及会话接纳/发布时按统一锁序取得会话锁，不持数据库事务等待模型、编码器或 MCP。暂停点是新合同专用、有版本的持久状态，保留所有冻结事实与有效观察引用，不能篡改旧 snapshot2 或把通用暂停点伪装为批准 checkpoint。有限暂停点只保证明确协议内的继续，不扩展为任意进程崩溃的通用恢复。
4. 任何暂停期间停止后续 Run 步骤；如有摘要，运行期间也不能继续。普通暂停继续、摘要发布及后继事务均重新检查 pause_id 未消费、来源与用途匹配、同一 attempt 仍有资格、取消未生效、owner 活跃、冻结 allowlist/生命周期及当前资源授权仍有效、累计预算和真实容量允许。原冻结授权不被记忆或当前登记扩张；撤权停止继续，取消仍可用。
5. 同 pause_id 的并发继续或相同幂等键只能产生一个后继；不同键竞争同点只有一个赢家，其余冲突；已完成的同键按持久事实重放，不再生成摘要或执行工具。继续采用同 Run 的后继 attempt 或等价的唯一执行占有，事件顺序跨 attempt 可追溯，旧 pipe 和迟到结果不得再次推进。继续前后不重置累计预算，也不重复 `thread.started` 冒充新 Run。

取消与发布/继续共享资格锁线性化：取消先提交则失效暂停点、拒绝发布及继续，迟到模型输出和候选不能写入；发布先提交则其已提交摘要/记忆作为真实派生事实保留，随后取消阻止继续并保留已接受/未知效果，不能声称回滚既成事实。发布及继续之间取消也必须胜出于未提交的继续。取消先撤资格再 abort，与当前语义一致；可得 usage 即使失败或取消仍按原模型计账规则如实保存，不得在释放锁期间丢失。并发安全不依赖仅靠 abort 成功。

生命周期沿 Run 接纳时冻结的 `request-bound` 或已真实交付的 `server-owned`：[design/20 §8](20-goal-scoped-delegation.md) 的断连、退出和停止语义不改变。request-bound 断连可能取消，重连不能自发恢复；server-owned 只有其真实 driver 和占有合同已交付才能在断订阅后继续。进程在暂停或摘要期间失联时不承诺自动续跑/重放外部调用；按相应生命周期停止或报告中断，保留已提交事实、清理无资格暂存，人工显式新请求不能冒充恢复旧 Run。

## 4. 摘要、覆盖与继续

### 4.1 输入、覆盖和来源

摘要只处理同 owner、同会话、可读的**原始可见消息**的确定有序前缀；输入还可携带已验证来源的上个有效摘要作为低信任材料，但不能把其文字当原消息来源。保护当前完整输入、系统规则、当前任务状态、工具调用身份和接受结果、失败/冲突/unknown、批准及当前决议、必要的完整回取依据；这些由原事实/保护集直接装配，不由摘要代替。R2-A 的确定性工具观察投影和受权回取继续可用，投影不能伪造空结果或丢掉重要失败。摘要中的历史指令、工具正文、记忆均是资料，不能晋升 system 或授予动作。

每个摘要版本绑定 owner、conversation、生成 Run/pause、生成模型/提示修订、原消息有序引用清单、前驱摘要及来源闭包、覆盖区间和提交版本；保存摘要文本、来源引用与生成时间，不保存秘密或混入普通消息。来源须属于冻结覆盖集合、实际存在且同 owner/conversation，候选引用不存在、跨 owner、越界或结构不合法就拒绝发布；来源存在仅证明可追溯，不证明语义正确。对更正、否定、待议、时间敏感事实保留来源和不确定性；后续需要精确事实时回查原文或当前权威领域状态，不能将旧记忆断言为当前提醒/任务状态。

覆盖不以创建时间上界单独推断：会话接纳和摘要发布在共同的会话序列化边界定义已提交消息集合及单调版本，摘要只覆盖显式冻结的有序 ID；时间排序保留 PG 微秒及 ID tie-break，不用客户端毫秒时间。发布 compare-and-swap 验证前驱摘要/覆盖版本及精确来源集合；期间新消息可以接纳，但永不并入已冻结集合，继续作为未覆盖消息。另一个 Run 同时 compact 若先发布导致前驱版本变更，输者冲突、不覆盖赢家；要重新发起须重新冻结、重新计费，不能把旧摘要覆盖在新前驱之上。对跨事务延迟提交的历史行，不以时间戳猜已覆盖；实际不在显式集合的可见消息必须保留，按协议稳定顺序进入后续视图。原消息不删、不改；覆盖是选择视图而非物理截断。

### 4.2 隔离调用和事务

安全点冻结输入后建立独立模型请求，专用 system 指令仅用于要求结构化摘要/带原消息 ID 的候选，原消息作为不可信数据；不提供可执行工具，不把专用 prompt、原始输出或模型中间响应写进普通会话、可见 delta 或工具调用历史。摘要解析后按独立 schema/大小门校验；系统只持久合格派生文本和来源、必要版本及失败元数据，不把模型候选当真实工具回执。模型输出引用合法仍可能产生指代偏移，不能自动认证为正确。

摘要成功时在短事务内复验资格、覆盖 CAS、来源及容量，原子发布摘要与覆盖关系；提交后继续读取该确切版本及未覆盖消息。记忆候选按独立短事务校验并保存，绑定本次成功摘要、原文来源和幂等批次；候选无效或记忆保存失败不回滚已提交摘要，但必须记录真实失败，不能称候选全部保存。用户取消先于各自提交时阻止该项迟到写入；已提交的摘要或记忆保留。候选去重/更正按 §6，不将旧日期或时间敏感状态自动覆写成当前事实。

手动和自动都要预留实际摘要调用的迭代、输入/输出与后续继续空间，并计入执行该调用的 Run 累计预算；活动 Run 内不另开 Run 或虚构免费调用。空闲时由用户明确接纳的控制 Run 使用其自身在接纳时冻结的独立预算，不能作为旧任务的续跑或借口为已耗尽预算的旧任务续命。缺失 usage 的原规则继续将累计 token 标为 unknown，不把估算冒充 verified，不因摘要重置。已有保护集、单次输出、完整序列化帧/HTTP body、模型消息数及可信窗口门仍适用；计量未知不能推算窗口百分比或保证调用成功。超出预算优先 `BUDGET_EXCEEDED`，容量不足 `HARNESS_CONTEXT_LIMIT`；供应商协议失败保持其真实类别，不臆测为窗口不足或自动裁剪重试。

失败、超时、非法输出、来源错误、提交冲突、撤权及预算/容量不足均显示真实失败，不显示摘要成功、不伪装记忆已写入。手动失败后，若安全点仍有效、未取消、当前授权和原上下文容量/预算允许，显式按原冻结视图继续同 Run；否则如实停止/报告不可继续。自动 compact 失败不能反复透明重试或用残缺上下文继续；仅当原候选仍通过全部门且没有硬错误时可继续原视图，否则真实失败终结。暂停点的每次继续也只能消费一次。已提交模型调用不可因为失败而免计账；取消和迟到输出遵守 §3。

### 4.3 自动触发

自动触发只在安全点、下一模型请求之前评估；同一个 Run 对同一覆盖版本至多发起一次自动 compact，避免在无法节省空间时循环。触发需要可信模型窗口和适配的输入计量，以及经实验确定、接纳时冻结的余量策略；**阈值未定**，不能用默认 64000 累计预算或模型名称冒充窗口。窗口/计量未知时不按百分比触发，不阻止用户手动请求；继续使用现有真实字节/消息门和投影，不能通过时明确容量失败。触发之后重新按最终请求计量和序列化检查；摘要本身可能无法装入，必须报告失败而不是保证一定能压缩。阈值及余量要用真实长任务、模型、输出空间和成本测量后定，不把一次 provider 窗口拒绝当可安全自动重试的证据。

## 5. 新 Run 选择与旧合同切换

仅新上下文 profile 取消“最近 63 条”产品选择：接纳事务在共同会话边界冻结可用摘要的确切版本、其已覆盖 ID 集合、截至接纳已提交的未覆盖可见消息和当前完整输入；模型视图为有效摘要 + 未覆盖消息 + 当前任务保护集。不得静默丢掉未覆盖消息或重复加入摘要已覆盖的原文；原始历史仍可通过受权历史接口读取。若无有效摘要则使用截至接纳的原始历史，在实际帧、HTTP body、模型消息数、窗口和预算内组装；装不下就报告容量限制，不回退为暗中的 63 条，也不自动在新 Run 接纳前开额外 Run。是否通过分段处理已有超长历史属于需要真实容量验证的实施设计，不能以静默截断冒充完成。

同步版本化 message_refs、start、snapshot/暂停点校验、TS/native 帧和数据库读取：去掉仅为 63+1 服务的 64 引用上限，不放弃唯一性、有序性、owner/conversation 和精确快照一致性；普通任务 Run 的当前用户输入仍在末尾，空闲 compact 控制 Run 则使用 §2 的独立可信控制输入而非虚构当前用户消息。协议必须在现有 1 MiB 帧/完整模型 body、模型消息数和实际容量门下使用有界表示，不能把无限 ID 列表塞入帧。实现可在可信存储引用不可变的有界清单/分段，并验证完整性和数量；完整清单即使不全进模型也必须可审计。不得先将无界正文聚合进内存再裁剪。新摘要与引用只影响新 profile 或该新 Run 明确暂停点后的视图；原冻结消息、原始 tool_refs、usage 和执行事实不可修改。

旧 Run、旧批准等待和已有 snapshot 一律按原 63/64 及冻结引用精确恢复，既不补新摘要，也不把新工具、资格、预算或授权 profile 回填；已有批准的 hash、目标和显式决议/继续语义不变。若新执行器对旧等待需要适配，仅允许 [design/20 §9](20-goal-scoped-delegation.md) 的受限只读适配；不能安全兼容时升级前安排完成或明确停止，而不是修改冻结记录。R2-A 原有容量门及保护集仍适用，本设计仅对**新 profile**替换其 63+1 选择约束，不提高 1 MiB 等物理上限。

拟议的[用户模型接入合同](22-model-provider-settings.md)若与 R3 同时实施，摘要调用及同 Run 继续须使用该 Run 冻结的本人模型绑定与当前资格；旧绑定不可安全使用时按其合同明确停止，不换用当前默认模型或借 compact 重建 Run。两项 Proposed 合同的实施顺序与协议版本须在集成时协调，互不证明对方已启用。

## 6. 记忆写入、查找与生命周期

**写入来源**只有两类：(1) 用户明确要求记住时，当次以本人原消息和清晰可保存内容走 memory 用例，成功回复必须以实际提交回执为准；保存失败明确报告，不靠助手自然语言假装记住。(2) 手动/自动 compact 时从本次覆盖的原消息提取候选，并在摘要成功后按 §4 独立保存。每轮结束不后台抽取；短会话无明确记住且未 compact 时不保证生成记忆。跨会话来源只能经当前 owner 授权读取，不可由模型自报其他 owner 或虚构 message ID。助手猜测、闲聊或原始资料内的命令不自动变成本人事实或执行委托。

持久实体至少包含 memory_id、owner_id、内容、来源消息 ID 集合及会话、来源类型（明确记住/compact）、创建和修订时间、可召回状态、生成修订、必要的有效期/失效信息；来源与 owner 必须在事务中验证并可回查。用户更正/停止召回针对本人记忆形成新修订或失效标记，保留来源关系；不按字符串相似度盲目合并不同事实或把旧值与新值同时当现值。若冲突或时效不能判定，保留来源及矛盾、不强行覆盖并让模型/用户核实。记忆不是 tasks、提醒、批准或工作区事实；用户明确记住不等于创建这些业务对象的授权。

提供本人查看、来源回查、更正和停止召回的受权动作；不以管理员身份跨 owner 读取内容，运维权限和应用 owner 权限分离。停止召回或过期立即在所有检索路径过滤并使派生索引失效；删除/停用派生记忆不删除原消息、已接受工具结果或备份，备份恢复后须先应用实际保留的失效事实再开放召回。TTL 的具体值、自动清理与历史回填策略**未定**；在选定并实施之前不能承诺某个保存期限或把现有历史全部自动回填。查看和历史 GET 只读，不触发提取或业务执行。

字面索引和 pgvector 向量都是可重建派生索引，按 owner、有效状态、来源可读性及有效期先过滤再排序；绝不能跨 owner 查询后在应用端过滤泄漏内容、分数或数量。记忆明文和来源是事实记录，向量记录绑定 memory 修订、编码模型/资产版本和维度；更新、撤销、停止召回或过期使旧向量不可见，索引缺失不得影响原文权威。查询先识别完整精确编号并优先字面精确命中，再分别检索字面和语义候选并融合；无编号时也保留各路来源和排序依据。不能把相近编号当精确命中，不得因仅返回 top-k 就断言有答案。

`recall` 必须区分：所有所需路径成功且无合格候选的真正空结果；编码器或向量索引不可用但字面可用的 `degraded`；索引尚未覆盖全部有效记忆或某路径失败的 `incomplete`。字面命中是候选，不是已证实相关；无答案时不能将任意向量候选包装成答案。查询需设置经评估的相关性/拒答策略，未校准前不以语义候选做确定事实回答；按来源回查并向用户表明不确定性。top-k、阈值、融合参数及索引类型均待独立中文材料和规模实验选择；阶段 0 的 k=3 与 RRF 参数是实验值，不是生产保证。

## 7. 部署、迁移与回退

PG16 已有数据仍是权威。先备份并演练原安装副本恢复，前向 migration 增加新版本状态、暂停资格、摘要/覆盖、记忆/来源及索引约束；旧数据与旧 Run 不回写。发布前核验实际 PG16 镜像含兼容 pgvector 扩展、安装权限及扩展版本；`CREATE EXTENSION IF NOT EXISTS` 不等于验证已安装版本。向量实现先采用已有 pgvector 能力，初期精确检索即可，规模证据不足不预置 ANN。核验索引建立、owner 过滤和失效一致性后才开放语义召回。

复用或适配现有 `apps/embedding` 固定 BGE 资产和编码服务须核对维度、归一化、资产摘要、许可及运行身份；阶段 0 是直接 CPU 编码，不证明现有 HTTP 服务和生产拓扑可用。服务/扩展不可用时提供 §6 的真实降级，不关闭基本 Run、字面召回或误报空；不能借此启用 R2-B。重建索引按模型修订与记忆版本增量处理，完成前标记 incomplete；回填历史是否进行尚未决定。

分批发布：盘点并处理有效旧批准等待 → 备份 → 停旧写者并前向迁移 → 同批部署匹配的 API/native/Web 和编码/PG 能力 → 校验兼容后仅对新接纳 Run 启用新 profile。新事实出现后关闭新入站、保留数据并前向修复，不能回退到会误读新状态/跳过失效标记的旧写者；不承诺破坏性 down migration。恢复演练包括原消息、摘要/覆盖、记忆状态、版本与可重建向量，且不得把重启等同任意 Run 自动恢复。日志与观测只记录身份安全的版本、阶段、错误、耗时、usage 是否已知及计数，不记录 prompt、正文、向量或密钥；不要把未知成本写成零。

## 8. 分阶段交付与验收

每个阶段可独立评审，但只有最后全链路通过才能关闭 #144；阶段 PR 使用 `Refs`。下面是未来验收要求，非本设计已执行的测试。

1. **共享合同**：评审 OpenSpec、状态机、版本化接口、数据所有权、授权/取消锁序和失败语义，冻结可并行实现的边界；核实旧批准恢复和 delegation 不扩权。
2. **A：通用暂停 + 手动 compact 闭环**：先证明不依赖 compact 的用户暂停保持等待、只有显式用户继续，以及运行时暂停只允许绑定的内部操作继续；取消、重复继续、在途 unknown 和批准等待均不可绕过。真实 Web → TS → native → 模型 → PG，证明活动流结束和工具已接受后暂停、独立摘要、同 Run 继续并消费指定摘要及未覆盖消息；另验证空闲会话显式命令及无可压缩消息语义。并发消息和两个 Run 的 CAS 不丢不重；无摘要/失败/取消/撤权/预算不足均真实报告，原消息及工具事实不变。此时未与 B 集成不得声称已提取记忆。
3. **B：明确记住 + 本人字面检索**：真实保存、读取来源、更正、停止召回；两个 owner、管理员、伪造来源及过期/撤权不得越权，失败不能冒充保存。仅字面路径不声称语义召回完成。A、B 在共享合同固定后可并行，迁移和协议有统一所有者。
4. **集成及自动触发**：compact 候选按来源校验并独立保存，摘要成功、记忆失败和取消竞态分别如实记录；真实长任务在可信计量安全点自动压缩并继续，同 Run 累计预算及 unknown 语义不回归。覆盖计量未知、空间不足、流失败、在途工具 unknown、审批竞争、旧冻结 Run、取消和断连。
5. **语义与总体验收**：真实 PG16、实际编码服务与模型资产分别验证字面、向量和融合，独立未用于调参的中文集覆盖命中、错归因、否定、更正、精确编号、无答案及两 owner；报告各路结果、降级和 incomplete，记录端到端延迟、资源、模型成本/未知用量、版本和未覆盖项。真实安装副本升级、重启、备份恢复及前向修复演练；完成对应合同、行为和 D1–D10 回归，不以阶段 0 样本替代正式路径证据。

待定决策由实施前实验/评审收敛：自动触发阈值和真实可用的计量/摘要预算预留；检索 top-k、阈值、融合和质量门；TTL、失效清理和历史回填；最终 wire/表/API 命名与有界清单表示。若实际供应商不能提供足够的计量或摘要质量、PG/编码部署无法满足 owner 隔离与恢复，须重新评估放行而非扩大为 R4、任意崩溃恢复或宣称已完整交付。
