# 25. 每日新闻订阅与微信投递

> 状态：Proposed
> 范围：本人微信接收绑定、每天采集与整理、投递和历史简报
> 边界：单一接收渠道、本人私聊、按日一期
> 阶段：#213

## 1. 归属与入口

新闻订阅保存用户授权、主题、地区和时间。Along 的微信连接保存本人接收资格。个人 Bot 用于用户从简报发起的后续讨论，会话归属遵从 [design/17 §2.1](17-r1-conversation-history.md#21-个人-bot-与对话归属)。Web 在「设置 → 聊天工具」管理连接，在「新闻订阅」管理订阅和历史。

仓颉 Host 的 `apps/host/src/worker.cj` 启动后台阶段，TS `apps/api/src/bin/host-worker.ts` 提供对应的私有能力入口。新闻处理沿用这一分工，仓颉负责唤醒，TS 负责订阅状态、来源采集、摘要和微信外发，PG 保存事实。现有 [`GET /brief`](../api/brief/brief_routes.md) 继续提供提醒和审批的只读汇总。新闻简报拥有独立发布周期和投递结果，所以 `news-briefings` 持有自己的记录。

## 2. 微信绑定和发送资格

沿用腾讯 iLink 扫码配对作为首选实验路径。Along 以登录态启动配对，服务端按本人及配对会话保存短期状态。确认接收者身份后，持久绑定 `owner_id`、平台接收者、凭据引用及绑定代次。前端只读取连接状态、必要的扫码材料及显示信息。绑定凭据沿用服务端密钥保护，二维码和发送凭据均从日志及历史简报中排除。

连接接口支持读取状态、发起配对、发送测试消息和解绑。用户发测试消息和订阅自动发送共用本人绑定校验。自动发送在取得持久发送许可前读取当前订阅及绑定代次。解绑使旧代次失效，重新配对后由本人重新选择接收绑定。许可已提交时按实际投递结果入账。

iLink 文档记录客户端在缺少 `context_token` 时仍会尝试发送。服务端接受条件由真实配对和短时发送实验确认。实验覆盖扫码后直接发送，以及必要时由用户只发一次绑定消息的路径。验收计时从绑定及测试发送完成后开始，关闭 Along 网页，微信端静默，两分钟后由服务端投递。实测结果用于定下适配器所需凭据及回执判断。[腾讯 iLink 协议](https://github.com/Tencent/OpenClaw-Weixin/blob/main/docs/protocol.md)

## 3. 订阅与每日触发

本人订阅保存主题、可选地区、本地发送时刻、启用状态和微信绑定引用。账户时区决定发送时刻，地区由本人填写或选择。启用前需要有效账户时区与已确认的接收绑定。编辑、暂停、关闭和换绑都会重新计算尚未领取的下一次触发。

Worker 扫描已到期的订阅。TS 以可信数据库时钟读取到期记录，在短事务中认领该本地日期并冻结本期设置、时区与截稿时间。`(subscription_id, local_date)` 唯一。沿用项目时间规则解析当地时刻，夏令时跳过所选时刻时取当日随后第一个有效时刻，重复时刻取第一次。若服务跨过整日本地日期才恢复，只安排仍属当前或未来本地日期的期次。更换账户时区对后续领取生效，已生成内容与日期保持原样，同日期仍服从唯一约束。

PG 记录订阅及期次状态，领取者用有期限的所有权保护未发布工作。任务中断后，接手者只继续尚未发布的当日期次。采集和模型调用在事务外执行，发布时再确认领取资格。收窄订阅时，以提交顺序裁决尚未取得发送许可的操作。

## 4. 采集生成与历史

服务端配置来源名单，首版用 RSS 或公开 API，以本期截稿时刻之前最近一天为采集窗口。主题和地区分别筛选，先按规范化链接去重，再归并指向同一事件的候选。每条要点保留来源名、原文链接和有据可查的摘要。模型仅整理选入的报道，输入视为不可信资料，输出链接限于本期采集结果。用户只选主题与地区，来源出站地址由服务端配置。

期次保存已发布摘要、来源引用、日期、时区和覆盖结果。来源失败时标明部分覆盖或采集失败，正常采集后的空结果另行显示。读取已发布一期始终返回原快照。站内按日期列出本人历史，详情按 owner 隔离。

用户点「和 Bot 讨论」后选择已有 Bot。沿既有流程创建空对话，显式首发时携带本人简报引用，服务端验证归属并冻结该期的有界摘要和链接。打开简报和选择 Bot 本身均不启动 Run。

## 5. 独立投递结果

保存一期简报后，微信发送使用独立投递记录，绑定期次及其接收绑定代次。发送前在短事务中核对订阅开关和绑定资格，并持久取得一次发送许可。事务提交后才调用微信，按实际响应记录已受理、明确失败或结果未知。对方受理表示接口确认接受，前端据此显示「微信已受理」。许可后崩溃、超时或连接中断且无法确认结果时记为未知，系统保留该期简报并停止自动重发。已经确认受理的期次在重复 Worker 唤醒下仍只保留原结果。

微信消息可独立阅读，包含该期要点与原文链接。站内按期展示内容和发送结果，采集与投递状态可分别查看。
