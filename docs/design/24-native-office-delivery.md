# 24. 原生会话资料处理与交付

> 状态：Proposed；行为增量评审通过后方作为实施合同，不代表功能已上线。
> 范围：Web 显式上传的会话资料、确定性任务表分析、原生文件交付及本人委托的一次站内提醒。
> 不包含：办公连接器、宿主路径、跨会话资料库、通用代码执行、自动发送或第三方任务同步。
> 阶段：#158；行为以 OpenSpec 为准，真实运行证据独立记录。

## 1. 目标与责任

用户在对话中显式选择一份 TXT/Markdown 纪要和一份任务 CSV，要求按负责人统计逾期未完成项、列出缺失和非法日期、下载 Markdown 报告及 CSV 汇总，并按原话建立一次站内提醒。生成报告使用本人选定模型，不承诺离线；入口须说明所选资料将提供给该模型。仅请求摘要或统计时不创建文件或提醒。

会话附件不冒充已登记宿主工作区，也不依赖飞书配置。`features/conversations` 持有接纳、会话和历史；原生资料用例持有暂存、解析及交付；`agent/tools` 持有工具资格、调用与回执；仓颉负责受预算约束的轮次；Web 负责草稿、上传和展示。现有 time-core、任务账、站内通知及 Run 生命周期保持各自所有权。

## 2. HTTP、暂存和接纳

以下路径相对 `/api/v1/conversations`。上传 `POST /attachments?draft_id=…[&conversation_id=…]` 接收单文件原始字节、专用展示文件名头和显式 `Idempotency-Key`，身份和 CSRF 校验先于读取；拒绝不支持的内容编码、空内容、非法文件名、格式和 UTF-8。新会话的草稿不创建空对话。元数据绑定 owner、登录 session 和 draft；已有会话另验证 owner。同键同参数及内容摘要返回原附件，不同内容冲突。文件名不作为路径。未绑定草稿撤销限原登录 session；绑定后本人可撤销。无资格方不能通过响应区分资源不存在和无权访问。

BFF 必须在丢弃请求头之前拒绝不支持的 `Content-Encoding`，或仅对上传入口转发该头供 API 拒绝；专用文件名头和幂等键须保留。请求传输可被代理重新分帧，限额以实际读取字节为准，不信任 Content-Length。API 和 BFF 的非 SSE 响应路径须保留产物字节，不能经文本转换。

`POST /messages` 保持 JSON/SSE，办公请求显式提供 `office_materials: {draft_id, notes_attachment_id?, tasks_attachment_id?}`，至少一个角色，每角色最多一个，须为 harness、delegation/1 和显式幂等键。先处理既有请求回执，再在接纳消息、Run 和 attempt 的事务中锁定、消费附件并绑定最终会话；冻结角色、ID、版本摘要与工具清单，不复制字节。普通请求的哈希不变，同一附件不能被不同发送键消费。旧 Run 不自动获得资格。办公模式不隐式继承工作区、历史附件、连接器或记忆工具；扩大资料范围需用户另行显式提交。

若原 Run 因缺少计算所需时区而终止于明确澄清，用户仅补充该缺口时，服务端只在同 owner、同会话、唯一且紧邻的可信关联成立时接纳后继 Run。接纳事务重新核验原输入仍有效且未撤销，引用原冻结角色、版本和请求锚，只增加本次明确补充的时区；该引用是受限续办资格，不是第二次草稿消费，也不复活原 Run。无唯一关联、资料失效或撤销时不读取原件，要求重新明确提交。相同补充请求按原幂等键重放，并发不同键竞争同一待澄清目标时最多一个获得续办资格。原目标的交付和提醒槽位跨该续办关系共享，已接受效果不重复；不能借续办添加资料、扩大授权或重置原运行事实。

同 owner 重新登录后重放已接纳的发送键，只可按原请求定位原 Run，不重新消费附件或获得新执行资格；未绑定草稿仍限原登录 session。下载以服务端读取产物字节前的授权检查为判定点：撤销先于该点提交则不返回字节；已经通过检查并开始发送的字节无法收回。撤销按产物记录的实际来源传播，引用该原件的产物不可再取回，不影响无该来源的产物；无法证明来源的派生产物按受影响处理。

下载 `GET /:conversation/runs/:run/artifacts/:id/content` 验证当前本人、会话、Run、产物和可用状态，只返回已接受且未过期或撤销的内容。响应包含正确类型、长度和 attachment disposition，以及 `nosniff`、`private, no-store, no-transform`；无公开 URL、Range 或 HTML 内联。BFF 仅对此入口透传下载头，保留中止和背压。历史先分页再批量读取元数据，不读取 bytea；GET 不触发执行。

限额建议起点为每附件 1 MiB、每产物 2 MiB、每 owner 活跃字节 32 MiB，草稿和已绑定原件 24 小时、产物 30 天；须经真实并发、RSS、WAL 和备份恢复实验校准。配额并发一致；超限、格式、内容、冲突和配额不足可区分。逻辑失效先于分批物理清理，保留幂等和状态所需元数据。

## 3. 私有数据、运行与恢复

资料元数据和字节保存在有配额的 PostgreSQL 私有存储；写入产物、清单和接受回执可在同一数据库事务提交。文件字节不进入工具 wire。资料正文可按有界片段进入模型请求；它是数据，不是扩权、提醒授权或外发指令。账本只保存引用和回执；确需携带正文的 observation 或恢复数据使用 Along 自有密钥及 owner、会话、Run、attempt 绑定加密。缺钥或绑定错误拒绝接纳或恢复，不能使用飞书密钥兜底或降级明文。

仓颉快照可在 observation、模型上下文和其他恢复字段重复携带正文，因此整个可能含正文的 checkpoint、暂停和 compact 恢复状态均需保护，而非只加密工具账本或删去单一字段。通用存储位置只能持有加密封套，不留正文；办公 Run 禁止跨 Run 自动记忆或 compact 档案吸收正文。恢复必须按原 attempt 和记录身份验证，不能通过省略必要 observation 绕过正式消费者协议；以当前源码构建的正式消费者验证完整恢复。

每次动作复核 owner、接纳 session、attempt/lease、Run 状态及资料资格；断开订阅不重跑，GET 不恢复。取消或撤销先提交则不得接受晚到结果或创建产物；已经接受的效果如实保留。显式撤销阻止原件和派生产物后续取回，不声称收回用户已下载或聊天已交付的内容；原件普通过期不连带产物失效。组合外键约束 owner/会话，唯一约束单次附件消费及同 Run 交付槽位；既有迁移只追加，不修改。

办公来源派生的聊天增量可能先持久化、后发送。按可证明的来源集合在实际流式发送和事件补读前重验资格，并与原件撤销串行裁决；撤销先提交时不得发送受影响或无法证明无关的未交付事件。已发送字节不追溯收回；不能确认已交付时不得凭持久化事实假定已送达。本人历史只保留可安全披露的已交付内容及真实状态，不通过重跑补足被阻止的内容。

## 4. 工具与确定性计算

工具名可在实现前确定；均采用封闭 schema，不能由模型提供宿主路径、SQL、URL、代码、凭证或任意资料 ID。纪要工具读取冻结槽位，返回展示名、版本、稳定行范围、有界正文及游标；截断不能声称已读完。CSV 工具预览校验问题，或依据冻结槽位及截至日计算；返回分析回执、覆盖、分类、负责人分组和带版本与数据记录号的有限样例，明细按固定分析分页。

首版输入为 UTF-8（可带 BOM）逗号分隔 CSV，支持引号、双引号转义、CRLF 和引号内换行；复用经过 Bun 兼容性验证的 CSV 库。固定列 `task_id,title,owner,due_date,status` 可重排；ID 作为文本保留前导零，空或重复 ID、空或重名表头、结构不齐及超限拒绝并定位，不静默跳行。状态仅 `todo/in_progress/done/canceled`；其他状态列为异常。起步限额建议 5000 条、32 列、每字段 8 KiB，另限制输入和模型输出字节。

明确给出并可由用户原话核验的绝对截至日优先；否则从 Run 冻结可信时区和请求锚求本地日期，缺时区只询问缺口，不使用服务器时区。合法公历 `YYYY-MM-DD` 严格早于截至日且状态为 todo 或 in_progress 才逾期；缺日期和非法日期分别计数且不算逾期。负责人去首尾空白后精确分组，空负责人独立于任何字面名称；异常标签可重叠。同版本和截至日应给出相同排序及统计。

交付工具接受已接受的纪要读取和 CSV 分析引用及有界说明；服务端渲染文件。模型可解读纪要，统计表和负责人汇总 CSV 只能来自已接受分析事实，不能使用模型回显数字或拼接的 URL。引用必须属于同 owner、会话、Run 和版本。Markdown 首版允许纯文本预览；富文本须先验证安全渲染。CSV 对不可信单元格的控制字符、前置空白后的公式前缀及全角变体转换为明确安全的展示文本，不改变原始记录；不承诺表格客户端二次另存后仍安全。

## 5. 效果、提醒与呈现

一次交付请求所需格式的产物清单、字节和成功回执同事务提交；相同 invocation 重放返回原回执。不同 invocation 重提同 Run 交付时以唯一槽位和规范化参数摘要返回相同产物或明确冲突，不覆盖。提交响应丢失时读取既有回执。正式目标结果的 `receipt_refs` 必须引用已接受调用并核对产物实际存在；附件 ID 或模型自造 URL 不是交付凭证。

复用现有提醒工具、可信时间锚、时区和任务状态；本组合目标先交付文件，再处理用户原话明确要求的一次站内提醒。表格截止日不是提醒授权。该 Run 的提醒动作槽位与任务创建同事务，避免模型换调用 ID 重提产生重复；另发的明确新请求不受全局文案去重影响。文件已交付而提醒因歧义、过窗或取消未建时分别报告事实；仅补时间缺口不重做文件。只报告真实状态，不承诺触发或送达。

## 6. 迁移、验证与回退

通过前向迁移建立私有元数据、字节、输入绑定及交付清单；不改变既有业务表和旧 Run 的权限。新办公接纳默认关闭，关闭后保留历史读取、撤销和清理。切回不识别新 Run 状态或快照的旧构建前停止新接纳并排空相关 Run，不通过删表回滚。备份按私有资料处理。

验收分别覆盖生产 Next/BFF 与 Elysia 真实字节、限额和中止，正式仓颉 start/调用/checkpoint/恢复/预算，真实 PG 的接纳与效果竞争、提交丢应答及旧库升级恢复，以及生产 Web 使用真实模型完成选中资料处理、两个下载和未来提醒入站。核对未选内容不进入模型、跨 owner 零披露、重复请求零重复副作用及成功回执对应可下载字节。黄金输入覆盖昨天/今天、完成状态、缺失和非法日期、非法状态、空负责人、Unicode、引号内换行与重复列；独立复算 CSV 并核对 Markdown 来源。记录真实路径、版本、未覆盖项、完成率、澄清、错误副作用、p95、RSS、WAL 和清理积压；纯合同或受控消费者测试不冒充真实模型验收。
