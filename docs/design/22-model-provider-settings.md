# 用户模型接入与运行绑定

> Proposed：[OpenSpec change](../../openspec/changes/add-model-provider-settings/proposal.md)。本文定义目标合同，不证明路由、SDK、Web、迁移或真实供应商验收已完成。原部署级合同仍适用于未切换部署；切换后本设计取代 design/14 §9、design/18 §3 对新 Run 固定部署模型及无 registry 的限制。API 和数据分别见 [API](../api/model-providers.md)、[schema](../schema/model-provider-schema.md)。

## 1. 决定与边界

当前 `harness-config.ts` 按部署装配模型 transport；`context-policy.ts` 将模型和 adapter 冻结到只追加策略，`harness-authority.ts` 恢复时比较当前部署模型。现有 `conversation_idempotency` 对 owner/key 保存24小时决议，冲突回读。以上为静态现状，不是部署验收。用户需要本人多个接入、默认及逐 Run 选择；依赖当前默认恢复将改变原 Run，往原策略追加字段又违反现有约束。

选择本人接入及不可变版本引用，Run 同事务绑定并独立冻结无秘密展示快照；保留原策略结构与唯一仓颉循环。TS 管身份、出站、密钥、持久事实和单次传输，不由 SDK 执行工具或自动 Agent 循环。不建设供应商目录、第三方能力保证、计费或通用插件。与把唯一部署 Key 复制给所有人相比，显式 owner 导入避免跨账户泄漏；与改写原 checkpoint/策略相比，新引用保留历史事实，但须明确旧 Run 不能安全绑定时的处置。

## 2. 配置、安全及发现

provider 为用户自定义接入而非供应商类型；model ID 是区分大小写的不透明完整字符串。无 Key 端点可用，不以 `has_api_key` 判断连接能力。仅 HTTPS 或受控本机连接可发送 Key；加密密钥与数据库分离，AES-256-GCM 认证加密并绑定 owner/provider，配置材料 `MODEL_PROVIDER_ENCRYPTION_KEY` 为 base64 编码的 32 字节，不能进仓库、日志或数据库。全 Key 不进入普通 GET、错误、日志、Run、checkpoint、SSE 或浏览器持久存储。提示不含实际密钥片段亦可为空。

凭据操作显式 keep/replace/clear，省略等于 keep；地址改变不得静默向新地址发送旧 Key，必须替换、清除或另有明确授权。测试未保存地址仅允许明确新 Key 或明确不发送 Key，沿用旧 Key 只能访问绑定的已保存地址。变更生成版本；replace 不撤销旧版本，clear/delete 撤销受影响旧版本的后续凭据使用；即使请求已发也不声称可撤回数据或既成工具效果，停止运行须使用原取消入口。

同步读取已保存版本，事务外请求 OpenAI 风格 models 列表，成功去重合并，不删除已有手动项；写入前重新核验版本，地址、凭据或启用状态已变则冲突，不将过期结果并入新配置。失败保持原列表，手动增删支持完整 ID。检测使用合成内容，不创建 Run、不发送历史、不调用业务工具；分别报告文本流、工具往返、usage 的实测状态，不把未测写成通过。

每个接入独立保存一个可选默认模型，选择范围仅限该接入已登记的模型；设置要求接入启用且地址已保存，但不要求 Key。设置某接入默认时同时将其设为对话全局默认；清除非全局接入的默认不改变全局默认，清除当前全局接入的默认则同时清除全局默认。删除接入或模型时同步清除相应默认，不自动选择替代。旧全局默认迁移为所属接入的默认。

所有推理、同步和检测共享出站策略：默认禁止本机、私网、link-local、云元数据等内部地址；部署者仅可对明确本地模型目标有限放行。校验 HTTP(S)、DNS 及实际连接地址，禁止重定向，并防 DNS 重绑定；不依赖单次解析或应用层 URL 字符串校验。API 容器 localhost 不等于浏览器所在电脑。不得透传 SDK 原始异常、上游正文、认证头或请求内容。若不能约束实际网络连接，此能力不得标为可安全交付。

部署者可用 `MODEL_PROVIDER_ALLOWED_LOCAL_ORIGINS` 列出逗号分隔的精确 HTTP(S) origin（含端口）；仅允许 IP 字面量的 loopback、RFC 1918 和 IPv6 ULA，DNS 名称、link-local 与云元数据不在此例外中。`outboundFetch(input, init)` 是 SDK 可注入的流式网络边界：检查 DNS 的全部结果，并将通过检查的地址固定到本次实际连接；不复用连接，不跟随重定向，传递取消，HTTPS 仍按原主机校验证书。模型发现复用同一边界；SDK 工厂必须显式使用它，不能回退全局 fetch。

公网模型接入必须使用 HTTPS；HTTP 只允许部署者明确放行的本地 IP origin，避免 Key 和对话内容明文传输。同步、检测与推理均在同一出站边界执行该限制。

受信任 DNS 代理使用 Fake-IP 时，部署者可通过 `MODEL_PROVIDER_ALLOWED_FAKE_DNS_ORIGINS` 明确列出完整 HTTPS origin；仅对应域名解析出的 `198.18.0.0/15` 地址适用。端口和域名精确匹配，HTTP、IP 字面量、其他保留或私有地址不因此放行；所有解析结果逐一检查并固定连接，TLS 验证原域名，重定向仍禁止。此例外不证明代理路由或供应商可用。

草稿检测复用与 Run 相同的单次 SDK 模型 transport 和受控出站，以合成消息进行文本与独立工具往返，工具结果由检测流程构造，不执行业务工具或写 Run；草稿密钥仅存在于本次调用。无模型 ID 时三项均为 `not_tested`；有模型但未注入 transport 时明确不可用。

## 3. 接纳、重放和恢复

先按现有身份、owner 和幂等规则检查有效记录。请求哈希纳入客户端显式提交的 provider ID 和完整 model ID；省略保留原哈希，省略与显式选择不同，即使两者当时解析到相同默认。同键同意图重放原 Run，保留原冻结决议，仍校验当前身份与读取授权；不同意图 409。并发唯一键冲突后重读并按同一哈希重放或冲突，不重新按默认接纳。仅未命中时在接纳事务解析本人有效、启用且列表内的选择，省略时读本人默认；无默认、已失效或跨 owner 明确失败，不猜替代。

拟议模型 Run 同键重放不因原 Run 仍 running 而返回现行 409：POST 只读交付原 Run 已持久事件前缀（可为空）并结束，不新建或跟随执行；客户端需要后续事件时从实际游标使用原 Run events GET 补读并跟随。这是对现行接流规则的拟议变更，身份撤销和披露授权仍须检查。

在同一事务持久 Run、原上下文策略和 `(run_id, owner_id, version_id, provider_id, provider_name, model_id)` 绑定。策略 model 与 adapter 仍匹配，版本引用只用于该 Run；显示快照独立保留，不包含地址、密钥、密文、内部版本。恢复时验证原身份/资格、预算、等待点和冻结策略，按原版本解析，不比较当前默认，也不转用新版本。Key 撤销或版本不可用时明确失败，不执行新模型调用。详情与历史列表分别投影 available、legacy_unavailable、not_applicable，按原 owner 边界只读；没有证据的旧绑定绝不从模型名、邻近 Run 或当前默认推测。SSE 词不扩展。

## 4. 传输和发布门

Vercel AI SDK 只可担当单次 Chat Completions 传输。现有工具资格、原子副作用、累计预算、取消、批准恢复、未知 usage 不变；多个工具提议全部不执行，按 native 既有行为在原预算内逐项决策。SDK 默认行为不得假定等价：受控实验曾见缺 `[DONE]` 被接受、默认重试及请求体差异；必须独立证明严格流 EOF/终止、损坏 UTF-8/截断/超限、准确发送前计量等于实际字节、纯计量零请求、无隐式重试、脱敏错误及 abort。无法实现这些约束时不得宣称完成 SDK 切换。

升级停旧写者，备份与识别旧库后仅追加迁移，管理员显式指定唯一目标 owner 才能导入原部署配置；不复制给所有账户，也不共享兜底 Key。旧无新引用 Run 沿原冻结合同，只有能够证明原模型和可信凭据身份、且原等待资格满足时才能继续；否则明确不可恢复，保留历史、预算、checkpoint、接受效果，不重做工具。读取不补写或启动执行。迁移失败不开新写者，修复后前向恢复；已接纳新事实后不能通过旧二进制无损回滚，停接纳并按备份/前滚处置。隔离升级副本需覆盖中断和旧等待，不触碰真实安装。

## 5. 验收与证据

分别验证双用户隔离和凭据生命周期、同步失败和版本竞争、默认及显式选择/并发幂等、历史稳定、旧部署迁移及等待处置。正式 Web → HTTP → SDK → 仓颉 → 真实受控工具 → 模型后续请求 → PG → 刷新补读独立取证，覆盖流/取消/预算/批准恢复；再经授权使用指定真实服务单独验收流、工具、usage、错误和取消。受控服务不证明真实供应商，配置存在不证明模型可用，本机模拟不证明实际部署网络或 HTTPS 安全。
