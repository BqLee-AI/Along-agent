## 8 冲突裁决

| # | 冲突 | 裁决 | 理由 |

| 1 | B03 微服务（9 服务） vs 单体模块化 | 单体胜 | v0 团队规模与运维成本；五缝接口化保留替换能力（harness 可替换落点） |

| 3 | B04 仓颉直连记忆/知识 vs 永不直连业务库 | 永不直连胜 | 安全隔离 + 瘦边界；上下文由调用方传入 |
| 4 | B02 MVP 5 件 vs v0 12 端点切片 | 12 端点胜 | 确认门/时间层/事件账三差异化必须进 v0；纯对话 MVP 不足以立住产品 |
| 5 | B06 本机库（SQLite） vs Postgres 唯一源 | Postgres 胜 | 云端多租户 SaaS + 自托管单镜像；本机版表述（关机错过/不保常驻）转为诚实口径保留 |

| 8 | WebSocket 实时 vs SSE 先行 | SSE 先行（v0），WS + `ws-ticket` P2 起 | WS ticket 方案 P2 起，v0 用 SSE |

## 06 不变量保留（迁移云端仍有效的实验起步值，待校准）

- 五条总闸：没点头不进钟 / 没把握就说没把握 / 对不上就停 / 只追加不涂改 / 能量什么才敢说什么。
- 时间入口规则：依赖顺序（时区→日期→时刻）、可直接归一 vs 必须问分界尺、模糊词一律挡、“明天”锚、夏令时两天、存摆分家。
- 归一 4 基准 + 错误出口（`NONEXISTENT`/`AMBIGUOUS`带候选/`TZDB_UNAVAILABLE`/`UNKNOWN_TIMEZONE`）。
- 确认规则：整句确认才算、24h 有效、两条待确认挡回、三件套（`c_id` + 全文 + `presentation_hash`）、连点同一 R、展示层死规矩、模板版本化。
- 状态机与门禁：R 状态流、触发三查、outbox 30s 扫、3 次退避（1min/5min）、15 分钟线、取消优先 + 安全指标（取消后发出数 = 0）。
- 诚实口径天花板：`OS_ACCEPTED` 只证明接口收了；只能说已记录步骤可核对。
- 全是待校准实验起步值：24h 有效 / 15min 线 / 1min 锚 / 30s 扫 / 3 次退避——迁云端后以可测指标校准，不当常量崇拜。
