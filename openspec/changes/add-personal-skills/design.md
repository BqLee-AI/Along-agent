# 自定义文本技能

用户可以把一套工作步骤保存为技能，分配给一个或多个本人 Bot，在发送某条消息时选用。以周报为例，正文可以约定按「结论、证据、待确认事项」组织输出。选择「周报」后发送素材，消息上显示实际使用的技能版本。

## 现有接入点

`/skills` 渲染预留页。`personal-bot-settings.tsx` 已管理个人 Bot 的角色说明、工具与资料范围。`admit-message.ts` 在接纳事务内冻结 Bot 配置的一部分。`bot-prompt-scope.ts` 在实际模型请求中附加冻结的 Bot 指令，`model.ts` 用同一输入完成计量并在供应商请求提交前检查当前权限。本方案沿用这条链路，在 Bot 配置与单条消息间加入技能分配和选择。

## 创建、分配与使用

- 技能页展示本人技能、用途、版本和停用状态。创建时填写名称、用途、正文，也可以选取本地 `SKILL.md` 并在预览后保存。前端显示字段错误与冲突并保留未提交内容。编辑和停用需要提交页面所见的版本。
- 导入支持 UTF-8 单文件、YAML frontmatter 和 Markdown 正文。遵循 Agent Skills 的 `name` 与 `description` 字段约束。服务端用仓库锁文件已有的 `yaml` 库解析，并将其声明为 API 的直接依赖。文件限定 64 KiB，正文限定 16 KiB（UTF-8），拒绝无效 UTF-8、重复键和 YAML 别名。`license`、`compatibility`、`metadata`、`allowed-tools` 可作为导入预览中的附加信息，持久化的运行字段只有名称、用途和正文。预览明确说明 `allowed-tools` 不改变授权。正文中的路径和链接按文本处理。完整目录、脚本、附件和远端安装需要独立的格式与执行合同。格式参考见 [Agent Skills specification](https://agentskills.io/specification)。
- Bot「技能」设置选择本人有效技能，复用 Bot 的版本比较。对话输入区只列该 Bot 当前可用的技能，每次最多选一个。提交成功后清除选择。刷新历史时展示已接纳的名称与版本，无需依赖当前技能状态。失败时保留文本和选择，用户可以刷新可用技能、换版本，或去掉选择后发送。

## 数据与请求边界

- `personal_skills` 持有 `id`、`owner_id`、`current_revision`、`disabled_at`。`personal_skill_revisions` 以 `(skill_id, revision)` 标识不可变版本，保存 `name`、`description`、`body`。一次事务同时写版本和推进当前指针。停用为终态，保留版本以便历史展示。不同技能允许同名，所有关联使用 UUID。空库与已有账户迁移后均无技能分配。
- 在 Bot config 中加入 `skill_ids`，旧记录按空数组解码，Bot 写入仍以现有 `revision` 校验。服务端在 Bot 更新事务中验证所选技能均属于本人且有效。已分配技能停用后立即从消息选择列表移除，Bot 设置仍可移除该分配。关系的当前事实源为 Bot config，资格由 Bot config 与技能状态共同判定。
- 提议接口为 `GET/POST /api/v1/skills`、`GET/PATCH /api/v1/skills/:id` 和 `POST /api/v1/skills/:id/actions/disable`。列表用现有分页约定，`GET /api/v1/bots/:botId/skills` 返回该 Bot 的有效技能元数据。创建复用幂等请求约定，接收结构化字段或原始单文件内容。导入预览为使用同一解析规则的无持久写入接口 `POST /api/v1/skills/actions/preview-import`。更新和停用携带 `expected_revision`。停用以条件更新设置 `disabled_at`，保留最后一个内容版本；停用后的内容不可修改。跨账户 ID 与不存在统一返回 404，非法文本返回 422，过期版本或同幂等键异内容返回 409。所有写入沿用认证与 CSRF。原生 Host 和 TS 路由使用同一业务用例。
- 新消息可携带 `skill: { id, revision }`，版本取自用户看到的可用项。接纳事务按 Bot、技能的顺序锁定状态，校验归属、分配、有效性与当前版本。选择进入现有发送幂等比较。精确重放返回原消息和 Run。新 Run 冻结 `{id, revision, name, body}`，消息历史保存 ID、名称和版本，随消息与 Run 原子提交。旧消息和 Run 缺少该字段时走普通路径。资格变化拒绝接纳，并提示可刷新选择。超过模型上下文预算时使用已有的 `HARNESS_CONTEXT_LIMIT`。

## 模型执行与撤销

TS 在现有 Bot 指令组装处附加一个有明确来源的用户技能段，宿主规则优先，同轮明确要求优先于技能默认步骤。相同有效输入用于测量与供应商发送。只有显式选择技能的 Run 加入正文，后续普通消息、历史重读和摘要不自动重加载。用于 compact 的摘要输入不包含技能正文，测量下一次对话请求时仍计入该 Run 的有效技能输入。带技能的消息使用模型路径，避免只读直达绕过选择。

Run 继续执行时沿用原冻结版本，修改正文只影响新选择。每次携带正文的模型请求提交前，用现有提交事务依次锁定 Bot 与技能记录并校验当前分配和停用状态。停用或移除先提交时阻止披露，用户看到本轮因技能资格变化受阻。已经提交给供应商的请求按现有 Run 生命周期处理。工具权限与资料授权仍由冻结 Run 范围、当前 Bot 范围及业务资格共同决定。审批判断继续走既有用例。仓颉继续负责会话编排，TS 负责技能存储和构造供应商输入。

## 验收

用受控模型记录实际收到的输入，验证选择一版、编辑后选择二版、精确重放、普通消息不注入、预算和授权。使用可同步的提交竞争测试证明先停用会挡住下一次模型请求。用真实原生 HTTP 和浏览器走通导入预览、保存、分配、发送、重读历史、取消分配和停用。在真实模型上验证周报示例的输出规则，区分模型表现与确定性权限证据。
