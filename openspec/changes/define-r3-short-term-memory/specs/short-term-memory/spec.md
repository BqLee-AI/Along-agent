## ADDED Requirements

### Requirement: 有来源的短期记忆与 owner 隔离

系统 SHALL 仅从本人在记忆页提交的内容、用户在对话中明确要求记住的内容或 compact 的有来源提取建立记忆。记忆可服务同一 owner 的跨会话请求，但不得跨 owner 读、写、检索、引用或泄露。手动条目的来源是本人提交的实际内容与修订；聊天衍生条目的原始用户消息及真实事件是事实权威。提取时须记录并校验真实来源、所属 owner 与覆盖范围，不把助手猜测、无关闲聊、错误来源或未核实的摘要写成确定事实。所有记忆都不是执行授权。见 [design/23](../../../../../docs/design/23-r3-short-term-memory-and-compact.md)。

#### Scenario: 明确记住与 compact 提取

- **WHEN** 用户明确要求记住事实，或合法 compact 提取候选
- **THEN** 来源和 owner 可追溯且真实存在，候选不自动取得高于原文的权威；模型将项目发布日期误指为发布文档发布日期等偏移不得在未核对来源时作为可靠事实发布

#### Scenario: 在记忆页添加本人记忆

- **WHEN** 本人提交项目、偏好或目标的分类与非空内容
- **THEN** 保存成功后在本人记忆页显示实际内容、分类和「本人手动添加」来源，不创建占位聊天，不要求模型成功，也不扫描历史对话。失败保留本人填入的草稿，不展示为已保存。

#### Scenario: 管理手动记忆

- **WHEN** 本人从记忆页更正手动条目的分类或内容，或停止使用该条目
- **THEN** 更正形成同一记忆的新修订；过期的编辑不能覆盖新修订；停止后不得再从任一检索路径召回，包括旧语义索引。现有聊天记忆继续保留其原文来源，不强行补分类。

#### Scenario: 信息更正和时效

- **WHEN** 原文中先前事实被更正，或记忆描述时间敏感状态
- **THEN** 保留可追溯来源及更正关系，不以旧值覆盖新值，不把过去状态当成当前已确认事实；冲突或来源不足时如实表达不确定

#### Scenario: 跨会话与越权

- **WHEN** 同一 owner 的新会话检索记忆，或另一 owner 猜测来源、记忆 ID 或查询文本
- **THEN** 前者只在当前权限及有效来源下使用本人记忆，后者不得读取或推断他人内容；权限撤销或源不可访问不通过索引绕过

#### Scenario: 本人查看、更正与停止召回

- **WHEN** 本人查看记忆及来源、更正内容或明确停止召回
- **THEN** 读取只读，变更形成可追溯修订或失效事实；停止召回后各检索路径立即排除该记忆及旧索引，不删除原消息或已接受领域事实

### Requirement: 有界检索不把相似度当事实

系统 SHALL 以原始事实为权威、以字面索引和 PostgreSQL pgvector 向量索引为可重建派生检索手段；检索先施加 owner 和适用权限过滤，精确编号命中优先于近似编号。top-k 是候选上限而非相关性、答案存在或事实正确的保证；top-k、相关阈值、TTL、历史回填及自动触发数值不因小样本固化为质量保证，代表性实验与调优不作为本次 MVP 合并前置。

#### Scenario: 精确编号优先

- **WHEN** 查询 `XQ-4792`，候选中存在精确编号及相似但不同的 `XQ-4793`
- **THEN** 精确字面匹配优先，不因向量相似度更高把相似编号当成目标；结果仍需核对原文

#### Scenario: 无答案与无关候选

- **WHEN** 向量 top-k 返回若干候选但没有支持查询的相关事实
- **THEN** 不以返回 k 条声称找到答案；可以明确无匹配或证据不足，不编造事实，不把相似度当确定性证明

#### Scenario: 派生索引缺失或失败

- **WHEN** 索引尚未构建、损坏或向量检索不可用
- **THEN** 明确区分受限降级、真实空结果和依赖失败；可用的字面路径只能返回其实际找到的受权结果，不能把降级当完整检索或以陈旧索引代替原文，不跨 owner 回退
