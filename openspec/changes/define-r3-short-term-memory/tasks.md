# #144 任务与证据（Proposed）

本文件是未来经授权实施及验收的清单，不是当前实现声明。阶段 0 的有限证据见[实验记录](../../../docs/verification/r3-stage-zero-2026-11-13.md)，设计真源见 [design/23](../../../docs/design/23-r3-short-term-memory-and-compact.md)。

## 合同与实施

- [x] 1.1 根据阶段 0 静态梳理、真实摘要调用和独立 PG16/pgvector 小样本形成 Proposed 设计与增量；标明协议错误原因未知、重试摘要指代偏移和实验局限。
- [x] 1.2 合同评审明确安全点与批准等待区分、消息覆盖和并发裁决、来源校验、失败语义、当前授权及旧 Run 兼容，完成后另行授权实施。
- [ ] 2.1 实现通用同 Run 安全点暂停/继续及持久状态；覆盖流结束、在途工具 accepted/unknown、取消与重复/并发继续、预算和权限；不将其扩展为任意崩溃恢复。
- [ ] 2.2 实现手动 `/compact` 与自动触发共用摘要、隔离输入输出、来源及覆盖记录，原子处理取消和新消息竞争；失败、部分输出、usage、容量及原事实保持如实。
- [ ] 2.3 完整迁移新 Run 的 63 消息和相关引用上限及消费者，保留容量门；旧 Run、批准继续、只读历史及冻结输入保持原语义。
- [ ] 2.4 实现明确记住与 compact 来源的 owner 隔离记忆、原文权威及字面/pgvector 派生索引；精确编号优先，并明确无答案、索引不可用和权限拒绝。
- [ ] 2.5 在独立代表性数据上测量召回、错误命中、无答案、中文、编号、并发和时效，依据证据决定 top-k/阈值、TTL、历史回填及自动触发策略；未定参数不得伪装为质量保证。

## 真实验收与收口

- [ ] 3.1 真实 Web → TS → native Harness → 模型/工具/PG 验证手动和自动 compact，关联原 Run/attempt、真实来源和最终答复；验证流结束及已接受工具结果，不以单独 completion/transport 代替全链路。
- [ ] 3.2 通过真实竞争覆盖暂停/继续/取消、完成与授权撤销、摘要提交与新消息、工具 accepted/unknown；验证单一裁决、无副作用重放、无迟到写入和真实失败展示。
- [ ] 3.3 对超过 64 条历史、容量不足、预算耗尽/usage 未知、旧批准等待/旧运行及多 owner 跨会话检索验证完整边界；记录原文、摘要和派生索引一致性，不以测试数据代表生产质量。
- [ ] 3.4 按实际执行范围记录测试、实验及剩余缺口；独立评审通过且完整验收后才归档变更、同步生效规格及关闭 #144。
