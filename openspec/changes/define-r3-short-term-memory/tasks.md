- [x] 1.1 根据阶段 0 静态梳理、真实摘要调用和独立 PG16/pgvector 小样本形成 Proposed 设计与增量；标明协议错误原因未知、重试摘要指代偏移和实验局限。
- [x] 1.2 合同评审明确安全点与批准等待区分、消息覆盖和并发裁决、来源校验、失败语义、当前授权及旧 Run 兼容，完成后另行授权实施。
- [ ] 2.1 实现通用同 Run 安全点暂停/继续及持久状态；覆盖流结束、在途工具 accepted/unknown、取消与重复/并发继续、预算和权限；不将其扩展为任意崩溃恢复。

- [ ] 2.4 实现明确记住与 compact 来源的 owner 隔离记忆、原文权威及字面/pgvector 派生索引；精确编号优先，并明确无答案、索引不可用和权限拒绝。
- [ ] 2.5 核对语义候选的来源回查、精确编号、降级和 incomplete 基本行为；不把候选或小样本冒充事实或质量保证。代表性检索基准、调优、TTL 和历史回填不作为本次合并前置。

## MVP 验收与收口

- [ ] 3.1 按实际源码版本记录隔离 Web → TS → native → 真实模型/PG 的运行中与空闲手动 compact、自动 compact 和同 Run 继续，以及跨会话记忆与真实编码器/pgvector 召回来源；分别记录 usage、结果和限制，不以单独 transport 代替全链路。
- [ ] 3.2 按实际覆盖汇总暂停/显式继续、取消、不重放、权限撤销、来源和消息竞争、工具 accepted/unknown、失败和预算/usage 的受控安全证据；明确未覆盖组合，不因未做代表性基准放宽安全行为。
- [ ] 3.3 汇总长历史、容量、跨 owner、更正和停止召回、降级以及旧批准等待/旧 Run 冻结资格的基本证据；隔离合成安装升级和备份恢复分别记录范围，不将其等同真实安装或完整旧 Run 恢复。
