## ADDED Requirements

### Requirement: 唯一原生 Harness 内的只读路由模式

系统 SHALL 仅在正式仓颉 Harness 内提供 Proposed 的 off/shadow/enforce 只读首步路由，默认 off；仓颉唯一决定下一步、目标工具及停止，TS 仅提供可信事实、匹配/参数来源、编码打分与既有 authority/网关/持久化/纯展示，不另建 TS Agent 或复制双语言规则。执行选择、接纳前提和模式见 [design/19](../../../../../docs/design/19-r2b-readonly-intent-routing.md) §1、§3–§4、§7。

#### Scenario: 默认关闭与原执行选择（D1/D8）

- **WHEN** 请求省略 execution、显式 business，或新 Harness Run 使用默认 off
- **THEN** 省略/business 保持原业务；off 的正式 native 不 probe、不编码，沿原模型路径；不新增 auto、伪 toolcall 或第二 TS 决策循环

#### Scenario: shadow 不执行潜在候选（D8/D10）

- **WHEN** shadow 得到可接管候选，包括完整 L1 命中或 L2 高分候选
- **THEN** 仅记录潜在证据，唯一最终决议为 fallback；不为 shadow 调业务 handler/旁路工具、不替换原模型回答，不宣称已经免模型交付

#### Scenario: enforce 与主运行依赖（D8/D10）

- **WHEN** enforce 命中已批准意图，或主 native/模型/协议依赖不满足原接纳前提
- **THEN** 前者仍由正式 native 提交并经 TS 资格核验；后者保留原类型化失败，不以可能命中 L1/L2 绕接纳或切到业务/fixture

### Requirement: 首步路由资格与不可变执行事实

系统 SHALL 仅在 fresh 首 attempt、首次模型之前提供一次路由机会，在新 Harness Run 原接纳事务中保存首 attempt 的不可变路由策略（off 亦记录）；实际启用路由时保存唯一终局决议，direct 展示实际接纳时保存 render 回执，均为只追加内部事实，不能补造未发生的步骤。旧 Run 缺路由策略等同 off，不能由恢复或只读访问补入；R2-A context policy 的独立规则不因此改变。见 design/19 §7–§8、§10。

#### Scenario: 新 Run 接纳与并发决议（D6/D8）

- **WHEN** 新 Harness Run 被接纳，或同一首步相同决议重交/冲突决议并发
- **THEN** 策略与首 attempt 同事务提交；相同已存决议仅回原回执，冲突拒绝，不重编码；policy/decision/render 的首 attempt、同 kind 唯一及来源关联受持久约束，不能更新或删除

#### Scenario: 旧 Run、GET 与同键重放（D6/D8）

- **WHEN** 缺路由策略的旧 Run 被读取，或 GET/同入站幂等键重放既有 Run
- **THEN** 不分类、不新写路由策略/决议、不新建 attempt 或工具；旧 Run 路由为 off，重放只返回原允许公开的事实，running 沿原冲突规则

#### Scenario: 批准继续与进入模型后（D8/D9）

- **WHEN** 有效批准等待点显式恢复，或本 Run 已开始模型调用
- **THEN** 路由资格禁用，不补策略、不 probe、不重新分类；恢复只沿原 snapshot2、冻结上下文/预算/allowlist，不将路由账作为新恢复点

#### Scenario: 内部记录与迁移兼容（D1/D6/D8）

- **WHEN** 新路由 checkpoint 与旧事件交错，或执行新增 kind 的迁移
- **THEN** 内部事实不进入外部 ThreadEvent/SSE，游标间隙合法；以新迁移扩充原封闭 kind 与关联约束，保留只追加和旧事实，不改旧迁移、frozen_context，不建平行路由表或 Run JSON 事实源

### Requirement: 完整请求与可靠参数先于接管

路由 SHALL 只接管可由单个现成只读用例完整交付的自足本轮请求，不遗漏任一目标、否定、条件、约束或承接关系。可信上下文、严格工具参数与当前资格优先于分数；参数仅来自完整本轮原话的可追溯范围或明确合同默认，不以历史、样例或时钟补齐。见 design/19 §3–§4、§6、§10。

#### Scenario: 三个有限白名单及默认（D8/D10）

- **WHEN** 完整请求仅需当前活动提醒有限列表、本人已记录时区、或单个真实合法 YYYY-MM-DD 的简报卡片，且所有门均通过
- **THEN** 分别绑定 list_tasks/get_user_prefs/read_brief_cards；提醒仅原活动集合、默认20或明确1..50，时区仅本人记录/null且不写，简报不补当天/相对/历史日期且最多50张；不为凑完整目标新增筛选、查全或分页

#### Scenario: 多目标、相邻目标与上下文未知（D8/D10）

- **WHEN** 请求含读后修改、写/批准/恢复/控制、结果核实、分析、查全/筛选等不支持目标，或可能指代/补参且无法可靠排除历史依赖
- **THEN** 不局部执行前三类或只保留读目标，完整原话与原冻结上下文交原 LLM；用户目标范围仍覆盖全部原能力，不缩成三个标签

#### Scenario: 参数来源、冲突与高分（D1/D8）

- **WHEN** 缺少必需参数、日期/数量重复或冲突、日期非法/条数越界、明确的数量要求无法解析或带不支持约束，或尝试从历史助手、样例、服务时钟或自报 owner 补参
- **THEN** 不接管，高分不能覆盖失败门；可信身份由 TS 恢复，来源范围按本轮原话 Unicode 标量核验，明确默认单独可追溯，不能把 UTF-16 下标冒充原话范围

#### Scenario: 全文输入与 L1 完整覆盖（D8/D10）

- **WHEN** 完整命令后追加否定、引文、条件或另一目标，或编码输入超限/需裁剪才可容纳
- **THEN** 不以关键词包含或前缀命中执行，不截断/删尾句/丢否定/拼历史；编码副本只用版本化 NFC、CRLF→LF 与 trim，参数仍取原话，原始持久输入不改写

### Requirement: 全竞争语义判断与固定拒识

L2 SHALL 对完整竞争空间作一次有界判断，采用冻结的四族/top2平均、按意图独立的绝对与异类差距阈值以及固定排除 veto；实际接管时最高类必须是已启用白名单，shadow 只计算潜在候选而不授予执行资格。分数不能替代目标、参数、能力或授权证明，guard/parser 也不得被描述成完整语义证明。见 design/19 §4、§6、§12。

#### Scenario: 最高类不允许接管或同分（D8）

- **WHEN** 全空间最高类未启用/非白名单，或不同类最高分相同
- **THEN** fallback，不捞白名单第二名，不靠类ID排序接管；竞争空间保留其他提醒/资料/控制/核实/普通交流及能力外目标

#### Scenario: 独立阈值与排除证据（D8）

- **WHEN** 最高白名单类未达到其绝对阈值或异类差距阈值，或对应排除证据 R 大于等于支持 S
- **THEN** 固定拒识，不用通用0.8、其他模型阈值或额外隐式阈值替代；无相邻排除证据的意图不启用

#### Scenario: 剩余语义风险（D8/D10）

- **WHEN** guard 未发现复杂性而参数与分数通过，但审阅发现漏目标/否定/对象/约束或输出越过回执
- **THEN** 仍判为实质误接，不以标签正确、parser通过或高相似度免责；新表达族与整链评估必须能使错误接管变红，不把词法门宣称为完整理解

### Requirement: 已暴露错误的通用语义回归

路由资产与消费者 SHALL 保留已暴露错误的通用行为回归，既保护目标完整性，也防止无语义依据的关键词误挡；不能改单句 gold、删除失败或增加逐句白名单。错误来源与既有材料暴露边界见 design/19 §2、§6、§12。

#### Scenario: 读取对象与追加动作不可混淆（D8/D10）

- **WHEN** 请求查询本人记录的时区，或同一请求在读取后还要求修改时区
- **THEN** 前者不能误派提醒列表；后者必须完整 fallback，不能静默执行纯读而丢修改目标。分别保留 BGEINT8 的对象误派与已淘汰 Dmeta 的漏第二目标反例来源，不混报为同模型错误

#### Scenario: 过去添加不等于历史状态筛选（D8）

- **WHEN** 请求描述过去添加的提醒但未要求历史状态/范围，且其完整语义仍是当前活动有限列表
- **THEN** 不仅因过去添加措辞拒识，也不擅自加历史筛选；仍按完整上下文、能力、分数和参数门判定，不要求某个固定句子必接管

#### Scenario: 动词成分与被否定的列表要求（D8）

- **WHEN** “到”属于读取/翻阅动作而非日期范围，或否定仅修饰不需要更长列表而非否定读取
- **THEN** 不仅因单字“到”或否定词触发日期范围/禁止读取；仍保留真正日期筛选、否定读取及多目标的拒识边界，不删除原话中的词

#### Scenario: 场景时间与明确日期（D8）

- **WHEN** 单日简报请求同时出现时间场景描述与唯一明确合法绝对日期，且场景没有构成额外日期目标
- **THEN** 不把场景词自动当冲突日期而误挡；反之真实相对日期要求、多个目标日期或缺日期仍 fallback，不借场景或当天时钟补槽

### Requirement: 版本绑定的单次完整编码与有界资源

编码服务 SHALL 只对固定预部署资产提供完整文本到向量的能力，不读取业务库或决定工具；路由仅一次编码、无请求内重试/切模型/双编码，并以冻结 binding 验证 tokenizer、模型与输出。目标服务、精确算法与 Proposed 预算见 design/19 §5、§11，不以离线计时代替服务证据。

#### Scenario: 输入计数与禁止截断（D8）

- **WHEN** 准备编码完整本轮文本，或同次固定 tokenizer 含 special tokens 的精确计数超过256
- **THEN** 使用与绑定一致的计数和禁截断编码；超限在 direct 前 fallback，不按字符估 token、不摘要重试；服务不能按请求下载或切换权重

#### Scenario: 绑定与向量异常（D8）

- **WHEN** 服务返回不同 binding、维度不符、非有限值或零向量，或固定资产不可用
- **THEN** 不用于分派，direct 前按可选编码失败回原 LLM；TS 校验后规范化合法向量，不混合不同模型/编码约定，也不在线切 E5

#### Scenario: 锁外预算与默认关闭（D1/D8/D9）

- **WHEN** 编码达到冻结 deadline、实例 inflight 满额，或 off 环境没有编码依赖
- **THEN** 编码不持 Run 锁等待IO，超时/满载 direct 前 fallback且不重试/排持久队列；off 不要求编码可用，既有 core readyz 类型化合同不降级；预算变更必须新版本且不能宣称为已测 SLA

### Requirement: direct 接纳前后失败与取消裁决

系统 SHALL 明确区分可选路由拒识与事实/协议/权限错误，以及 direct 接纳前后不可逆的路线边界；direct 一旦接纳，不得切 LLM 或开新 slot 重做。取消先提交即撤销新动作与展示资格，编码、传输丢失或进程崩溃不新增恢复点。见 design/19 §8–§10。

#### Scenario: 接纳前可拒识与不可绕行错误（D8）

- **WHEN** direct 尚未接纳，出现低分/不适用/可选编码失败，或出现事实损坏/畸形协议/权限失败/DB无法接纳决议
- **THEN** 前类完整回原 LLM 且不注入猜测标签锚定；后类按原错误语义停止，不伪装普通拒识使 LLM 绕过可信边界

#### Scenario: 接纳后任何步骤失败（D8/D10）

- **WHEN** direct 决议已接受，随后 reserve/invoke/snapshot/render 失败，或工具返回 denied/failed/unknown
- **THEN** 保留真实账并沿既有错误语义终结，不论工具是否已实际执行都不再转 LLM、不换 slot、不重新编码/选择路线，不把失败结果说成完成

#### Scenario: 编码或展示与取消竞争（D8/D9）

- **WHEN** 编码在途或文本准备后原取消先提交，随后迟到候选/工具请求/展示/finish 到达
- **THEN** 不新增动作、不接受迟到正文或成功终态，资格前后复核；编码可 abort且会话关闭释放请求/计时器，不以等待 IO 锁阻塞取消，也不伪撤销先前真实效果

#### Scenario: 回答丢失与进程终止（D6/D8/D10）

- **WHEN** 决议/结果/展示已提交后 socket 丢失，或 native 在任意路由中间步骤终止
- **THEN** 保留已提交事实，GET/同键重放只补原存储内容，不补执行/渲染/分类；崩溃沿原失败终结，不由路由账自动恢复或伪报成功

### Requirement: 不可变发布版本与逐意图证据门

系统 SHALL 以不可变 bundle 绑定模型/编码/目录/打分/参数/处理器/模板/预算及评估依据，v5 的 TS/native/contracts/正式消费者同批切换而 snapshot2 不加字段；未通过逐意图完整证据门的 L2 不得实际接管，影子计算不授予执行资格。精确绑定与阶段标准见 design/19 §5–§8、§11–§14。

#### Scenario: 半新半旧与资产变更（D6/D8）

- **WHEN** 部署中协议不兼容、找不到冻结版本，或模型/目录/guard/parser/阈值/模板/预算任一改变
- **THEN** 不混用资产或偷偷兼容旧wire；按接纳前后失败边界处理，新资产建立新 bundle 并重新分组校准/冻结/未见留出验收，不能覆写原版本或沿用旧阈值冒充新证据

#### Scenario: 已暴露与目标宿主证据不足（D8/D10）

- **WHEN** 仅有合成非盲样本、已暴露旧 test 或 Windows 离线编码结果，而无目标 Linux 服务/正式消费者/真实 Web/自然 shadow 证据
- **THEN** 不宣称上线通过；旧材料留作回归不冒充未见留出，未知成本/usage 如实 unknown，不把离线 p95 当 HTTP或端到端承诺；未过门意图保持 shadow/off，不开启实际接管

#### Scenario: 自然 shadow 与受控逐意图启用（D8/D10）

- **WHEN** 拟从 shadow 启用某意图
- **THEN** 须全部拟接管候选逐条审阅无已知实质误接，D1/D6/D8/D9/D10 消费者边界和目标宿主/真实 Web通过，真实 L1miss 增量非零且保守净收益为正，并取得对应实验/小批授权；否则不允许该意图 enforce，可继续 shadow 或保留 L1＋L3并关闭 L2，不由算法自动开量

#### Scenario: 风险声明与停止（D8/D10）

- **WHEN** 受控小批证据不足以支持统计可靠性声明，或出现漏目标/越权/绕批准等实质误接
- **THEN** 不把少量零错或299示例当独立自然保证/开发前置/发布许可，不自动放量；严重误接立即停受影响意图并保留原事实与版本，后续重新评估而非降阈值或删错例
