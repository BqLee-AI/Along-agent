## MODIFIED Requirements

### Requirement: 常驻输入与连续会话

系统 SHALL 在首次发送、运行中和运行结束后保留可达的对话输入面；完成后可在同一会话明确发送下一轮。连续消息来自已存可见消息与原运行事件，不凭文本相似度猜测关联或重复拼接最终档案与同一流式回复。新 Harness 运行在接纳时冻结同用户、同会话最多63条前序可见 user/assistant 消息及本轮完整输入，按冻结顺序执行和批准恢复；不是永久记忆，不重放旧工具调用。只读首步路由不改变冻结合同：仅实际进入原模型的运行要求将冻结上下文装配为模型输入，合格 direct 则不伪造模型请求。见 [design/19](../../../../../docs/design/19-r2b-readonly-intent-routing.md) §3、§7–§10。

#### Scenario: 不选工具的多轮交流（D8/D10）

- **WHEN** 用户直接发送普通问题，收到回复后在原页面追问
- **THEN** 输入不消失，页面保留前轮消息与本轮回复；第二轮沿原 conversation_id 新建 Run 并冻结接纳时前轮可见上下文及完整当前输入，不混入其他用户、其他会话或 system 消息；若进入原模型则模型收到该冻结输入一次，若合法 direct 则零模型交付而不伪造已发模型

#### Scenario: 刷新后明确追问（D8/D9）

- **WHEN** 用户刷新、重登或从历史发现原会话，再输入下一条消息
- **THEN** 加载和历史恢复只有 GET；输入面仍可达，只有用户明确发送才创建新 Run，新运行使用同会话已存可见上下文，不重发旧消息或自动恢复旧执行

#### Scenario: 在途和未知状态保留边界（D8/D9）

- **WHEN** 原运行仍在执行、等待批准、发送结果待核实或工具效果未知
- **THEN** 输入面继续展示真实不可发送原因，不能通过发送新消息绕过原运行；继续和取消仍走原 Run 的明确操作，不把输入新文本当成批准或恢复

#### Scenario: 有界窗口与批准恢复（D5/D8/D9）

- **WHEN** 会话历史超过64条消息，或原批准等待后又出现后来消息
- **THEN** 新运行只保留接纳时最新63条前序可见消息及完整当前输入；批准恢复沿原冻结引用，不混入后来消息，不截断当前输入，超1MiB聚合帧明确失败而非成功或切换模型；没有跨轮冻结引用的历史 Run 不因恢复补造上下文

## ADDED Requirements

### Requirement: 有限只读交付保持事实与输出天花板

会话 SHALL 将 direct 的确定性展示限定为原工具接受时的有限事实，不将有限列表/卡片、正常空结果或状态记录扩大成全量、分析、已完成写入或必达承诺。结果边界见 design/19 §4、§9；既有时间、冻结展示与安全 Markdown 合同不变。

#### Scenario: 活动提醒有限视图（D8/D10）

- **WHEN** direct 返回最多指定条数的当前活动提醒或 has_more
- **THEN** 展示原状态、冻结本地时间/时区及标题预览和有限范围，保留 has_more，不补算时间、不称全文/全部/一条不漏；scheduled 不等于必达或已收到，cancel_pending 不等于已取消

#### Scenario: 本人记录时区与 null（D8/D10）

- **WHEN** direct 读取本人偏好中的 timezone_id 或 null
- **THEN** 仅说明已记录值或未设置，不改偏好、不推断宿主/浏览器时区，不把读取宣称为已切换时区或完成其他目标

#### Scenario: 单日简报有限卡片（D8/D10）

- **WHEN** direct 返回明确日期的已有简报卡片
- **THEN** 仅展示原日期、卡片字段及来源，说明接口最多50张且无查全证明，不称重新生成、完整资料摘要或完成分析，不补今天/历史/相对日期

#### Scenario: 正常空、失败与容量边界（D8/D10）

- **WHEN** 合法有限读取为空，或工具/展示容量/来源读取失败
- **THEN** 真空仅说明本次有限查询未返回记录，不推断从未存在；失败保持原类型化事实，不变成空列表/成功完成，不偷偷截断/摘要正文来宣称完整交付

### Requirement: 路由回答的真实恢复与内部事实隔离

会话 SHALL 从已存外部事件恢复 direct 的确定性可见正文，保持与 provider 可见增量不同的真实来源，不因历史展示启动分类、编码、工具或模型。内部路由策略/决议/render 只作可信运行事实，不成为公开事件或客户端动作授权。见 design/19 §8–§10，既有本人历史与当前授权合同保持。

#### Scenario: 刷新与同键重放（D6/D8）

- **WHEN** direct 正文已存后用户刷新、重登、GET补读或同键重放，且源任务/偏好/简报后来改变
- **THEN** 只恢复原事件中的已接受正文，不从当前源重新生成，不重复拼入最终消息，不补编码/分类/工具/attempt；旧事件与旧 Run 仍按原历史合同可读

#### Scenario: 内部记录交错与来源诚实（D1/D8/D10）

- **WHEN** routing policy/decision/render 与外部事件交错，或页面展示零模型 direct 的回复
- **THEN** 外部消费者只读取原七词事件，内部记录不被解析或泄露，游标间隙合法；正文不冒充 provider token 流/模型润色，技术记录不伪造调用和 usage

#### Scenario: 失败、取消与显式新动作（D8/D9/D10）

- **WHEN** direct 在真实结果前后失败、取消已先提交，或用户从历史显式发起新消息/有效批准继续
- **THEN** 历史展示保留真实已存部分/失败而不补执行或伪报完成；新消息才新建 Run，批准继续仍沿原 Run 且零路由，不借历史恢复、输入新文本或客户端状态绕过当前执行资格
