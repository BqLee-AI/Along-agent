## ADDED Requirements

### Requirement: 用户显式暂存私有会话资料

系统 SHALL 在对话草稿中支持本人上传 TXT/Markdown 纪要与任务 CSV，按真实请求分别呈现上传中、暂存成功和失败。选择或上传不等于发送，不得创建空对话、写入宿主工作区或发起模型、交付及提醒动作。发送前须说明本轮所选资料会提供给本人配置的模型处理，不承诺离线。见 [design/24 §1–§2](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 新草稿显式选取但尚未发送（D8/D10）

- **WHEN** 用户从新对话选择并上传一份纪要和一份任务表，尚未明确发送
- **THEN** 入口可见模型使用说明，成功项仅显示暂存标识、展示名、格式、大小和有效期；没有新会话、消息、Run、模型请求、工作区写入、产物或提醒

#### Scenario: 部分上传和切换草稿（D8/D10）

- **WHEN** 一项上传成功而另一项尚在上传、被中止或失败，或用户切换对话、草稿或登录身份后旧请求才返回
- **THEN** 已成功的暂存与未成功项分开显示，未成功项不得进入发送范围；迟到响应不把旧资料选入当前草稿，刷新、重登和重连不自动上传或发送

### Requirement: 上传按真实字节限额与幂等结果处理

系统 SHALL 先验证上传身份和 CSRF 再读取原始内容，按实际字节和本人活跃配额限制上传，验证受支持的编码、文件名、格式和内容，且文件名只作展示。重复上传必须按原请求语义及内容识别，不得多写字节、延长已失效暂存或绕过配额。见 [design/24 §2、§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 未认证或 CSRF 无效时拒绝读取（D8）

- **WHEN** 未登录请求或 CSRF 无效的请求经生产 Web/BFF 提交超限或非法上传体
- **THEN** 返回对应认证或 CSRF 拒绝，而不是先读取字节再返回超限或内容错误；没有可用暂存或配额占用

#### Scenario: 实际字节、中止和并发配额（D3/D8）

- **WHEN** 上传无长度或声明长度与实收不符且实收越界，连接在上传中止，或多个各自合法的上传并发争用同一本人剩余配额
- **THEN** 超限与配额不足可区分；超限、中止的未完成上传不留下可用暂存，成功上传合计不突破本人上限，其他 owner 的独立配额不受影响

#### Scenario: 编码、文件名及内容校验（D8/D10）

- **WHEN** 上传使用未支持的内容编码或格式、非法文件名、空内容或非法 UTF-8，包括通过生产 BFF 提交
- **THEN** 按原因拒绝，不把代理丢弃编码信息当作合法上传，不把展示名用作宿主路径，也不把失败显示为成功或空资料

#### Scenario: 同键重放与变更冲突（D3/D6/D8）

- **WHEN** 同一合格草稿上传的响应丢失后，以原键、原参数和原字节重试；或在同一作用域用原键改动内容或参数
- **THEN** 相同请求返回原附件而不新增占用；变化明确冲突、不替换原件；重放不能恢复已撤销或到期的暂存资格

### Requirement: 暂存、历史读取和运行授权按身份隔离

系统 SHALL 将未绑定附件限定在原 owner、原登录会话和原草稿，已有会话的附件须符合该会话归属；绑定后区分本人撤销、本人历史与下载授权，以及基于接纳时身份和冻结执行资格的动作授权。不合资格的资源访问不得透露存在性、元数据或内容。见 [design/24 §2–§3](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 已知引用不能跨边界探测（D1/D8）

- **WHEN** 另一 owner 或同一本人在不同登录会话、不同草稿或错误对话中持有未绑定附件的有效引用，尝试提交或撤销，或在他人会话中尝试暂存
- **THEN** 对无资格资源的结果与资源不存在不可区分，不返回私人元数据、内容、消费或撤销状态，不改变该附件、会话或 Run

#### Scenario: 同账户重登只恢复本人读取资格（D6/D8）

- **WHEN** 用户以同一账户重新登录，读取本人已绑定资料的历史，或试图沿用原登录会话的未绑定草稿和旧 Run 执行
- **THEN** 本人仍可读历史、撤销本人已绑定原件及下载尚可用的产物；不接管旧的未绑定暂存，也不因持有历史链接或已登录而恢复旧 Run 执行资格

### Requirement: 显式办公请求原子接纳并冻结资料范围

系统 SHALL 只在用户明确发送、至少选择一个资料角色且每个角色只选一个合格附件，并提供显式幂等意图时接纳办公 Run。仅支持具备 server-owned 生命周期的原生 Harness `delegation/1` 委托；原话、Run、初始 attempt 与资料单次消费及绑定一并生效。运行仅获得接纳时选定的角色、资料版本与合格工具，不隐式继承工作区、旧附件、连接器或记忆授权。见 [design/24 §2–§4](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 只有显式所选角色进入本轮（D6/D8）

- **WHEN** 本人草稿中有多个已上传文件，会话另有历史附件或已登记工作区，用户明确仅选一份纪要或同时选纪要和任务表发送
- **THEN** 只生成并绑定一条原话和一个 Run，其资料角色与版本、执行资格均取自本次接纳；未选内容不进入模型，未选角色无相应工具，模型不能补填任意资料，扩范围须另行明确提交

#### Scenario: 资格不满足时不部分接纳（D6/D8/D10）

- **WHEN** 发送声明办公模式但未选择资料、重复角色、缺显式幂等意图、含不合格资料，或当前 driver、原生消费者或私有恢复条件不满足
- **THEN** 按实际原因及身份边界拒绝，不静默删减资料、不回退旧执行路径；不留下本次消息、Run、attempt 或空对话，也不消耗其中任何附件

#### Scenario: 回执优先且发送键不能改义（D3/D6/D8）

- **WHEN** 已接纳的发送响应丢失，合格调用者用同键同意图重试，即使资料已被原请求消费或已失效；或同键改动草稿、附件或角色分配
- **THEN** 在原读取授权下先核对原回执，相同意图只定位原 Run 与原事实，不再验作新消费、不新开 attempt 或执行；异意图明确冲突，不替换原绑定，也不因重放恢复已失效内容的访问

#### Scenario: 不同发送键争用同一附件（D3/D6/D8）

- **WHEN** 两个不同发送键的接纳请求并发争用同一尚可用的暂存附件，其中一个请求还选了另一份附件
- **THEN** 同一附件最多进入一个 Run；失败方无部分消息、Run 或绑定，也不消耗它另选的合格附件

### Requirement: 撤销与到期改变当前可用性而不改写既成事实

系统 SHALL 对合格的显式撤销按 CSRF 保护、单向幂等处理。撤销阻止后续取得原件及其派生产物；普通原件到期不连带产物到期。取消或撤销先提交时不得再接受晚到结果或创造交付效果；先接受的效果仍是事实。逻辑失效先于字节清理，保留状态及幂等所需事实。见 [design/24 §2–§3、§5](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 撤销草稿、重复请求与接纳竞争（D3/D8/D9）

- **WHEN** 原登录会话撤销未绑定草稿附件、重试同一撤销，或撤销先于并发接纳提交
- **THEN** 撤销只使其失效一次；后续发送不能消费该附件，重试上传不能使它可用，不因撤销创建假历史或补执行

#### Scenario: 撤销或取消与在途交付竞争（D8/D9/D10）

- **WHEN** 同一 Run 的取消或原件撤销与产物接受并发
- **THEN** 取消或撤销先提交就不接受晚到结果、不创建新产物；交付先提交则如实保留原交付事实，取消不伪报回滚，原件撤销后其派生产物不可再下载，也不声称收回已经下载或已交付的聊天内容

#### Scenario: 原件过期与交付物独立过期（D2/D8/D10）

- **WHEN** 已交付报告的原件自然到期，而产物仍在自己的有效期内；随后产物到期，清理尚未运行或已删除字节
- **THEN** 原件到期后不再可取；报告在自身可用期内仍可下载，自身到期后即不可下载，与物理清理时点无关，历史保留真实交付与当前不可用状态，重放不重新生成

#### Scenario: 持久化但尚未交付的事件遇撤销（D8/D9）

- **WHEN** 含办公资料派生内容的聊天增量已持久化但尚未交付，原件撤销先提交，随后流式发送或重连补读尝试交付该事件
- **THEN** 发送和补读前按来源及当前资格裁决，不发送受影响或不能证明无关的未交付内容；不因事件已经持久化而声称已送达，已发送字节不追溯收回，也不重跑以填补历史

### Requirement: 本人历史只读投影资料事实和可用交付

系统 SHALL 从持久接纳和已接受交付事实分页投影原话、来源与产物元数据，显示文件名、类型和实际可用状态。历史读取不携带附件或产物字节、不披露私有恢复数据、授权材料或私有摘要，也不触发执行。上传和历史遥测不得记录临时上传文件名、私有内容摘要、正文或授权材料。Markdown 如提供预览，须为纯文本或符合既有安全渲染合同，不载入原始 HTML、外链嵌入或危险链接。见 [design/24 §2–§3、§4–§5](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 重登和翻页恢复原历史（D6/D8）

- **WHEN** 用户断开订阅、清除临时状态后重登并分页查找一个已交付 Run
- **THEN** 仍可定位原消息、来源和接受过的文件；列表及 Run 历史只投影元数据，订阅断开不取消 server-owned 运行或引起重跑，打开、刷新、分页和重连只读，不新建 attempt、模型请求、工具调用或提醒

#### Scenario: 预览含主动内容（D8/D10）

- **WHEN** 可预览的 Markdown 含原始 HTML、外链嵌入或危险链接
- **THEN** 预览仅展示为文本或按安全渲染规则过滤，不执行内容或自动发出外部请求；预览不是交付凭证，也不改变可下载文件内容

#### Scenario: 局部读取失败不是未交付（D8/D10）

- **WHEN** 原消息读取成功，但来源、产物状态或后续历史页读取失败
- **THEN** 保留已读事实并明确缺少的部分及只读重试，不将失败替换为空历史、无产物、可下载或完整成功，不通过重跑修复历史

#### Scenario: 历史与遥测不外泄私有资料（D1/D8）

- **WHEN** 用户上传可辨识的私有资料，发生拒绝、读取历史或下载
- **THEN** 对话历史和错误不披露原始附件正文、私有摘要或内部授权；遥测不记录原始上传文件名、正文、摘要或授权材料；合格本人的明确下载仍可取得已接受的字节

### Requirement: 下载只交付当前本人有权取得的原始字节

系统 SHALL 只为当前本人返回完整关联会话与 Run 的已接受、未过期且未撤销产物；下载入口由可信服务端事实提供，不接受模型拼接的 URL 或附件标识冒充交付凭证。生产 API 与 BFF 须保持原始字节及安全下载语义，不提供公开、分段或 HTML 内联交付。见 [design/24 §2、§5–§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 字节保真、安全响应及中止（D8）

- **WHEN** 本人经生产 Web/BFF 下载已接受的 Markdown 或 CSV，或在传输中主动中止
- **THEN** 完整传输与已接受字节一致，类型、字节长度和附件下载名正确，禁止嗅探且私有、不可缓存和转换；中止与背压贯穿代理，不改写历史或重新执行，不使下载通用头放宽既有响应路径

#### Scenario: 拼接、越权或当前失效不能取回字节（D1/D8/D10）

- **WHEN** 请求拼入不属于该会话或 Run 的产物、使用他人引用、用户未登录，或产物尚未接受、已过期或已撤销
- **THEN** 不返回任何文件字节；无资格方不能探测是否存在，本人仅从授权历史得知真实不可用状态，不提供公共绕行链接或内联内容

### Requirement: 文件、提醒与 Run 状态分别取自真实结果

系统 SHALL 分别呈现运行生命周期、已接受且核验存在的文件、提醒当前真实状态及仍待澄清的缺口。资料正文不是提醒或外发指令；只请求摘要或统计时不创建产物或提醒。对于明确要求文件加一次站内提醒的目标，先交付文件，再处理被明确委托的提醒；澄清仅补可信缺口，不重做已接受交付。见 [design/24 §1、§3–§5](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 真文件与真提醒分别可核对（A1/A4/D8/D10）

- **WHEN** 用户明确请求报告、清单和一次站内提醒，真实运行已接受两个文件和提醒任务
- **THEN** 文件入口对应可下载的已接受产物，提醒入口对应原真实任务和当前状态，创建不等于已排期、已触发或已送达；Run 终态与模型措辞都不替代任何一项回执

#### Scenario: 部分成功及仅补提醒缺口（A4/D6/D8/D10）

- **WHEN** 文件已接受但提醒因缺时区、歧义、过窗或取消未建，或用户之后仅答复同一可信且仍待解决的提醒缺口
- **THEN** 分别显示文件已生成、提醒未创建及真实原因；需要澄清时只问缺口、不猜时区，可信接续只处理尚可继续的未建提醒，保留原回执而不重生文件或扩原资料范围

#### Scenario: 摘要或统计不接受资料中的行动指令（D8/D9/D10）

- **WHEN** 用户仅请求摘要或统计，所选文件却含外发、生成文件或设置提醒的文字，或任务表包含截止日期
- **THEN** 仅在授权范围内处理资料内容，不建交付物、不建提醒、不发送到其他目的地；资料中的文字和日期不产生任何动作授权

#### Scenario: 提交未核验时不报成功（D8/D10）

- **WHEN** 模型宣称完成、提供自行拼接的链接，或文件提交的应答丢失且尚无法核实原回执
- **THEN** 不将声明、附件标识或流结束当成交付；只读核对原接受事实，无法确认时保留待核实状态，不补发新请求或盲目重做

### Requirement: 新接纳开关和升级不改变既有对话合同

系统 SHALL 默认关闭新办公接纳，保留普通消息的请求识别、原幂等及 JSON/SSE 行为、既有工作区和批准路径、旧 Run 的冻结资格。关闭新办公接纳不得关闭已接纳历史、下载、撤销或清理，也不得用旧构建解释未排空的新运行。见 [design/24 §2–§3、§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 普通请求和旧 Run 回归（D6/D8）

- **WHEN** 新版本处理未声明办公资料的旧式请求或原幂等键的重放，并读取或显式操作原有会话、Run、批准与工作区深链
- **THEN** 保持原请求匹配和 JSON/SSE 语义及原结果位置、批准和执行边界，不为普通请求追加新资格，不因部署升级、历史读取或旧操作授予办公资料工具

#### Scenario: 关闭只阻止新办公接纳（D6/D8/D10）

- **WHEN** 未开启能力的部署收到新办公发送，或已有交付的部署关闭新接纳后再发送新请求、重放原请求及打开历史
- **THEN** 新办公发送明确不可用且无接纳副作用，原合格重放仍定位原事实；此前本人历史、仍可用下载、撤销及清理继续生效，普通请求不受影响

#### Scenario: 前向升级及回退保留本人历史（D5/D6/D8）

- **WHEN** 旧库经前向迁移升级，或私有资料从备份恢复，或计划切回不识别新办公 Run 的版本
- **THEN** 旧事实与冻结授权保持原样；含资料及其状态的备份恢复后，仍可用的私有产物对本人提供相同字节，恢复出的撤销和到期记录不重新授权；不兼容版本须先停止新接纳并排空相关 Run，不以删表或补造权限回退
