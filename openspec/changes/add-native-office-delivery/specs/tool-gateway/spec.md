## ADDED Requirements

### Requirement: 办公工具只接受冻结资料及本运行的合格来源

网关 SHALL 仅按冻结角色提供对应读取与分析能力，并在执行和回取前校验本人、接纳会话绑定、当前 attempt 与占有、Run 状态、资料状态及版本。办公参数只选择受支持的动作与冻结来源；不接受任意附件或宿主路径、SQL、URL、代码、凭证，也不以资料正文赋予执行权。已接受的私有来源在仍有资格时才可按有界原事实回取，不重执行、不换版本；工具账本只留引用和安全回执，不留资料正文。见 [design/24 §3–§4](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 纪要按稳定行范围读取（D8/D10）

- **WHEN** 合格运行读取冻结纪要的部分行并按游标继续，或重交同一已接受调用
- **THEN** 返回来源展示名、冻结版本、稳定行范围及有界正文，未完时提供后续游标；有资格的重放只回原接受页，不重读、不把部分页当作已读完或新版

#### Scenario: 模型提交越界资料与参数（D1/D6/D8）

- **WHEN** 模型提交未选角色、任意资料 ID、其他本人／会话／Run 的来源、不匹配的版本或企图传入宿主路径、SQL、URL、代码、凭证，或从失去资格的 attempt 回取私有观察
- **THEN** 网关拒绝执行或回取，不透露无资格来源的存在性、正文或元数据，不更改冻结资料、不留下任何请求指向的效果

### Requirement: 任务 CSV 的分析口径确定且可复算

网关 SHALL 按 [design/24 §4、§6](../../../../../docs/design/24-native-office-delivery.md) 的固定输入模板、严格 CSV 校验、时间权威与分类口径，分析冻结任务表并提供有界、带版本与数据记录号的结果。只采用可由用户原话核验的明确绝对截至日，否则使用 Run 冻结的可信时区与请求锚；不从资料、模型自报值或服务器时区推断。分析明细只按原接受分析及其固定条件分页，相同输入版本和截至日的计数及顺序一致。

#### Scenario: 严格解析、输入模板与定位（D8/D10）

- **WHEN** CSV 使用合法 UTF-8、可选 BOM、逗号分隔、重排的固定列、带转义的引号、CRLF 或引号内换行；或出现非法格式、空／重复表头、缺固定列、空／重复任务 ID、记录结构不齐、非法 UTF-8 或超限
- **THEN** 合法记录按模板读取，Unicode 和 ID 前导零保留，来源号按数据记录而非物理行；非法输入报告类型和可定位问题，不静默跳行、猜测列映射或返回部分统计作为完整成功；缺截止列只指出实际缺口并提供输入模板，不替用户猜列

#### Scenario: 截至日仅来自可信输入（D8/D10）

- **WHEN** 用户原话提供可核验的绝对截至日，或未指定日期而处理跨过 Run 冻结时区的本地午夜，或缺少可信时区
- **THEN** 绝对日优先；否则使用请求锚在冻结时区对应的日历日，不因处理或重放时已过午夜改变；缺时区只询问这个缺口，不用系统默认值、文件日期或模型猜测继续计算

#### Scenario: 黄金任务表的可复算统计（D8/D10）

- **WHEN** 固定截至日分析五条黄金记录：甲昨日待办、甲今日进行中、乙昨日已完成、未分配且缺日期与状态非法、乙日期非法的待办
- **THEN** 总数五、分组二／二／一、逾期一、异常行两条；缺负责人、缺日期、非法状态、非法日期各计一，重叠标签不重复计异常行；日期须为合法公历且严格早于截至日，只有待办或进行中可计逾期，不把未知状态猜为未完成；负责人去首尾空白后精确分组，空负责人不与任何字面名称合并

#### Scenario: 分页不得更换分析条件（D8/D10）

- **WHEN** 模型请求校验预览或同一已接受分析的明细续页，或换截至日、版本或条件却沿用原分析翻页
- **THEN** 预览按实报告格式与校验问题，不冒充完整分析；成功分析包含覆盖、分类计数、分组及带稳定记录号的有限样例；续页以原分析事实稳定顺序返回，条件不符则拒绝，模型回包与逐页容量保持有界

### Requirement: 原生文件交付由可核验证据生成且整套原子提交

网关 SHALL 只在用户要求交付时，使用同一 owner、会话、Run 与冻结版本的已接受来源，由服务端生成所请求格式。Markdown 的统计与负责人汇总 CSV 必须来自同一已接受分析，不能以模型重报的数字或原始 CSV 替代；说明有界，导出逐单元格保护不可信文本。一次交付的全部文件字节、清单和接受回执同事务提交；本办公模式的单套交付例外于同参数新调用通常是新动作的规则，不覆盖旧产物。见 [design/24 §4–§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 两种交付共享证据且安全呈现（D8/D10）

- **WHEN** 用户请求 Markdown 与负责人汇总 CSV，模型给出合格的纪要和分析来源，但说明或参数试图重报统计；负责人文本含控制字符、前置空白后的公式前缀或全角公式变体
- **THEN** 只有已接受分析派生的统计进入两种交付，Markdown 给出可核验来源和逐项异常，CSV 采用正确转义和安全文本展示，不改变源数据或核验记录号；受支持表格打开路径不解释危险单元格为公式，不承诺重存后仍安全，汇总 CSV 不冒充输入模板

#### Scenario: 不合格引用或回执不能证明交付（D1/D8/D10）

- **WHEN** 提交借用其他 owner、会话、Run 或版本的来源、未接受分析、附件 ID、模型生成链接，或试图用任意 CSV 内容作为交付事实
- **THEN** 网关拒绝不合格输入，不生成或覆盖产物、不披露无资格事实；只有真实已接受调用所指且核验存在的产物可证明交付，可信服务端而非模型提供下载位置

#### Scenario: 多格式失败不留半包，提交丢应答只查原事实（D3/D4/D8）

- **WHEN** 请求双格式交付，任一字节写入、清单或结果提交失败，或真实事务提交响应丢失后重交原调用
- **THEN** 失败则无部分可下载文件、清单或成功回执；响应丢失时以持久事实判定，已接受则回原产物和回执，未证实成功不得声称交付，不换调用绕开原事实

#### Scenario: 换调用 ID 重提交付不生成第二套（D3/D4/D8）

- **WHEN** 同 Run 用不同调用 ID 并发或顺序提交相同规范化交付，或用不同参数试图修改已占用的交付
- **THEN** 同意图只引用原产物，异意图明确冲突；实际只有一套已接受产物，不覆盖、不产生重复文件，不以参数相同合并另行接纳的新 Run

### Requirement: 接受办公效果与取消、资料撤销有唯一裁决

网关 SHALL 与持久 Run 取消及原件撤销串行裁决办公读取、分析和交付的接受，不凭执行进程此前持有资格接受迟到结果；已经接受的效果保留事实，当前可用性另核验。显式撤销阻断原件及按实际来源派生的交付物；无法证明来源的派生按受影响处理，原件自然到期不连带已交付产物失效。见 [design/24 §2–§3、§5](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 取消或撤销先提交（D8/D9/D10）

- **WHEN** 真正的 Run 取消或资料撤销先于在途资料结果、文件交付提交或新办公动作完成持久裁决
- **THEN** 不接受迟到结果、不创建交付物、不以重放或更换调用推进运行；不披露已撤权正文或未接受产物，不编造成功回执

#### Scenario: 效果先提交而读取资格随后变化（D4/D8/D9）

- **WHEN** 文件先被接受，随后停止 Run、显式撤销某件原件或原件自然到期，用户再查看交付或请求取回字节
- **THEN** 原接受回执保留，停止不回滚文件；撤销仅阻断受影响或来源不可证明的产物及原件，不影响有证据与该原件无关的产物；原件自然到期不影响产物自身尚有效的下载，不声称收回已经发出的字节或聊天内容

### Requirement: 单次站内提醒按明确委托和本运行槽位创建

网关 SHALL 在办公组合目标的文件交付接受后，复用既有提醒用例与可信时间规则，为用户原话明确要求且时间合格的一次站内提醒创建真实任务。资料中的日期、指令或工具可见性都不是授权。该模式单一提醒动作槽位与任务创建和接受回执同事务；同入站键、同 invocation 或同 Run 换调用 ID 都不产生重复提醒，不按文案合并另发的明确新请求，也不为文件与提醒引入跨步骤原子性。见 [design/24 §3、§5–§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 只创建原话授权且时间合格的提醒（A4/D8/D9）

- **WHEN** 用户要求文件和一次站内提醒，模型在文件未接受时、缺少可信时间或时区、提醒窗口已过，或仅凭资料中时间和指令时提议创建
- **THEN** 不提前创建、不猜可信时间、不批量按表格日期创建；只对实际缺口请求澄清，区分过窗、无授权和交付未完成；文件已接受且提醒原话授权、时间合格后才可创建

#### Scenario: 重放及换调用 ID 只产生一次任务和回执（A4/D3/D4/D8）

- **WHEN** 合格提醒创建前后遇到提交响应丢失、原入站键重放、同调用重交、不同调用并发竞争同一办公 Run 槽位，或用户明确另发一个独立的新请求
- **THEN** 依据原事务及回执核对，同一 Run 最多有一个真实任务及对应创建事件和站内调度事实，冲突不能再建或改写；明确另发的新请求自己裁决，不因文案相同被全局去重

#### Scenario: 提醒失败、取消与既成文件独立（A4/D4/D8/D9/D10）

- **WHEN** 文件已提交，提醒事务明确失败或 Run 取消先提交；或提醒任务先被接受，随后 Run 才取消
- **THEN** 前者既不留下部分提醒效果也不回滚文件，保留提醒未创建及真实原因；后者保留已创建任务，不把 Run 取消当成任务撤销。只显示真实任务状态，未观察到触发或送达不宣称发生
