## ADDED Requirements

### Requirement: 仓颉办公运行只获得接纳时冻结的资料资格

办公 Run SHALL 仅在正式原生 Harness 支持 server-owned 生命周期及 `delegation/1`，且私有恢复前提满足时接纳。可信运行端从持久接纳事实装载显式选定的资料、角色、版本和对应工具清单；每次动作重新校验本人、接纳登录会话绑定、当前 attempt、执行占有、Run 状态及资料资格。工具可见性不是动作授权；旧 Run 和新 attempt 均不因部署而扩权。见 [design/24 §2–§3、§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 选定角色及版本限定正式运行（D6/D8/D9）

- **WHEN** 用户仅选择本草稿的一份纪要，另有未选 CSV、旧附件、本人工作区、连接器或记忆能力，正式仓颉启动并向所选模型发出请求
- **THEN** 只有本次冻结的资料版本和合格工具参与运行；不提供任务表分析能力，不将未选内容、工作区、历史附件、连接器或记忆能力加入请求，也不允许模型自行指定资料 ID 扩大范围

#### Scenario: 接纳前提不足不切换执行器（D6/D8）

- **WHEN** 新办公请求不具备对应的委托与生命周期，driver、正式 native 消费者或私有恢复所需配置不可用
- **THEN** 明确拒绝接纳，不消费资料、不新建运行、不发模型请求，不回退到普通业务、替身或明文路径；普通请求保留原行为

#### Scenario: 隔离旧资格与只读重连（D6/D8/D9）

- **WHEN** 新能力上线后读取旧 Run，办公 Run 断开并重连订阅，或者失去当前占有、接纳绑定不符的进程再次提交动作
- **THEN** 旧 Run 保留原权限；订阅断连只影响读取，在原预算和时限内由服务端持有现有执行，补读不新建 attempt 或重跑；失去资格的提交被拒绝、不披露资料或推进运行

### Requirement: 私有办公上下文仅在合格恢复中重建

系统 SHALL 将办公资料导出的私有观察及所有可能携带正文的 checkpoint、暂停与 compact 恢复状态，使用 Along 自有密钥按原本人、会话、Run 和 attempt 绑定加密；普通账本、审计、遥测及通用快照不留明文副本，通用存储只持加密封套或非正文引用，跨 Run 自动记忆和 compact 档案不得吸收文件正文。恢复仍限既有合法恢复边界，先核验原记录、绑定与当前资格，再为正式消费者重建完整、有界的恢复上下文；不因缺钥、绑定错误或容量不足省略必要观察、退回明文或改用飞书密钥。见 [design/24 §3、§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 正式消费者按原事实恢复（D6/D8/D9）

- **WHEN** 正式仓颉已观察含可辨识私有正文的选中资料，保存合法恢复状态后按既有允许的路径恢复
- **THEN** 持久状态中所有可能携带正文的副本都受到绑定加密保护；正式消费者收到原配对观察和冻结来源并正确继续，累计预算和调用进度不重置，不重读原件制造观察、不重做已接受工具，也不把正文写入通用明文快照或跨 Run 档案

#### Scenario: 解密或资格校验失败不恢复（D1/D8/D9）

- **WHEN** 缺少 Along 密钥、私有封套损坏、将封套挪到其他本人／会话／Run／attempt，或恢复时资料资格已失效
- **THEN** 明确失败，不启动 native 恢复或发起模型、工具调用，不披露正文，不使用飞书密钥、空观察、重读源文件或明文替代

#### Scenario: 只读补查和无效 checkpoint 不恢复（D6/D8/D9）

- **WHEN** 读取历史、请求事件补读、重放已接纳请求，或尝试从普通中间 checkpoint 或取消后的 Run 恢复
- **THEN** 只读操作最多返回原授权下的已存事实，不启动、重跑或披露内部恢复数据；无效恢复不创建新 attempt，也不以新预算绕过原生命周期

### Requirement: 资料正文不得获得指令或执行权威

系统 SHALL 只在正式仓颉循环中，将有界纪要片段、统计摘要及有限来源作为资料观察提供给用户选定的模型；不得传入文件原字节或把正文提升为系统指令、用户委托、可信时间或发送目的地。能力和效果由可信运行端依据用户原话与冻结资格裁决；摘要或统计请求不产生文件、提醒或外发。见 [design/24 §1、§3–§4、§6](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 文件内请求不产生效果（D8/D9/D10）

- **WHEN** 用户只请求摘要或统计，纪要或 CSV 指示忽略规则、读取其他资料、创建文件、安排提醒或将正文发送到指定地址，并诱使模型提议相应动作
- **THEN** 正式仓颉把内容保留在资料观察边界，可信端拒绝超范围提议；不读取未选资料、不创建交付或提醒、不向指定地址发送内容，合法读取与统计仍服从原资格和预算

#### Scenario: 有界观察、截断和来源身份保持（D8/D9/D10）

- **WHEN** 纪要或 CSV 明细大于一次模型观察容量，后续轮次或恢复需引用已接受来源
- **THEN** 模型只收到有界片段或摘要及其真实版本、覆盖和分页状态，不收到文件原字节；不把截断当作已读完、不把观察变成指令，后续读取计入原预算，无法保留必要上下文时明确失败而不扩容或绕过

### Requirement: 办公交付结果按真实证据独立终结和接续

办公 Run SHALL 用既有结构化目标结果分别记载文件、提醒和未解决缺口，不以模型正文、单个工具完成或 Run 终结替代领域证据。文件完成须验证已接受的调用与真实产物；提醒仅据真实任务回执及状态陈述。可信后续澄清仅处理仍待完成的项目，不恢复旧 Run 权限、不重做已交付文件；扩大资料范围须另行显式提交。见 [design/24 §2、§5](../../../../../docs/design/24-native-office-delivery.md)。

#### Scenario: 已生成文件但未创建提醒（A4/D6/D8/D10）

- **WHEN** 文件先被接受，随后提醒因缺时区、歧义、过窗或取消而未创建
- **THEN** 保留文件交付证据，如实报告「文件已生成，提醒未创建」及实际原因，生命周期停止不抹掉已交付事实；只在需要且允许接续时询问实际缺口，不猜时区、假称全部完成或触发通知

#### Scenario: 只补提醒缺口（A4/D6/D8）

- **WHEN** 用户仅回答与原目标有可信关联且仍待补足的提醒时间或时区
- **THEN** 经既有澄清接续机制只处理未建提醒，复用已交付事实；不重新读取、分析或生成文件，不开启旧 Run 的工具资格，不隐式增加附件或改写原结果

#### Scenario: 全部完成和证据不足分别裁决（D4/D8/D10）

- **WHEN** 结构化结果宣称已交付文件及提醒，其中任一项仅有模型声明、拼造链接、无验真回执或缺失的产物字节，或所有所需证据均能核实
- **THEN** 证据不足的项目不标成功，保留其他已核实的独立事实；仅在全部必需项目都有证据时报告完整完成，提醒已创建只陈述真实状态而不保证触发或送达
