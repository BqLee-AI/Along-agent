# 仓颉服务宿主迁移设计

## 背景与目标

迁移前，`apps/api/src/bootstrap/application.ts` 启动 TS listener 和 Worker，`agent/execution/attempt/session.ts` 持有原生 Harness 的宿主请求。原分工见 ADR 0009。迁移将 HTTP/SSE 连接、Run 编排和 Worker 推进交给仓颉。阶段与入口归属见[迁移矩阵](../../../../docs/plans/cangjie-backend-migration.md)。

## 决策

### 仓颉宿主以领域能力为调用单位

仓颉接收请求、解析 HTTP 表示、选择入口用例并控制流生命周期。TS 接受结构化的内部操作及输入，返回领域结果或稳定错误，独立核验其信任边界所需身份与资格。仓颉启动或恢复已接纳 Run，操作可用的模型和工具端口，并发布可披露的事件。Web 契约仍以现有公开契约为准，需为当前 Eden 类型消费提供同等的静态约束。

Worker 按取消、排期、认领、投递、回执、过窗顺序推进提醒周期，按独立生命周期驱动邮件。涉及锁、唯一索引、outbox 和状态原子写入的操作由同一 TS 用例持有一次 PostgreSQL 事务。PostgreSQL 是已接纳消息、执行权与效果回执的唯一事实源。仓颉使用可信结果决定下一阶段，宿主核验继续在线。

### 进程内权限与私有传输

仓颉管理常驻 Bun 能力进程，并通过仅同一用户可访问的 Unix socket 调用它。固定工具链的镜像实验中，先等子进程退出再读标准输出的实现卡住，带超时的一次性捕获可完成就绪检查。Unix socket 实验通过同一个镜像中的仓颉 HTTP 客户端访问 Bun，直接复用 HTTP 分帧和并发连接。父进程用独立的标准输入管道通知子进程退出，标准输出保留给日志。

请求 ID 随内部调用传入并由响应回传。单次调用以完整的有限响应结束，传输失败映射为依赖不可用。长流单独定义拉取、取消、结束和确认，流由消费者按需拉取。业务线依赖领域能力结果。新能力必须在真实生产基镜像中验证其并发、超时及退出语义。

内部调用带明确操作、调用关联 ID 和对应授权输入。进程异常后的有副作用请求通过部属用例的幂等键、调用登记或回执核对。对未确认结果应用现有未知效果合同，保留原预算和执行权。TS 能力返回的公开错误由 CJ 投影到原 HTTP/SSE 表示，私密材料只经原有披露核验进入公开流。

### 交接与回滚

镜像保留 `api|worker|all` 的角色选择。操作员按现有升级入口排空旧版本，确认持久状态可交接，再启用目标版本。执行权由现有租约及数据库栅栏裁决。候选版本继续读取支持范围内的旧协议快照，版本回退前检查运行状态能否被目标版本读取，约束见 #176 和当前恢复合同。无法确认兼容时保持停写并给出可操作诊断。

## 针对首条真实链路的取证

用生产镜像和独立 PostgreSQL，从聊天请求观察仓颉接收和调度、持久提醒与 outbox、仓颉 Worker 推进到通知以及独立回执。对照旧入口的公开输出。组合覆盖提前取消、投递与取消竞争、进程退出、SSE 断开、重连及重启。分别记录宿主、Run 执行权和领域回执证据。
