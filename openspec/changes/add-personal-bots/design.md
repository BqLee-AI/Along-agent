# 个人 Bot：实现设计（待评审）

## 1. 责任与取舍

Bot 表达本人长期职责和执行范围上限，Conversation 保存独立话题历史，Run 保存一次执行的事实。三者都不替代账户授权。沿用仓颉 Host、Harness、TS 领域能力与 PostgreSQL 的既有分工；不增加 Bot 专用执行器或工作进程。仅做可随会话切换的角色预设会让归属和运行依据含糊；一 Bot 一会话又不能保留独立话题，因此两者均不采用。

现有 `agent/run/admit-message.ts` 已在消息接纳时检查重复提交并冻结 Run 上下文；`features/model-providers/run-binding.ts` 持有模型绑定；`agent/tools/invocations/` 和 `agent/run/approvals/` 持有持久资格、效果和批准入口。历史读取仍归 conversations，不为 Bot 重建 SSE 或恢复协议。

## 2. Bot 及会话接口

- 使用项目现有 GET/POST、认证、错误和响应约定。新增本人 Bot 的列表、创建、详情和配置保存：`GET/POST /v1/bots`、`GET/POST /v1/bots/:botId`；另有 `GET/POST /v1/bots/:botId/conversations` 分页与创建。配置以完整值原子保存，过时修订冲突。指定模型只能引用本人已配置的模型，不保存凭据。资料选择使用明确的本人登记 ID 和访问能力；空范围不代表全开。
- 对话创建用既有请求幂等约定保存空对话，同键同意图返回原对话，异意图冲突；没有消息、模型请求或 Run。首次成功消息接纳才按原合同冻结时间依据，失败不产生部分消息或 Run。Bot 列表只返回该 Bot 的对话。已有按对话 ID 的消息、详情、SSE 和动作接口继续使用；从对话确定真实父级，不能从消息参数指定另一父级。
- TS Bot 模块持有配置和范围写入，conversations 持有归属与历史；数据库约束同 owner 关联，且绑定不可改。生产 Host 与 TS 比较入口走同一业务用例；新 POST 接入现有写准入、CSRF 和错误优先级。顺带核对 Eden 消费，使用新 DTO 表示 Bot 导航关系，避免给原严格 DTO 或 SSE 帧直接加字段。首阶段提供创建、查看及编辑，不开放删除、归档或改绑。

## 3. Run 接纳与恢复

先按客户端意图裁决幂等，重复请求命中后不读取后来变更的设置；新接纳在既有事务读取一个完整的 Bot 修订并保存角色、指令、模型绑定和工具/资料上限。继承时解析用户默认；显式绑定不可用则返回原模型不可用错误，Bot 对话拒绝冲突的单消息模型选择，单次资料请求只能缩小实际范围。恢复使用不可变配置记录或等价快照，而非按 Bot ID 重读设置。

角色和指令是模型行为上下文，不是账户授权、可信工具事实或用户消息。优先验证在 TS 正式模型请求组装处，将冻结文本与原 native 指令共同构成计量和发送用的同一请求，连接原恢复快照，保留现有 S0 约束及输出预算。若无法保持原计量、帧限制和提示优先级，再评审最小原生协议增量。同一接纳规则覆盖普通发送和续接，检查直读路由、资料相关入口及 compact；仅做摘要/计量的操作不因此获得行为指令或工具资格。请求生命周期、暂停及 SSE 语义不变。

## 4. 当前资格与效果边界

资格来自「原 Run 的冻结能力 ∩ 当前 Bot 范围 ∩ 当前用户／资源资格」，并遵守现有目标内委托。配置收窄要和许可共享持久裁决边界：预约检查并非放行；事务内效果要与其提交事务共同裁决，事务外写在最后一次不可重复许可处裁决，不为外部 I/O 持锁。实施时固定与现有 attempt、Run、资源锁兼容的锁顺序，用双连接验证，不给每个入口各造一套。复核文档确认、恢复、绑定与实际 apply，并覆盖**提醒确认本身可创建或取消任务**的提交事务；只使用持久关联的原 Run，不能推测归属。向模型重新披露受限资料或回读工具观察同样需要当前资格，不能绕过工具限制。保留历史 GET、已消费批准重放和已发生效果；已许可在途或未知效果按原合同收尾。

## 5. 切换与测试数据清理

切换后，Bot 是新建和继续对话的唯一入口。所有对话须有同 owner 的父 Bot，发送消息须指定已有对话。Web、仓颉入口、TS 比较入口和 API 契约一起移除首条消息隐式创建无 Bot 对话的路径。

实施时先停止旧写入，清点并收尾仍在运行或待批准的旧测试 Run，再对确认属于本地测试的无 Bot 会话清理及其专属执行记录。先在隔离数据库副本核对依赖和删除边界。旧会话、Run 与其专属审批链接在清理后按原不存在合同返回。已提交的提醒、事件账、用户与模型配置、工作区资料及独立记忆继续保留。有保留记录引用待清理会话时，停止这次清理，报告依赖，不伪造来源或扩大删除范围。

数据库升级须确认无 Bot 会话已清理，发现未处理历史时阻止切换；常规部署不执行自动删库或历史清理。待清理记录仅限已确认的测试数据。切换后旧写入方保持停止；需要恢复旧版时使用切换前快照。R3 继续按本人级归属。
