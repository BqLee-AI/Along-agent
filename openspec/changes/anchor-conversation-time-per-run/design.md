# 提醒日期锚：请求归属与冻结边界

## 1. 现状与必要性

Observed：基线`61693cf`及既有design/05把`conversation.anchor_received_at_utc`用于连续会话的新Run，纯入口使用显式`anchorReceivedAtUtc`，并把本地跨日或超过60秒的延迟判为`DATE_CHANGED`。`propose_task`的时间原话与事项`note`分离；纯归一不拥有时钟、DB或批准事务。恢复与幂等重放已有冻结上下文边界，不需要为本变更迁移旧事实。

历史行为证据：中文时钟Red曾将“3点二十分”解析为15:00而非15:20；它属于可独立修复的格式缺陷。日期Red则显示11月1日的新“今天”仍使用10月30日会话锚，以及同日本地仅几分钟澄清被标为跨天。这证明用户可见差异，不证明新政策已获批，也不代替未来精确版本的消费者验收。

既有冲突：design/05 §3规定延迟保护，§5.2及已归档`close-v0-time-errors`任务2.2明确conversation保留会话锚；安全spec的“A4显式时区与Web候选重提议”引用既有延迟/跨午夜约束。本change明确修改这部分行为，不把它包装成不改变合同的实现修正。

## 2. 候选取舍

## 3. 推荐合同

Proposed：日期锚归属于被接纳的提醒意图，而不是整段会话的寿命。新用户明确说今天/明天/后天/昨天并形成新Run时，用该消息服务端接纳时刻建立本轮不可变日期上下文；明确绝对日期不从时钟补年份或改日。客户端时间仅诊断，模型只传原时间表达，不能生成权威锚或UTC。

“新明确日期”指用户明确发起新的日期陈述，不是工具重放、按钮选择fold时携带的原文或服务器重放的旧消息。延续原提醒的候选重提议即使带回原文中的“今天/明天”，仍须证明同一提醒关系并保留原锚；不能仅靠相对词正则重置。若无法区分新请求与原澄清，必须先澄清意图；用户确认新的完整日期请求后，才按新的服务端接纳事实建锚，不能回填旧Run。

仅补时区等澄清消息没有新的日期授权。继承必须能够证明：同owner、同conversation、唯一且尚未完成的原提醒请求，其原输入、实际缺字段澄清或候选失败及冻结锚均可由可信持久引用追溯；当前消息确属补该请求而非独立新目标。仅“同会话最新Run”、文本相似、模型声称在继续或存在旧时间词均不构成该关系。存在多个候选、无关中间目标、缺失/损坏来源或关系不明时，要求用户完整重述明确日期时间时区，不任挑一个锚。当前消息不得充当批准或恢复旧Run的入口。

继承只复制明确的原请求日期上下文进入新的Run，不修改前Run；当前接收时刻仍单独冻结用于跨日判断。在确认时区内本地日期相同，超过60秒本身不是跨日，不换算原相对表达；若本地日期实际变化，则要求具体日期，不能把原“今天”解释为新一天。无确认时区先问时区，不用设备/位置猜本地日界。

例如同一确认时区内原接纳为本地11月1日10:00、可信澄清为10:02，保留原锚，不以120秒间隔报跨日；原接纳23:59:50、澄清11月2日00:00:10，即使仅20秒仍须问具体日期。若这条消息是独立新请求“今天下午提醒……”，则使用11月2日本轮接纳锚，不继承11月1日；仍独立执行未来时间和批准有效期校验，不能用取消60秒条件放行过期目标。

同一Run内部工具调用、已预约调用重放、同键消息重放和批准恢复只消费其持久冻结的anchor/received上下文，不因等待超过60秒或重启读当前钟。既有对象的规则覆盖、fold、偏移、UTC、presentation和确认有效期不因此重算；新的显式日期陈述只能建立新请求，不能覆写旧对象。

## 4. 责任与兼容

- conversations拥有消息接纳、原提醒关系验证和Run冻结。现有`repository.ts`输入引用、`frozen_context`及`harness-authority.ts`冻结消费是调查入口；它们的存在本身不证明已记录“同一未完成提醒”关系。实施前必须核实原输入、实际澄清/候选失败、未完成状态和原锚的持久关联是否足够；不足则澄清，不能自动继承。不以公开自由文本自报授权或引入第二套模型循环。
- 公共归一用例只接收调用方给定的不可变值；time-core不读系统钟、env、网络或DB，继续执行有限规则覆盖和明确字段检查。
- gateway保持`raw_time_text`与`note`分离；完整提议缺日期/时区/时段/事项只有澄清，无批准或承诺写入。低层局部格式归一成功不等于完整提醒可创建。
- A2 revise仍使用其持久首次接收锚；读取、按钮确认、取消和worker继续沿原冻结值，不对旧Run补锚、不迁移旧approval/task。

实现必须证明来源与请求归属，并覆盖关系不明的负例；相对词正则或最新Run不能代替关系验证。本规范变更不新增运行时状态或迁移。

Deferred：本提案规定可继承所需的证据，不声明现有schema已能表达该关系，不指定新字段、表或迁移。只有完成持久来源调查并经实现评审确认后，才决定是否需要最小数据变更；缺来源的旧数据继续澄清，不回填猜测关系。服务端接纳锚与本轮接收时刻分别冻结后，工具及恢复入口只能读取，不能在消费时重新取钟。

D1/D2/D6/D8/D10与A4：旧会话新明确今天/明天用本轮接纳锚；仅有可信原请求的时区澄清保留原锚；关系不明、多个候选或旧缺来源不能猜；同日超过60秒与真正跨午夜分别验收；缺时区先问；缺日期、时段、事项零批准。A2/D2/D6/D9：同键重放、原Run工具调用、批准恢复和只读历史不重算，不创建新执行或改写旧冻结值；fold候选重提议和确认门保持原合同。
