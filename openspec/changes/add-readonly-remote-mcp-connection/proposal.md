# 普通对话中的 Microsoft Learn 公开资料搜索

## Why

用户在普通对话询问 Microsoft/Azure 官方资料时，应由现有模型判断是否需要检索、组织查询词并依据真实官方结果回答，不应先连接应用或切换专用模式。公开服务无需个人密钥；协议实验与产品运行分别举证。

Spec：`docs/design/14-r1-document-task-loop.md` §1、§4.3；`docs/design/20-goal-scoped-delegation.md` §2–§3、§4、§6、§8–§9。

## What Changes

- 合格新 Harness Run 在接纳时冻结单一公开搜索工具；普通会话无需任何 Microsoft Learn 设置、连接、查询字段或逐次审批。现有模型自行判断是否调用，工具严格接受 `{query}`，允许按任务提炼或翻译公开技术查询。
- 目的地固定 `https://learn.microsoft.com/api/mcp`，唯一调用 `microsoft_docs_search`。复用 MCP SDK、既有 Run/attempt 网关、事务外只读执行、不可变接受结果及审计；发现项不动态注册为权限。
- 工具说明要求仅发送完成公开资料检索所需的技术关键词，不发送私有正文、账户/工作区标识或密钥。保留飞书私有读取 Run 的既有工具隔离；说明不是严格数据防泄漏门，不新增分类器、逐字匹配或审批平台。
- 结果保留有界公开摘录与真实官方来源，作为不可信资料而非指令。失败保留超时、服务、协议和容量分类。
- 干净移除未发布连接卡、路由、状态、代次、显式查询入口及无用途的未合并 0042 表/manifest/目标版本测试变化。已合并迁移及旧实验安装不动；新版本使用全新隔离正式安装验收。

## 非目标 / Deferred

不启用 #88，不新增 provider 或平台设置；不接任意 URL、动态工具、写工具、下载全文、市场、通用注册表、OAuth、tool_search 或后台执行器。不改变正常对话、工作区、提醒、审批与模型配置合同，不迁写旧 Run、不扩展旧冻结工具名单，不扩大飞书私有读取资格。

## Impact

- `tool-gateway`：固定单一公开查询、模型参数、当前执行资格、输出与审计边界。
- `conversations`：普通输入直接使用现有 Harness；没有 Learn 专属 UI/状态/入站字段。
- 实现涉及窄 MCP 适配、模型工具说明、TS/native 结果合同与新安装验收；本 PR 仅提交 OpenSpec 草稿，不启用产品行为。
