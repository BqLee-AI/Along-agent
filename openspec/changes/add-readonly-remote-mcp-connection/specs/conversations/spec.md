## ADDED Requirements

### Requirement: 普通会话零设置使用官方公开搜索

系统 SHALL 沿用既有普通对话与现有模型，让模型按问题决定是否调用 Microsoft Learn 公开搜索、组织查询词并依据实际返回的官方摘录回答。不要求连接应用、专用模式、额外查询字段、provider/平台设置或逐次审批，不新增正常对话、工作区、提醒和审批的硬阻断，不启用 #88。

#### Scenario: 普通输入查询微软官方资料

- **WHEN** 用户在新普通会话输入 Azure Database for PostgreSQL Flexible Server 备份保留问题并要求出处，未配置任何 Learn 连接或模式
- **THEN** 合格新 Run 冻结搜索工具名单，现有模型可提炼或翻译技术 query，自行调用固定公开 MCP，依据真实返回结果回答并显示真实官方链接，事实可在历史只读定位。

#### Scenario: 无需检索的普通消息

- **WHEN** 普通消息不需要外部资料，模型未选择搜索
- **THEN** 对话正常完成且不产生 MCP 请求，不因名单含搜索而自动发现或调用上游。

### Requirement: 保留已冻结名单与既有私有读取隔离

系统 SHALL 使用原 Run 持久化工具名单执行和恢复，不因部署或新目录给旧 Run 增加工具。飞书私有读取 Run SHALL 保留原工具收窄，不暴露公开搜索。工具说明 SHALL 禁止将私有正文、标识或密钥写入 query，但不得把提示词称为严格数据防泄漏门，不增加分类器、逐字当前消息匹配或审批步骤。

#### Scenario: 旧 Run 恢复不自动扩权

- **WHEN** 已冻结不含 learn_docs_search 的旧 Run 被继续、恢复、重放或查看
- **THEN** 名单不变，伪造搜索调用本地拒绝且零出站；读取历史不自动执行。

#### Scenario: 飞书私有读取仍隔离公开出站

- **WHEN** 现有飞书私有读取资格被接纳于 Run
- **THEN** 按原工具收窄合同不暴露 learn_docs_search，不能借该私有读取 Run 调用公开搜索；不扩大飞书授权或更改其披露边界。
