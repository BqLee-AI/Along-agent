## ADDED Requirements

### Requirement: 本人模型接入与安全凭据

系统 SHALL 仅允许合格本人管理自己的模型接入、模型列表和默认选择，保护凭据并区分保留、替换和清除；所有访问和出站请求遵守 [design/22](../../../../../docs/design/22-model-provider-settings.md) 安全边界。

#### Scenario: 账户隔离和不回显

- **WHEN** 两个用户分别创建接入，或一人伪造另一人的接入 ID
- **THEN** 不能读取或更改对方配置、借用其凭据；普通响应、日志、错误、Run、checkpoint、SSE 与浏览器持久存储不包含完整 Key

#### Scenario: 更新地址或清除凭据

- **WHEN** 用户更新 endpoint、保留、替换或明确清除 Key
- **THEN** 空输入不隐式清除；新地址不得静默携带旧 Key；清除或删除使受影响历史版本后续调用不可用，不能声称撤回已发数据或工具效果

#### Scenario: 同步、手动维护和过期结果

- **WHEN** 模型发现失败、服务不支持列表，或请求期间配置版本改变
- **THEN** 不删除已有模型；过期发现不写入新配置；用户仍可手动添加不透明完整 ID，重复添加不产生重复

#### Scenario: 默认失效

- **WHEN** 删除或禁用默认接入，或移除默认模型
- **THEN** 同事务清除默认，不自动选择其他接入或模型

### Requirement: 新 Run 冻结选择和可读历史

新模型 Run SHALL 在接纳时按本人显式选择或默认解析唯一有效配置版本，与 Run、上下文策略及安全展示快照一致提交；历史读取不从当前配置推断，见 [design/22](../../../../../docs/design/22-model-provider-settings.md)。

#### Scenario: 选择和后续更改

- **WHEN** 用户新建模型 Run 后切换默认、改名、停用或删除接入
- **THEN** 原 Run 不切换版本，详情和列表读取相同接纳时名称与完整 ID；新选择失效则明确拒绝，不回退其他配置

#### Scenario: 幂等重放与竞争

- **WHEN** 同 owner 同键同客户端选择意图重试，即使默认或配置已变化
- **THEN** 按现行资格和读取授权直接重放原 Run，不再解析默认；即使原 Run 正运行也只读交付已存事件前缀（可为空）并结束 POST，不启动或跟随执行；授权完成后响应头标识原会话与 Run，空前缀也可定位事件 GET 补读；显式选择与省略不同，同键异意图冲突，并发唯一冲突后回读比较，不产生第二决议

#### Scenario: 历史来源不足

- **WHEN** 读取旧模型 Run 但不能可靠还原绑定，或读取不使用模型的业务 Run
- **THEN** 分别返回 legacy_unavailable 和 not_applicable；不从默认、相邻 Run 或模型名猜测，GET 不执行、不补写

### Requirement: 明确旧部署迁移

系统 SHALL 要求部署管理员显式指定导入目标用户，保留旧事实并对不能安全继续的旧等待明确拒绝和处置；不得复制共享密钥给所有用户或以新配置冒充旧绑定。

#### Scenario: 旧等待和失败恢复

- **WHEN** 原部署升级或迁移中断，旧 Run 无可证明的原接入引用
- **THEN** 历史仍可读，旧等待的 `can_resume` 为 false，即使批准已决议也不允许恢复；不重做工具、不改写 checkpoint/预算/身份；停旧写者并以前向恢复处理，不擅自回滚已接纳新事实
