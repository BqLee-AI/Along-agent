# workspaces Specification

## Purpose

规定本人受管工作区的有限文件授权、真实 MCP 检索与全文基线、冻结文档批准、唯一文件替换及独立回读合同。批准只授权，不等于保存；冲突与未知效果保留各自事实，不以受控模型或当前文件相同代替真实任务交付证明。

## Requirements

### Requirement: 可信工作区选择与有限文件授权

系统 SHALL 只让用户从本人服务端登记项选择工作区，并冻结本 Run 的有限文件授权；浏览器、模型和 MCP 不能自报 root、扩展文件范围或改变原运行归属。具体登记、接口与边界见 docs/design/14-r1-document-task-loop.md §3。

#### Scenario: 本人选择与刷新（D1/D8）

- **WHEN** 用户在现有 Web 的 Agent 模式选择本人工作区并提交任务，随后刷新/补读
- **THEN** 同一 Run 可见原选择及安全相对范围，补读不启动执行，也不暴露宿主 root/他人登记项

#### Scenario: 越界及链接目标（D1/D8）

- **WHEN** 请求伪造工作区/owner/路径、访问未登记文件，或 symlink/硬链接/目录替换使目标不满足受管边界
- **THEN** 系统拒绝读取/写入，不披露范围外字节，不因字符串前缀相似或模型指令而放行

#### Scenario: 登记变化或撤销（D8）

- **WHEN** 等待或运行期间 root/登记摘要不再匹配，或当前权限被撤销
- **THEN** 新动作被拒绝，不借恢复静默扩大授权；原接受事实按当前访问资格读取

#### Scenario: 重复或重叠工作区登记（D8）

- **WHEN** 不同登记指向相同 root 身份、相同规范目录或祖先/后代目录
- **THEN** 冲突登记不启用，不允许同一物理目标借不同 workspace 锁并发覆盖；无工作区的原业务仍可用

### Requirement: 真实有限检索及可恢复读取观察

TS 工具 SHALL 对授权文件实际列目录、搜索和全文读取，提供版本与明确失败；仓颉把观察纳入下一轮选择，不用固定 TS 调用序列或隐藏 Agent 替代。工具与错误合同见 design/14 §4、§7。

#### Scenario: 资料位置或读取失败变化（D8）

- **WHEN** 授权资料的位置/可读性改变，第一次读取失败或搜索仅取得部分结果
- **THEN** native 后续模型请求包含真实位置/失败观察，并允许由模型选择不同检索/查证；不把失败说成空结果或继续使用编造内容

#### Scenario: 搜索与全文版本（D8）

- **WHEN** 同一文件在两个新逻辑读取之间改变，或试图用搜索片段代替修改全文基线
- **THEN** 新读取反映实际字节版本；原 invocation 重放保持原快照，非全文/不属本 Run 的引用不能作为写入基线

#### Scenario: 有界结果（D8/D10）

- **WHEN** 文件、搜索或预览无法满足现有传输/接受结果安全边界
- **THEN** 系统明确报告超界，不静默截断、不把部分结果当穷尽，也不对未完整核验内容执行替换

### Requirement: 文档批准绑定精确基线与完整目标

文档修改 SHALL 绑定本 Run 的真实全文读取版本、唯一字面量替换及确切完整目标；用户按钮只授予该动作权限，不等于文件已修改。预览/决议与持久关系见 design/14 §4–§5。

#### Scenario: 正常精确预览与按钮（D6/D8）

- **WHEN** 模型基于真实读取提出唯一匹配的替换，用户核对冻结预览并确认
- **THEN** 批准绑定原目标、版本和完整内容；此时没有文件写入或 task 创建，后续只能执行该冻结动作

#### Scenario: 所见不一致或模糊替换（D8/D10）

- **WHEN** 提交预览/hash 不一致，old_text 无匹配/多匹配，或引用不属当前 Run
- **THEN** 不授权、不写文件、不自动 replace-all/rebase，也不修改原批准的冻结内容

#### Scenario: 批准状态与真正效果分离（D8/D10）

- **WHEN** 批准已通过但尚未执行、被拒绝，或实际执行结果未知
- **THEN** Web/Run 分别呈现真实授权和效果状态，不把 approved 当文件成功，不绕过拒绝重提同义动作

### Requirement: 版本冲突与无关内容保留

实际替换 SHALL 在受控写入边界验证基线版本，只写批准冻结的目标字节；全部未修改内容保持原样。文件互斥和条件保证见 design/14 §3.3、§6。

#### Scenario: 读取后或批准后内容改变（D8）

- **WHEN** 其他受控写者在读取/批准之后改变目标，使实际版本不等于冻结基线
- **THEN** 当前 apply 返回明确冲突且零替换；重新读取后的不同目标必须重新批准，不能沿原批准重新匹配写入

#### Scenario: 保存内容精确（D8/D10）

- **WHEN** 合法版本上的替换成功
- **THEN** 保存字节精确等于批准目标，BOM/换行/空格及未命中前后区段保持；真正后续读取能核对目标而非回显参数

#### Scenario: 确定冲突后新批准完成（D6/D8）

- **WHEN** 批准 A 的原 apply 已接受明确零写冲突，随后新读、新批准 B、原绑定 apply B 和独立回读均完成
- **THEN** 同目标唯一后继可以完成任务，A 的授权/冲突事实不变；最终展示区分原未写和新修改成功，不要求旧冲突伪装 applied

#### Scenario: 不确定或未完成不能被覆盖（D8/D10）

- **WHEN** 原动作 unknown/未尝试，或冲突后继仍 pending、被拒绝、未执行或未知
- **THEN** 不允许借新提议绕过原动作或报告完成；只有同目标可信零写前驱到真实批准/写入/回读的成功链可被接受

### Requirement: 非事务写入唯一许可与诚实未知

文件效果 SHALL 复用稳定 invocation 和非事务一次许可；同批准只绑定一个 apply invocation。没有绑定确证时保持 unknown，不以数据库事务或当前相同内容推断外部恰好一次。见 design/14 §5.3、§6 及 tool-gateway 非事务要求。

#### Scenario: 批准换新调用或重复提交（D6/D8）

- **WHEN** 原 apply 重交，或同批准试图取得另一个 invocation
- **THEN** 原引用仅重放接受结果/unknown，新引用被拒绝，不产生第二次文件替换

#### Scenario: 写入后接受结果丢失（D8/D10）

- **WHEN** 替换可能已发生但绑定结果未被接受，重启/重交时当前内容恰等于目标
- **THEN** 原调用仍未知且不重写；相同 hash 只可证明当前产物，不制造该调用执行过的回执或成功终态

#### Scenario: 确定写前未生效（D8）

- **WHEN** 可信执行器在写前证实冲突或未生效失败
- **THEN** 接受对应明确观察/失败，实际字节不变；重交不会重新执行该逻辑动作

### Requirement: 实际 TS MCP 消费与正式文档结果

系统 SHALL 经正式 TS MCP Client/Server 消费真实文件工具结果，并经现有 Web/native/TS 链完成真实文档产物；受控模型合同不等于真实模型验收。选择及证明边界见 design/14 §8–§11。

#### Scenario: 真正 MCP 文件读取（D8）

- **WHEN** native 在现有 Web 任务中选择文件读取工具
- **THEN** 实际 SDK Client 经协议调用 TS Server 并把真实文件结果交给 native；省略调用/结果纳入会使同消费者验收失败，不以 echo/mock/工具列表代替

#### Scenario: 真实模型与独立回读（D8/D10）

- **WHEN** 获授权的真实模型完成有冲突的项目资料整理及已批准简报更新
- **THEN** 仓颉依据实际证据选择查证/修改，并以新的真实读取核对保存内容；只有原绑定写入和相符回读都被接受，才可报告任务成功

### Requirement: 历史上下文片段不替代完整基线与新回读

系统 SHALL 区分 context_slice、原完整 workspace_read 和 apply 后新的全文读取；投影/回取不能改变精确批准、唯一 apply、零写 conflict 或 unknown 效果规则。见 `docs/design/18-r2a-harness-context.md` §4、§7–§9 与 `docs/design/14-r1-document-task-loop.md` §4–§7。

#### Scenario: 旧片段帮助精确修改（D6/D8）

- **WHEN** 模型从旧观察回取 old_text 后提出精确替换
- **THEN** 提案仍须引用同 Run 原完整 read，TS 核对完整基线/唯一匹配/当前版本，context_slice 引用不能作全文基线；完整目标和无关原字节不由投影改写

#### Scenario: apply 后回取旧事实（D8/D10）

- **WHEN** apply 已接受后模型仅回取旧读或旧片段并声称完成
- **THEN** 不满足 verified/done，必须 apply 后新创建且接受的真实 workspace_read 核对产物；批准本身仍零写且不算效果

#### Scenario: 大资料真实任务与错误事实（D6/D8/D10）

- **WHEN** 正式模型处理至少六份大资料、冲突日期与一次读取失败，发生投影/原来源回取后批准继续
- **THEN** 原 Run 以真实证据查证并唯一写入/新回读，保留冲突与失败的区别；unknown 不重写、不转成功，小任务不因新增机制无谓增加模型调用
