# tool-gateway Specification

## Purpose

定义TS工具网关的稳定调用身份、本地批准/接受结果原子性、当前权限与冻结结果重放，以及非事务未知效果的一次许可/只读核对边界；保留按钮确认、确定性时间、只追加账、取消与真实回执保证，不将本地去重扩大为通用external exactly-once或仓颉Harness验收。

## Requirements

### Requirement: 稳定逻辑调用身份与内容绑定

TS工具网关 SHALL 在副作用前持久预约逻辑调用引用；身份不由参数摘要、追踪请求或执行attempt代替。同引用的绑定内容不可改变，新引用允许同参数新动作。具体接口、数据所有权与迁移见docs/design/04 §3、§7和docs/schema/conversation-and-runs-schema.md。

#### Scenario: I2 同slot或同引用重交

- **WHEN** 同一Run同slot的预约回答丢失后重取，或调用在同Run有效attempt中顺序／并发重交
- **THEN** 系统定位原逻辑引用，不因新request或attempt新建动作；已有接受结果被重放，未提交本地事务按原引用处理

#### Scenario: I3 同参数合法新调用

- **WHEN** 本人同Run以新slot取得新引用并提交相同工具和参数
- **THEN** 系统按新调用处理，不因args_hash相同吞掉动作或审计；原取消提议复用pending批准的业务规则仍可适用

#### Scenario: I2 内容替换或运行关联不符

- **WHEN** 同slot／引用改tool或参数，或尝试跨owner／Run借用引用、提交不属于Run的attempt
- **THEN** 系统拒绝冲突或错误关联，不返回他人接受结果、不执行工具、不更改原绑定

### Requirement: 本地批准与接受结果原子提交

网关 SHALL 将本地工具批准创建／取得、已接受结果和执行审计在同一数据库事务提交，提交后才返回；失败不得留下与调用结果脱节的批准。不修改design/06确认消费单事务、time-core或事件账合同。

#### Scenario: I1 批准写入后审计或结果写失败

- **WHEN** 实际本地批准INSERT成功后，结果或审计持久化失败
- **THEN** 本次业务事务全回滚，不遗留脱节批准／接受结果／审计，也无task、task_events、outbox或通知副作用；预约可保留供同引用恢复

#### Scenario: I1 本地执行错误已证实回滚

- **WHEN** 本地工具抛错且业务效果已在事务内回滚，结果和失败审计能够正常持久化
- **THEN** 系统接受脱敏失败并关联原调用，重交不再执行业务；若连结果／审计也不能提交，则不宣称已有持久失败

#### Scenario: I2 提交回答丢失

- **WHEN** 本地事务COMMIT回答丢失，调用方用同引用通过新连接重交
- **THEN** 以数据库事实判定：已接受则回原结果，未提交则无该事务副作用；不另造引用或第二批准

### Requirement: 分类结果与冻结快照重放

网关 SHALL 持久关联成功、批准等待、拒绝、澄清、类型化错误与明确失败，并区分已接受的操作未完成观察；已接受结果不能被重交覆写。任务/文档批准按各自冻结材料恢复，只读工具回接受时安全快照；原始秘密不得落账。见 `docs/design/06-approvals-confirmation-gate.md` §10、`docs/design/09-agent-runtime-and-checkpoint.md` §5–§6 和 `docs/design/14-r1-document-task-loop.md` §4–§5、§7。

#### Scenario: I4 批准终态后的调用重放

- **WHEN** 已接受调用的批准后来被确认、拒绝、过期或替代，再提交原调用
- **THEN** 仍关联原批准及其种类的冻结材料，任务批准保留原 hash、展示版本和有效期，文档批准保留原版本/确切目标；不重建、不重新归一、不消费，当前状态另读

#### Scenario: I4 只读源变化或时间规则不可用

- **WHEN** 接受结果后任务／偏好等源发生变化，或当前时间规则不可用，再重交同引用
- **THEN** 系统回原接受快照或类型化结果，不重新查询／归一伪装成重放；新引用才可获得新结果

#### Scenario: I4 拒绝与错误重交

- **WHEN** 已接受denied、clarification、time_error或failed的调用被再次提交
- **THEN** 回原分类和安全结构，保持调用／Run／首次接受关联；不因权限后来扩大或时间变化重新执行

### Requirement: 当前访问资格与提交审计

系统 SHALL 在返回结果或执行前验证真实owner、conversation、Run、attempt关联，并在未接受执行时与Run取消／终结串行裁决；重放历史事实不恢复执行资格。当前权限变化不覆写原接受结果。调用提交通过只追加审计关联正确引用和请求，不按参数摘要丢审计。见design/04 §3、design/09 §1、§5–§6。

#### Scenario: I4 权限撤销再恢复

- **WHEN** 已成功接受调用后当前权限被撤销，随后又恢复
- **THEN** 撤销期间拒绝访问原结果且不执行；恢复后仍读取原接受结果，各次提交审计不篡改历史接受事实

#### Scenario: I5 效果证据返回时权限已撤销

- **WHEN** 获一次许可的执行栈取得绑定正确的效果证据，但接受结果前当前访问权限被撤销
- **THEN** 系统仍原子保存已知效果事实与接受审计，响应拒绝且不披露结果；权限恢复后即使没有核对能力也能重放原结果，不再执行效果

#### Scenario: I4 取消先提交

- **WHEN** Run取消或失去执行资格先提交，此后提交尚未执行的预约
- **THEN** 不执行新的工具副作用；已发生的效果不伪称撤销，也不借重放推进Run

#### Scenario: I4 审计只追加与历史兼容

- **WHEN** 新调用接受／重放／拒绝，或读取迁移前的旧审计与SSE
- **THEN** 新提交关联正确调用／Run／attempt／request，旧行不伪回填结果，审计仍禁UPDATE/DELETE，旧SSE可原样补读

### Requirement: 非事务效果未知不盲重发

共同调用协调边界 SHALL 将一次非事务执行资格在动作前持久提交，只有取得该次资格且确认提交的当前执行栈能够调用动作。文档批准只绑定一个 apply 调用；未知只能核对或保持未知，不能因新 slot 再写、凭次数/当前相同内容转成功或宣称外部 exactly-once。见 `docs/design/04-five-seams-contract.md` §3 和 `docs/design/14-r1-document-task-loop.md` §5.3–§6。

#### Scenario: I5 许可后动作前进程终止

- **WHEN** 一次资格已提交，但进程在真实非事务动作前终止，再重启重交
- **THEN** 即使实际效果计数为零也保持未知，不补执行，不假报成功

#### Scenario: I5 效果已发生但接受结果前终止

- **WHEN** 真实非事务副作用已持久产生，进程在接受结果提交前终止，随后顺序或并发重交
- **THEN** 真实效果累计不再增加，回未知；可查询时只读核对同调用／内容绑定的证据，确证才接受结果，无查询或查不到继续未知

#### Scenario: I5 明确未生效失败与已接受成功

- **WHEN** 可信动作证明写前失败，或成功结果已被接受后再次提交
- **THEN** 前者为明确失败且零外部写，后者回原成功且真实效果仍一次；两者都不因重交重新发动作

#### Scenario: R1 同批准换新调用（D8）

- **WHEN** 原文档 apply 重交或试图借同批准预约另一个逻辑调用
- **THEN** 原调用只重放接受结果/未知，新调用被拒绝，不发生第二次替换

### Requirement: 实际使用路径与既有安全保证保持

实现 SHALL 在真实 HTTP、会话、PostgreSQL 和效果边界验证调用与结果归属，workspace 工具也只能经同一可信网关。事件补读不执行，工具接受不等于 Run 自动恢复；五个既有工具和新增工具不保留绕过网关/身份的旧签名层。D8 依正式消费者实际证据限定，不以声明替代 MCP/真实模型/文件产物证明。见 `docs/design/14-r1-document-task-loop.md` §8–§11。

#### Scenario: I6 真实提议确认与取消

- **WHEN** 有效会话／CSRF经HTTP发起消息得到工具批准，再按冻结详情按钮确认或走取消提议
- **THEN** 批准、调用结果与Run正确关联，同批准重复确认同task；未有撤销回执仍cancel_pending，冻结展示、时间类型错误、事件只追加与取消优先不变

#### Scenario: I6 POST重放及GET补读

- **WHEN** 原消息按同入站幂等键重交，或GET after_seq补读已存事件
- **THEN** 沿既有运行中409／完成重放合同处理，补读不新建调用／attempt／批准，不再执行工具

#### Scenario: I6 工具接受前后传输失败

- **WHEN** 批准后审计写失败，或工具结果已接受后socket／checkpoint写失败
- **THEN** 前者无脱节批准且流仅有既有失败终结，不发虚假批准成功；后者保留已接受结果、不重做工具，不声称自动继续该Run

#### Scenario: R1 正式 MCP 与文件消费者（D8）

- **WHEN** 本次生产构建经本地公共用例及签名 HTTP 执行 workspace 文档任务
- **THEN** 实际 native、PG、SDK Client/TS Server 和真实文件参与；省略必要调用或结果纳入导致同消费者失败，而非以历史报告补足

### Requirement: 事务外只读 MCP 与唯一接受结果

只读 MCP SHALL 在短事务资格检查后、事务外调用，再以短事务裁决首次接受的不可变快照，不占 Run 锁等待外部 IO，不借写效果 unknown 限制纯读。见 `docs/design/14-r1-document-task-loop.md` §4.3、§8。

#### Scenario: R1 读取未返回时取消（D8/D9）

- **WHEN** MCP Server 尚未返回且取消先提交
- **THEN** 取消不被等待 IO 的 Run 锁阻塞；连接被收回，迟到数据不推进运行或披露撤权内容

#### Scenario: R1 同引用并发读取（D6/D8）

- **WHEN** 首次接受前同引用读取取得不同源版本，随后再次重交
- **THEN** 只接受并返回首次接受的原快照，后续结果不覆盖；已有接受结果时不再次调用 MCP

### Requirement: 同 Run 原接受观察的受控回取

系统 SHALL 通过同一 ToolGateway 提供有界原接受事实读取，使用新持久调用、当前权限及原接受版本，不重新执行原操作；内部装配不能成为模型免预算回取。接口见 `docs/design/18-r2a-harness-context.md` §6–§7。

#### Scenario: 来源后续改变与分页（D8）

- **WHEN** 已接受只读结果的当前文件改变，模型按来源读取原正文或数组分页
- **THEN** 返回原接受版本、单位/范围/total/has_more 与确切内容；整结果遵守页字节门，UTF-8/Unicode 不损坏、数组稳定，不重调 MCP 或把当前文件当旧结果

#### Scenario: 来源资格拒绝（D1/D8/D9）

- **WHEN** 来源跨 owner/Run、未完成未接受、当前撤权、旧 attempt 或取消先提交
- **THEN** 拒绝且不披露存在性/内容，不返回空页伪成功，不新执行原操作；旧 Run 冻结 allowlist 不因升级自动扩权

#### Scenario: 新调用与不可递归来源（D8/D9）

- **WHEN** 模型请求回取、重放同引用或试图以 context_slice 再切片
- **THEN** 新动作按既有调用号/64 引用/预算审计接受，同引用重放原页；递归来源明确拒绝为不支持，不能生成免费重放链或绕网关读取

### Requirement: 投影保留失败与不可变来源

TS SHALL 从可信接受账生成投影元数据，不把省略字段伪装为空结果、完整搜索或新执行；来源损坏不能靠回读当前文件修复。见 `docs/design/18-r2a-harness-context.md` §4、§7–§8。

#### Scenario: 部分搜索和不同版本（D8/D10）

- **WHEN** 搜索含逐文件 failures，同路径多个接受版本被投影
- **THEN** 保留失败数量、不完整性和各来源身份，原 matches/failures 可回取，不称零匹配/穷尽，也不合并版本或冲突日期

#### Scenario: 超大元素与缺失来源（D8/D10）

- **WHEN** 单元素无法放入页，或可信已接受引用的底层结果损坏/缺失
- **THEN** 前者明确 range_too_large，不返回半元素或无进展下一页；后者协议失败，不以空结果、摘要或当前版本替代原事实
